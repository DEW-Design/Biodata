# 2026-09-30 - Attribute filter on the Data Ingestion Report

- **Sept 30 2026: Attribute filter on the Data Ingestion Report.** The designer chose "choose an attribute to filter on" over a filter modal, and asked for it to be worked in. New `app/pages/_shared/attribute-filter.tsx` (composed from design-system parts: `Popover`, `Select.ComboBox` with `listbox="inline"`, `Checkbox`, `RadioGroup`, `InputDatePicker`, `TagGroup`/`Tag`, `Button`; no new component, so no section 1.4 override). Flow: "Add filter" after the search opens a searchable list of attributes (those already on are ticked); choosing one shows its values in the same popover with a back control and Clear; filters apply as they are chosen; each one is a removable chip under the toolbar, with "Clear all". Attributes on the report: Validation status, Submission status, Dataset processing status, Template type, Template, Project (searchable), Project status, Ingested by (searchable), Ingested (date: last 7, 30 or 90 days, or a custom range; an out-of-order range shows an error and does not filter). Replaces the report's `ListFilterButton` and the disabled "Additional filter" control (nothing was decided for it; the attribute filter covers the need, and it is easy to bring back). New clause CONTRACTS 4.2d says which filter applies when: the attribute filter for many-facet lists, `ListFilterButton` for short ones; the short lists are unchanged. "Project timeline" is still left out: the project list carries no start or end dates. Verified: tsc, eslint on the touched files, and a live Playwright pass (en-AU locale, BioData Admin) covering keyboard search and selection in the attribute list, options filtering (60 rows to 6), presets, a custom range, the out-of-order message, two filters together, chip removal and Clear all, zero console errors. Open: chips use the design-system Tag, which is uppercase, so they read "VALIDATION STATUS: FAILED"; a chip is removed with its X and edited by choosing the attribute again in "Add filter" (chip click does not reopen it); the DS date field rejects day 31 while no month is set (react-aria behaviour, not changed). Other lists keep the old filter until the designer decides to move them. Not committed.
