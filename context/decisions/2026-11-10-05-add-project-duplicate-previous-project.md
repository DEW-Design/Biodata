# 2026-11-10 - Add Project: Duplicate previous project

- **Nov 10 2026: "Duplicate previous project" at the top of Add Project.** The business's comment, from the designer's screenshot: "[Adding new Project, Event, Occ, Obs] Duplicate prev. record". This entry is the Project part; Event, Occurrence and Observation are handled apart. Job: someone adding a project that is much like their last one starts from it and changes what differs. Principles: 6 Reveal in steps (the start is one press, not re-typing), 1 Say less (offered only where it does something), 3 One system (the form pattern, the created projects store). Closest page: the form pattern's own action buttons (4.1) and the Projects list, which already reads the created projects store.
  **What it does.** On the first section ("Project basics") of both Add Project layouts (option 1, and option 2 with its Datasets step: one `RegistrationFlow`), a secondary `Button` with `Copy01` (3.12: "Duplicate, copy") reads "Duplicate previous project", with the source beside it ("BD-5138 - Coorong Wetlands Bird Monitoring"). Pressing it fills the form from the project created most recently in this browser (`useLatestCreatedProject`, the persisted created-projects store) and says so in a toast. New: `project-registration/duplicate-project.tsx` (the helper `duplicateProjectForm` and the button); `useLatestCreatedProject` in `created-projects-store.ts`; four lines in `registration-flow.tsx`. No shared component changed; without a previous project, or once the form is touched, nothing is drawn or different (1.6, 2.12).
  **Carried:** abstract, the data owner and every contact with role and access, the geographic extent, focus areas, method and its notes, permits, targeted species, and every restriction. **Not carried:** the project name and full title (so it has to be named; the form blocks Continue on it, as for a new project), the URI or DOI (one project's identifier), the logo (it does not survive a reload anyway), the dates (the start opens as today, the end empty, as a new project does, 2.11) and, in option 2, the dataset step (no files). The project number is assigned on create as ever (BD-5138 then BD-5139 in the pass below). **Status:** the form has no status and created projects are saved as Active, so "Draft status" in the brief is not something this form can express; nothing was added for it.
  **Offered only while the form is untouched** (`!dirty`, and the Datasets step untouched): pressing it replaces the answers, so it is never shown over something typed, and after use it goes (no second press). With the Pre-fill sample content switch on, the sample fills the form at mount, so the button is not shown; that is the intended order (a sample, or a copy, not both). With the switch turned on after a duplicate, the sample replaces the copy, and turning it off puts back the copy.
  **Persistence (the same comment's zustand line).** The created projects store was already zustand `persist` to localStorage (`biodata-created-projects`); a duplicate is saved through the same `saveCreatedProject`. Nothing new to persist for projects. Event, Occurrence and Observation records are session-only today (`edit-store.tsx`) and are another change.
  **Verified (live, fresh context, scrollbars drawn, 1440x1000, Registered User, both layouts):** no previous project, no button; after creating one (through the sample switch), the button shows with its source; pressing it leaves the name empty, keeps the abstract; Continue is blocked with "Details missing: Project name"; after naming it, the Review step shows the owner (Birds SA), three contacts with their roles and access, the extent, focus areas, methodology and limitations, and every restriction of the first project; the discard prompt opens on Close (the form is dirty after a copy) and Keep editing returns; Save draft toasts as before; Create project makes BD-5139 beside BD-5138; after a reload the Projects list shows both and the new project's page opens; option 2's Datasets step carries no files; zero console errors. `tsc` clean, `eslint` clean on the three files, `check:contracts` passes.
