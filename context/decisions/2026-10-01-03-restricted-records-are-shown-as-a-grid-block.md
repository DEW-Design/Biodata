# 2026-10-01 - Restricted records are shown as a grid block

- **Oct 1 2026: Restricted records are shown as a grid block.** The designer pointed out that a restricted species' blur is a square block of a grid, not a circle, and that drawing a circle lets anyone work out the position. Checked in the code: the location was snapped to the centre of a grid cell and drawn as a soft blurred circle of the stated radius around that centre (so the brightest point of the blob was the cell centre), the hover text and record page claimed "within about 5 km" although the real position is within half a block (2.5 km) of that centre, the record page blurred the snapped coordinate table with a CSS blur (the text stayed in the page), the Species table printed the snapped coordinates, and a search area tested the real point, so a small search area moved about could find a record's true position. Changed: (1) `geo.ts` gains `generalisedBlock`, `blockCentre`, `blockTouchesBoundary` and `isRecordInAnyBoundary`; (2) the map draws the block (`SAMapMarker.fuzzyBlock`, `FuzzyArea` in `sa-map.tsx`): flat, a thin edge, no centre mark, no blur (the SVG blur filter and its CSS are removed), never drawn smaller than 14px across at state-wide zoom, legend "Restricted (block)" with a square swatch, hover text "location restricted to a 5 km block"; (3) Explore's search matches a restricted record by its block (`isRecordInAnyBoundary`, with the role's block size; artefacts take their record's) in the area counts, the project roll-up and every results tab; events and projects are still matched by their own points; (4) the record page shows the block and, in place of the coordinate table, a "Location restricted" card with no coordinates and the request-access button; (5) the Species table and its exports say "Withheld (in a 5 km block)"; (6) the project page's record panel, full view and inspector draw the block from the record's own position, hide the coordinate table and the coordinates line under the map, and read the block size from a new `SurveyRecord.blockKm` set in `project-seed.ts`, so the note, the map and Explore agree (records in `survey-data.ts` without it fall back to a 0.1 degree block, about 11 km); (7) the peek card and project note wording changed to "shown only as a block". `ref-roles.md` records the rule. Block sizes are unchanged for now (5 km for birds, 10 km for everything else, `restrictedRadiusKm`); the designer will send the real values, which go in that one function. Verified: tsc and eslint on the touched files; a Node check of the geometry (a small circle anywhere inside a block gives the same answer as one anywhere else in it; a circle 3 km outside misses; 0.4 km from the edge hits; polygons inside, containing, crossing one edge and far away behave); and a live Playwright pass as Registered User on Explore (a flat square path with no blur filter in the page, legend, hover text, no coordinates anywhere in the page text) and on the project page for the Malleefowl record (note, block map, no coordinates), zero console errors. Open: (a) Region ("Mount Remarkable") and the project name on a restricted record still name the place more precisely than the block; whether to withhold them for restricted records is the designer's policy call, raised twice and not yet answered; (b) the grid is in degrees, so a block is about 17 percent narrower east-west than north-south; the real values may want a metric or a 0.1 degree grid; (c) project and event points are still matched and drawn by their true location; (d) the project page's landscape score still reads the record's true coordinates; (e) the new report pages from another session (`reports/specimendb-refresh-report-data.ts`, `sensitive-restriction-report-data.ts`) still use `obfuscateCoordinate` (kept, unchanged) and show the snapped centre, so they should move to the block; (f) `check:contracts` fails on 4.7 in `reports/project-detail-report.tsx` (a "Registered by" label) from another session, not from this change. Not committed.
