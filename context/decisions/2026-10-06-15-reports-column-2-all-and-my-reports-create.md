# 2026-10-06 - Reports column 2: All and My reports, Create a report, and My reports as generated reports

- **Oct 6 2026: Reports column 2 is a fixed nav with an actions group, and My reports exists. From the designer: "Fixed nav: All reports, My reports. User actions: Create a report - choose a report - generate." Four questions were put to the designer first (0.4) and answered: a "My report" is "a report I generated"; Generate produces, in the designer's words, "e.g., my DLA requests, my reports, essentially" (read here as a saved run, see below); Create a report picks "the report and its scope"; the new nav replaces the Categories list in column 2.**
  - **Column 2 (`ReportsNav`, `reports-nav.tsx`):** the section's own All / My switch as on the DLA, DSA and nominations lists (`AgreementScopeNav`, `?scope=all|mine`): "All reports" and "My reports", then an Actions group (the shared `ActionRow`) with "Create a report" (`BarChart01`). The Categories list from `2026-10-06-13-*` and `-14-*` is gone from column 2; the category tabs in the page stay (the designer's own choice, `-14-*`), on the All reports view.
  - **All reports:** the catalogue as before (cards or table, the category tabs, Favourites).
  - **My reports (`my-reports.tsx`):** a list like the others (4.2): header "My reports" with its count, the table in a card with the numbered footer (Report, Project, Generated, a "..." menu), each row a link that opens the report. The "..." menu removes the entry from the list (never the report). Newest first, sortable. Empty: "No reports generated yet", with a Create a report button. It lists only reports the role is still offered.
  - **Create a report (`create-report-modal.tsx`):** a dialog (`FormModal`) from column 2's action and from My reports' empty state (one open state, `useCreateReportDialog`; drawn once by the shell): choose a report (the ones the role is offered, A to Z, required), then the project for a report that has a project scope (All projects, or one of the projects the role can report on), then **Generate** (the `BarChart01` icon, the one the app uses for reports). Generate saves the entry, shows "Report generated" and goes to My reports. Only Species Detail and Events, Occurrences and Observations have a project scope today (`ReportEntry.scoped`), so no other report asks for one; the Data Validation Error report has its own project and dataset selects and is not offered a scope here.
  - **What "generate" produces here, said plainly:** a saved run (`generated-reports-store.ts`, per browser like favourites): which report, the project, when. Opening it opens the report as it is now with that project already chosen (`?project=`, read by the two scoped reports). It is not a copy of the rows as they were: reports are live views and the app has no backend to keep a snapshot. If the designer meant a snapshot, or a file, that is a different build (the other two answers offered).
  - **Verified live (Playwright, 1708x1024, Registered User, zero console errors):** column 2 reads Reports, All reports, My reports, Actions, Create a report; My reports empty state; the dialog opens, an empty submit is refused (the report is required), choosing Species Detail Report shows the Project select (All projects, Adelaide Hills Bushland Survey, Flinders Ranges Reptile Atlas), Generate lands on My reports with the row (Species Detail Report, Adelaide Hills Bushland Survey, 6 Oct 2026 10:11); a Data Licence Agreement Report run has no project; opening the species row opens `/pages/reports/species-detail?project=adelaide-hills` with that project selected in the toolbar; Remove drops a row; the category tabs still work on All reports. `tsc`, eslint on `app/pages/_shared/reports` and `check:contracts` pass.
