# 2026-10-05 - Pages tool lists only the persona's pages and invites switching

- **Oct 5 2026: the Pages tool on the Prototype tools bar (`2026-10-05-09-*`) now shows only the screens the viewed persona can open, and hides every other one. From the designer: "Show pages relevant to the persona, and hide all the ones that do not apply. Encourage the user to switch between personas. If page access != persona, then do not fabricate / show that page in the route altogether."**
  - **Replaces** the earlier behaviour (a screen the role cannot use was dimmed with a lock and its reason). Now it is absent from the Tree and the Search view, and from the area counts. A screen the role cannot open but whose sub-screens it can would have those sub-screens moved up one level (no such case today).
  - **What counts as "not the persona's":** the same rule the lab used, `availability()` in `app/_prototype-tools/pages-map-data.ts`: the index's access ("Signed in", "BioData Admin", "BioData Super Admin") plus the bar's whole-page gates (`page-gates.ts`, the role-access matrix). The screens themselves are unchanged: a restricted page reached by its address still keeps its three columns and states the restriction (3.7); only the map stops pointing at it.
  - **Encouraging a switch:** the foot of the panel says how many pages are left out ("50 pages are not part of what Public user sees") and lists the other six personas as buttons with the number of pages each has (Super Admin 72, BioData Admin 64, BioData User 43, Privileged Admin 43, Privileged User 43, Registered User 43, and so on). A button switches the persona in place: the panel stays open and the tree redraws; if the page you are on is not open to that persona it goes Home, as the role tool does. The header now reads "N pages for <role>".
  - **Shared, not copied:** the persona switch (`useSetRole`, `app/_prototype-tools/role-switch.ts`) is one hook used by the "Viewing as" menu and the panel; the menu's behaviour is unchanged.
  - **Verified live (Playwright, 1708x1024, zero console errors):** Public user 22 pages in 6 areas (Start, Sign in, Home, Projects, Explore, Unlinked); Registered User 43 in 10 (adds Data licence, Nominations, Template Finder, Reports); BioData Admin 64 in 14 (adds Data sharing, User management, Taxonomy, Notifications); no lock icons anywhere in the panel; hopping from BioData Admin to Registered User from the panel keeps it open on the same page with 43 pages; a search for "voucher" as Registered User finds only the Voucher ID Update report, not Voucher Management. `tsc`, eslint and `check:contracts` pass.
  - **Not done:** a keyboard-only pass of the persona buttons, narrow windows, Privileged and BioData User personas by eye (the counts come from the same rule), and the Emil typography pass on the footer.
  - **Open for the designer:** (1) "Sign in" (10 screens: log in, sign up and so on) is open to Everyone, so it shows for signed-in personas too; they are not part of a signed-in person's journey, so hiding them for signed-in personas is a small step if wanted. (2) Areas with one screen (Start, Home, Template Finder) show as a group holding one row; they could show as a plain row. (3) Registered User, BioData User and both Privileged personas all have 43 pages, because the index and matrix do not tell them apart yet. (4) The 3.8 line, the screen-index route check, and deleting the lab, from `2026-10-05-09-*`, are still open.
