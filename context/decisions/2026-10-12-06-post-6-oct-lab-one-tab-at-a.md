# 2026-10-12 - Post 6 Oct lab: one tab at a time, search for anything, the records branch

- **Oct 12 2026: Post 6 Oct lab: one tab at a time, search for anything, the records branch.** The designer, from a screenshot of the rail and Home: "everything happens in one tab unless another tab is opened. Another tab is opened? Open Home. If the search icon is clicked, we need to open a new tab with the ability to search for anything. Let's look at project-detail first. Also, clicking on the tree/branch icon opens the branch bit on the projects." In `/proto/post-6-oct` only. Follows `2026-10-12-05-post-6-oct-lab-legal-links-end-the.md`.

  **Tabs are no longer one per page.** A tab holds a page and moving replaces it: a rail click, a link or row in the content, a task, a search result, the project switcher and a breadcrumb crumb all move the current tab. A new tab opens only on request: "+" opens Home (it was a project picker), the search button opens a Search tab (the open one is shown again rather than a second), and a Cmd or Ctrl click on a plain link opens a new tab beside the current one (a react-aria row cannot see the modifier, so only anchors do). This replaces the previous pass's "a page opened from another page opens beside it". The breadcrumb is the way back (Home, Projects, the project); there is no history stack yet. The pill's view is kept per tab and page.

  **Search is for anything** (`search-page.tsx`, rewritten): one field over the pages of the app, projects, species, data licence requests, data sharing agreements, nominations, users and notifications, each in a titled group with the typed text in bold, and scope tabs (All, Pages, Projects, Species, Requests, Admin) that appear only when they have results. Each role searches only what it can open, by the same feature checks the sections use (`dlaAccess`, `dlaAllView`, `dsaManagement`, `nominationAccess`, `userManagement`, `notificationManagement`), and a role that sees only its own requests searches only those. With nothing typed it lists every page, every project and the first species; records are searched once something is typed. A result moves the Search tab to the page when the lab holds it (a page, a project) and opens the real page when it does not yet (a request, an agreement, a nomination, a user, a notification).

  **The branch** (`branch-drawer.tsx`): the branch button in a project's bar (it was a disabled placeholder) opens the project's records as a tree, over the page from the left under the bar, so it takes no width from the content or "On this page". Same records, order and type icons as Project records (`recordIcon`), the first two levels open, each level folds. Picking a record opens Project records with it selected and closes the tree; picking the project at the top opens Project records with nothing selected. Escape, the close button or a click outside closes it. The button shows as pressed while it is open, and any view of the project can open it.

  **Open for the designer (CONTRACTS 0.4):** a back and forward for each tab (moving in place loses the page you left, apart from the breadcrumb); where a search result for a record the lab does not hold should open (the real page leaves the lab, and no record page is built here yet: the next step after the project page); whether "+" should offer a choice (Home, Search, a project) rather than always Home; whether the branch should dock beside the page (and push it) rather than slide over it; the rest of "look at project-detail first" is not yet described: the Overview and the branch are in, and more direction on the project page is welcome.
