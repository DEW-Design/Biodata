# 2026-11-16 - Duplicate is a control on the record, not rows in the Add menu

- **Nov 16 2026: Duplicate is a control on the record, not rows in the Add menu.** The designer, with a screenshot of a record's Add menu (Observations: Individual, Population, Non-biotic, Community, a divider, then four rows "Duplicate previous indi...", "...po...", "...non...", "...co..."): "this duplicate treatment is terrible. It should be a control on a record-level, as in in the 3 dot menu on the record. The current state looks like an anti-pattern." It reverses the placement chosen on 10 Nov (`2026-11-10-06-*`, the business's "Duplicate prev. record"), where Duplicate previous was a row for each type in each Add submenu and in the menu's search.
  - **Job and principles (0.10):** a person with edit access, on a record, wants another like it. 1 Say less (four cut-off rows, each saying "Duplicate previous" again, in a menu about adding), 3 One system (a record's actions are Add, Edit and its "..." menu, 4.6; NT detail and the vocabulary grids already put Duplicate, `Copy01`, in a "..."), 5 Make it obvious (the action sits on the thing it copies). Borrowed: the notification record's "..." (`nt-detail.tsx`).
  - **What changed (`app/pages/project-detail`):**
    - `record-quick-actions.tsx`: the record's "..." menu is Duplicate (`Copy01`, 3.12), a divider, then Delete record (destructive, below the divider, 4.6). The Add menu no longer has any duplicate row: not in the Events, Occurrences and Observations submenus, not in the search. It takes a new `onDuplicate(parent, option)`, given by the panel (`record-panel.tsx`) and the full view (`record-full-view.tsx`) as their own `onAdd`, so the add form opens exactly as it does for any new record.
    - `record-rules.ts`: `duplicateOptions` and `previousOf` (the "last record of the type" search) are gone; `copyOf(source, records, childrenOf)` says where a copy of a record would go (under the source's own parent) and returns the option that starts it, or null. A copy is offered exactly when that parent may take another of the same kind and type (`childOptions`), so an observation that is its occurrence's only one has no Duplicate (an occurrence carries exactly one observation), and the project has none. It is left out, never drawn dead (2.12, 3.15). `duplicateRecord` is unchanged: fields, dates, location and species carried; new code and sequence number; the name blank (named like any new record); nothing inside the source copied.
    - The comment at `records-explorer.tsx` `startAdd` and the headers of the two files above say where it lives now.
  - **Verified (live, Chromium, BioData Admin, Adelaide Hills Bushland Survey, Project records):** "..." on a Transect, an Occurrence and a Non-biotic observation under an event: "Duplicate", then "Delete record"; on an observation under an occurrence: "Delete record" alone; Duplicate on the Transect opens "New transect" with its description, Source ID, comment and dates, a new ID (TR00502) and the name as the placeholder "Transect 2"; Add transect saved it (28 to 29 records); the record's Add menu lists only the types in each submenu and searching "duplicate" shows "No matches"; zero console errors; `tsc`, `eslint` on `app/pages/project-detail` and `check:contracts` pass.
  - **Changed meaning, said plainly:** the old row copied the last record of a type (even one elsewhere in the project); Duplicate copies the record it is on, beside it. That is what a control on the record means, and it is the more predictable of the two; the old behaviour is gone, not kept.
  - **Not changed / open for the designer (0.4):** (1) **Add Project's "Duplicate previous project"** (`project-registration/duplicate-project.tsx`, `2026-11-10-05-*`, also the business's request) is a button in the form's first section that copies the project created most recently; by the same logic it would be a Duplicate in the project's own "..." menu. Left as it is until the designer says. (2) **The Table view** has no row menu, so Duplicate is in the record panel and full view only. (3) Roles other than BioData Admin, the narrow window and touch were not checked. Not committed.
