# 2026-10-23 - Data Validation Error Report: project and dataset are dropdowns on the toolbar, right of Filter

- **Oct 23 2026: Data Validation Error Report: project and dataset are dropdowns on the toolbar, right of Filter.** The designer, with a crop of the report's toolbar (a "Parameters 2" button and two chips, "PROJECT: BD-5137" and "DATASET: DS-2026-01003"): "back to data validation error report: I feel having parameters is weird. What if they sat as drop downs instead of the current state? Let's smartly move it to the right of the filters button."
  - **Clause overridden, named (0.1):** CONTRACTS 4.6 item 4 (15 Oct 2026) made parameters one button and a popover on every report and said "MUST NOT draw parameters as a grid of fields, a row of selects or a panel between the card and the toolbar". The designer's instruction overrides that **for this report only**, and the contract now says so as an exception under the sentence it overrides, with the reason (two linked choices that the whole report is about and that are changed often) and that another report takes the same only with the designer's say-so. It is not a precedent (0.1).
  - **What it is now:** the toolbar is one row, **search, Filter, Project, Dataset, then Columns at the right**. Project and Dataset are the design system's `Select` (small, 36px like the buttons beside them, 256px each), each with an `aria-label` and no label above, each showing what it is set to. The Parameters button, its popover, its count and the two chips are gone from this report, because what each is set to is what it shows. Measured at 1686, 1440 and 1280px wide windows: one row 36px high, in that order, Columns at the right.
  - **What each shows (a fix made on the way):** the first build gave each item a label and supporting text, and the trigger cut the label first ("B..." beside the full project name; the dataset's file with no id). Each is now one line with the code or id first and the name or file after it, "BD-5137 · Flinders Ranges Reptile Atlas", "DS-2026-01003 · flinders_bushland_assessment_01.xlsx": cut at the end when there is no room, never at the code, and the same line in the list. Only projects and datasets that had errors are offered, as before.
  - **Behaviour kept:** choosing a project moves to its newest dataset (BD-5137 to BD-5039 moved the table to REC0008 of that project), choosing a dataset changes the rows, both by mouse and by keyboard (Enter on the Dataset dropdown, ArrowDown, Enter: DS-2026-01017 to DS-2026-01031), and the search, filters, sort and page stay as they are across a change (checked: the search term stayed).
  - **How, so it is a variant and not a fork (1.6):** `ReportParameters` has an opt-in `inline` flag. `DataReport` draws `parameters.fields` right of Filter when it is set; `ParametersPopover` returns nothing for it. Every other report is unchanged (checked: Species Detail still has its Parameters button; the others have none, as before). Documented on `/patterns/report-toolbar`.
  - **Checked live (Playwright, Super Admin; zero console errors):** the three widths, the lists of options (two projects, four datasets for BD-5039), the choices above. `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` clean. Also checked: a Registered User (2 projects and 3 datasets for the first) and a BioData Admin (4 projects, 5 datasets for the first), each with the first project and dataset showing. **Not checked:** a window narrower than the row (it wraps, as the toolbar always did), Safari.
  - **Open, for the designer:** whether the other reports with parameters (Species Detail, and Events, Occurrences and Observations) should follow, so that the reports read alike; and, for anyone whose one project has one dataset, whether two dropdowns with nothing to choose are worth drawing (2.12) or should show as plain text (no role in the sample data has that case, so it was not seen).
