# 2026-10-23 - Edit screens: no Editing label, Fields per section, Add section, where the record sits

- **Oct 23 2026: Edit screens: no Editing label, Fields per section, Add section, where the record sits.** The designer: the "Editing" status confuses people. Fields should be managed per section, a section should be addable, the hierarchy should be obvious in the full view with full names and not just IDs, and the large tile behind the record's icon is not needed. Two choices were put to the designer and decided: fields are managed per section in the card's header (the record-wide "Fields shown" column goes), and Add section brings back a section the record type has that is not on screen. A user-named custom section was not chosen, because the data model has none.
  - **CONTRACTS 4.8 changed by designer decision.** Item 2: a card in edit mode keeps the brand border and halo, and MUST NOT say "Editing". Item 6: each card in edit mode has a "Fields" control with its count, a checklist of that section's fields, and "Add section" sits under the cards. Item 7 (new): the right column keeps the record's summary while editing, with where the record sits (shape, full name and ID for each step). Rules regenerated (`npm run contracts:rules`).
  - Full view (`record-full-view.tsx`): the "Editing" label is replaced by `SectionFieldsMenu` (`visibility-panel.tsx`), a quiet "Fields 6/10" button opening a checkbox menu. Ticks apply at once and Escape keeps them. Identifiers and required fields are ticked, disabled and marked "Always shown". `AddSectionMenu` lists the sections not on screen. Choosing one shows all its fields, adds it to the edit, and scrolls to and flashes it. The right column no longer swaps to `VisibilityPanel` (still in the file, now unused). The Record card stays in edit and view, with Type as the full name ("Event-Transect") and a "Where it sits" list from the project down, indented like the tree. Each step has its shape, full name, type and ID, and opens its record (not while editing). The header's 56px tile is gone: the shape sits in the eyebrow at the tree's size, and a species photo is kept.
  - Details panel header (`record-panel.tsx`): the 40px tile is gone, and the shape sits before the name at the tree's size.
  - The "Editing" label is also removed from the project page's cards (`project-tab.tsx`) and the taxonomy record cards (`tx-records.tsx`). They have no hidden fields, so no Fields control.
  - Kept, open for the designer: the sticky footer still reads "Editing every section · Unsaved changes" (CONTRACTS 4.8 item 4), as do the project and taxonomy footers. Asked whether that wording should change too. "Where it sits" is new label copy, to be confirmed. `VisibilityPanel` is unused and could be deleted.
