# 2026-10-02 - Data Ingestion report: the Record ID of a run with errors opens its Data Validation Error report

- **Oct 2 2026: Data Ingestion report: the Record ID of a run with errors opens its Data Validation Error report.** The designer asked whether clicking the record should link to the Data Validation Error report, as the Validation status chip and failure count already do (same day, earlier entry).
  - **Built:** in the Data Ingestion Report Pre-Flight Validation, the pinned **Record ID** of a run with errors is a link to `/pages/reports/data-validation-error?dataset=<id>` (role kept). It is brand-coloured text with an underline on hover, the link treatment the project field notes already use (`text-brand-secondary hover:underline`), at the Record ID's own size and weight (Barlow 14px medium, tabular figures). A run with no errors keeps its plain ID.
  - **Why only runs with errors:** the Data Validation Error report lists only datasets with errors, so for a clean run there is nothing to open (it would land on a different dataset). Which runs have errors is the error report's own rule (`hasErrors`), shared with the chip and the count. The coloured IDs therefore also say which uploads have errors.
  - **Verified:** `tsc`, `eslint`, `check:contracts`; live as BioData Admin: 14 of the 50 rows on the first page have a linked ID (all 4 Failed rows, plus the runs with business rule failures), clean runs have none; click and keyboard (Right arrow into the cell, Enter) both open DS-2026-01001's report; zero console errors.
  - **Open:** if the designer wants every ID to be a link, the error report would need a state for a clean dataset ("no errors"); not built. Not committed.
