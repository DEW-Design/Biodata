# 2026-10-02 - DLA and DSA audit logs: rebuilt for older records, system moves logged, local dates

- **Oct 2 2026: DLA and DSA audit logs: rebuilt for older records, system moves logged, local dates.** The designer reported that audit logs were not showing up in DLA and DSA.
  - **Cause (reproduced):** a clean browser shows every seeded record's log correctly, and moves made in the app are logged and survive a reload. The failure is a browser that already held requests or agreements saved before `history` was added: the version-1 migration gave them an empty log, so the Audit Log tab drew an empty bordered box (a 2px strip on DLA). Reproduced by stripping `history` from the persisted state.
  - **Fix 1, rebuild (`rebuildHistory`, `agreement-status.ts`):** persist version 2 rebuilds an empty log from what the record knows. A seeded record gets its seed trail; any other record gets "Submitted" on its submitted date and, if it has moved on, its current status on its last-updated date, with the note "Earlier steps were not recorded for this record." Nothing in between is invented (0.3). A draft gets one Draft entry.
  - **Fix 2, system moves (`autoTransitions`):** Approved becoming Active on the start date and Active becoming Closed the day after the end date were shown in the status but never logged, although the shared type documents `"System"` for them. They are now log entries by System, derived at read time, and `effectiveStatus` is their last step so status and log cannot disagree. An Approved record whose end date has also passed now reads Closed (it used to stop at Active). A status move or an edit starts from the resolved record, so these entries are saved with it.
  - **Fix 3, dates:** `todayIso` in `dla-data.ts` and `dsa-data.ts` used the UTC date, a day behind in Adelaide until 9:30am, so a move made in the morning was logged with yesterday's date. Both now use the browser's local date (`localIsoDate`), as User Management already did.
  - **Fix 4, empty state:** both Audit Log panels say "No status changes have been recorded for this request/agreement." if a log is ever empty, instead of a blank box. It should no longer be reachable.
  - **Verified:** `tsc`, `eslint` on the touched files, `check:contracts`; live browser as five roles: all 9 DLAs and 14 DSAs show a log whose newest entry matches the status, a version-0 and a version-1 persisted state both rebuild, the clock-driven cases log System entries, a new move is dated 2 Oct, zero console errors.
  - **Open:** other places that log status changes with `toISOString().slice(0, 10)` and so carry the same day-behind date: project-detail record creation dates (`record-form.tsx`, `record-inspector.tsx`, `records-explorer.tsx`) and the report data helpers; adding a location and editing a request are not audit events (the log is of status moves only). Not committed.
