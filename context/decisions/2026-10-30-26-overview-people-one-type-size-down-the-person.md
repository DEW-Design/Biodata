# 2026-10-30 - Overview people: one type size down the person block, and a rule between stacked people

- **Oct 30 2026: a person on the project page's Published by and Project managers cards is one type size from the name to the phone number, and stacked managers are divided by a rule.** The designer, with a screenshot of the Project managers card: "typography nightmare. also, needs vertical stack dividers to space out the content."
  - **What was wrong, measured.** Each person was a name (14px, medium, primary), then the organisation or team at **12px** with a 16px line, then the email and phone at **14px**: a small line between two larger ones, the fault CONTRACTS 2.9 already names (its origin: "a small 'where' line sat between two larger lines and broke the hierarchy"). The second manager began 16px under the first with nothing between them, so two people read as one block; the Published by card already had a rule between its contacts.
  - **Principles at stake (0.10):** 2 One thing first (a type ladder where each level is one step from the next), 3 One system (the same person is drawn the same way in both cards and as the shared `ContactCard` draws one), 9 Craft shows. They agree.
  - **Where the type came from (2.9).** The design system and the sibling that plays this role: `ContactCard` (`_shared/contact-card.tsx`), which sets a person's name `text-sm font-medium text-primary`, its organisation `text-sm text-tertiary` and its mail and phone lines `text-sm text-tertiary` with a 14px icon. The project page's team line now takes the organisation's classes, `text-sm text-tertiary`. Nothing new was defined; the role beside the name and the badge are as they were (4.7).
  - **Dividers.** Project managers: a rule, `border-t border-secondary` with 12px under it and 12px between the items, on every manager after the first, the same markup the Published by card uses for its contacts (0.9). The first manager has none: the card's title is directly above.
  - **A person's block does not change height by role.** It had `py-2` only for a role that can edit (the hover fill's padding), so the same contact was 8px taller to a BioData Admin than to a Public User. The vertical padding is always there now; the hover fill and the negative margin stay for the roles that edit.
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the file and `npm run check:contracts` pass. Live (Playwright, Adelaide Hills, zero console errors), `getComputedStyle` on every text in the two cards: every line is 14px with a 20px line height, the badge being the only 12px (the `Badge` component's own); the name is 500 in the primary colour and the role, team, email and phone are 400 in the tertiary colour; the rule sits between Maya Dewitt and Phoenix Baker, 20px under the last line above it and 20px over the name below it (12px of gap or padding plus the 8px each person block carries); Public User measures the same positions apart from the header height below. Typography QA (2.9, `/emil-typography` and `/emil-design-foundations`): one scale step (`text-sm`), weight and colour carry the levels, no figure on these cards changes while a person looks at it, so no tabular figures are needed.
