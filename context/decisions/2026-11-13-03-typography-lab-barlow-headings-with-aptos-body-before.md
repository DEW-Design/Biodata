# 2026-11-13 - Typography lab: Barlow headings with Aptos body, before and after

- **Nov 13 2026: Typography lab: Barlow headings with Aptos body, before and after.** The designer asked for `/proto/typography`, "title in Barlow + Aptos for body", strictly on proto. Job: the designer, comparing today's type (Barlow everywhere, CONTRACTS 2.2) with Barlow titles and Aptos body, on the real screens, before choosing. Principles: 3 (one system: a typeface is one decision, so the lab changes it once, at the variable every component reads), 4 (tell the truth: real screens and real components, not a mock-up), 9 (craft shows: measured, not eyeballed), 8 (read at the real sizes). Nothing outside `app/proto` and the lab's line in the `/proto` index changed: no component, token or product screen.
  - **Built:** `app/proto/typography/page.tsx`, three views on `LayoutOptionSwitcher` (4.4): A Before (the real screen as it is), B After (the same screen, headings Barlow, the rest Aptos), C Side by side (a specimen of real components, `Badge`, `Button`, `Input`, headings and a label/value list, at true size, Barlow beside Aptos). A and B take a screen: the project page, the Projects list, Add project (framed same-origin, as Biodata Admin). Registered in `app/proto/page.tsx`. Not in `production-routes.ts` (nothing is folded into a page).
  - **How "after" is made:** every component sets its face through `font-barlow`, which reads `--font-barlow`, so the lab changes that one variable on the body (in a frame, through one style element added to the frame's document, never an attribute on a node React draws: the first version set attributes and caused hydration errors in the frame) and puts headings, and the header's "BioData SA" wordmark, back on the original face. A title on these screens is a real heading (h1 24px, h2 18px, h3 14px, all semibold). The frame's own Prototype tools bar is hidden so there is one bar.
  - **Aptos is read from the machine, nothing is shipped:** it is a Microsoft font with no web licence in this repo and it is installed here (`~/Library/Fonts`). The lab detects it and says so on a machine without it (fallback Segoe UI or the system font). **Aptos has no Medium (500):** it has Light, Regular, SemiBold, Bold, ExtraBold and Black, so text the product sets at 500 (labels, buttons, table names) draws at Regular in "after", and `font-synthesis: none` stops a fake one. The lab says this on the page.
  - **Measured (Chromium, 1600px):** headings and the wordmark Barlow, body Aptos, in A, B and C; text width Barlow to Aptos at the same size is within 2 per cent (a value 183.9 to 187.0px, the hint 226.4 to 227.5, a form label 100.5 to 98.9, the outline's longest label 198 to 200, the Approve button 51.7 to 51.2), so layouts hardly move; the specimen's headings are identical in both. Zero console errors on a single load of each view; `tsc`, `eslint` and `check:contracts` pass. Not measured: contrast and weight rendering side by side at 12px (Aptos reads larger at the same size, x-height; judged by eye only), other roles, a Windows machine.
  - **Not decided (0.4):** whether to adopt it. If so it is a token change (`--font-barlow`, 2.2's wording "Product UI, generated screens and every DEW component are Barlow", the `font-barlow` on portaled content, and a licensed way to serve Aptos, since the deployed site cannot read a font from a visitor's machine), which is the designer's decision and a clause change (9.4). The designer's earlier "title in Barlow" would also need "title" defined: headings only, as here, or also card and section labels that are not headings. Not committed.
