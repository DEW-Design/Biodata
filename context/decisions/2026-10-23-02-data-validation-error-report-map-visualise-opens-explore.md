# 2026-10-23 - Data Validation Error report: Map visualise opens Explore on the dataset, with coordinate outliers

- **Oct 23 2026: Data Validation Error report: Map visualise opens Explore on the dataset, with coordinate outliers.** The designer asked for Map visualise on the report, "also, outliers?". Asked two questions: where it opens (chosen: Explore filtered to the dataset, with a way back to the report) and what outliers mean (chosen: coordinate outliers on the map). Told that Explore has no notion of a dataset and could not show error records on its own; the designer chose "Explore plus an error layer". This closes the open item of the 2 Oct entry (a disabled primary action).
  - **Built:**
    - The card's white "Map visualise" button is enabled and goes to `/pages/observations?dataset=<run id>` with the role kept.
    - Explore's first layout reads `?dataset=` and, when it is there, shows `DatasetErrorMap` (`app/pages/observations/dataset-error-map.tsx`) in Explore's own shell, map, zoom buttons, key and floating card, in place of the search. The Explore search is not run in this view; "Search Explore" leaves it. The second layout ignores the parameter.
    - The card has "Back to report" (to `/pages/reports/data-validation-error?dataset=`), the dataset and project, an "All errors" and an "Outliers" tab (both with icons, 3.13) in Explore's own result cards, outliers first. A dot or a card opens an error summary card on the right (Escape or X closes it).
    - Colours: red for a record away from its species' cluster, orange for a record outside the project extent, grey for any other error, brand for the typical cluster, drawn only while a species outlier is chosen. The project extent is the dashed outline Explore draws for an area a location must sit inside.
  - **Where a record is (derived, never read, 0.3):** in `data-validation-error-report-data.ts`, `ErrorRow` now has `location` (the point of the real occurrence its species came from, nudged about 1 km, from its own generator seeded `<run id>|where` so species and rules do not change) and `outlier`. A species outlier takes the point of a real occurrence 12 km or more from the species' cluster; an out-of-extent record the point of one outside the extent; so both are on land, and the distance in the description (CM-SPECIES-OUTLIER) is now the real distance between the two points (it was a random 12 to 260 km). A project with no occurrences of its own now takes the occurrences within 60 km of one seeded occurrence (it took the whole state), so a dataset is one place; this changes which species those datasets show. The extent is a derived circle that holds the dataset's occurrences (12 km at least), not a registered one: only one project has a registered extent in the data. A record whose occurrence is restricted for the role is drawn as a block and one hidden from the role is left out (record-access.ts).
  - **Verified:** `tsc`, `eslint`, `check:contracts` (it first failed 3.13 on the tabs, fixed with icons). Live at 1440 x 900 and 1024 x 700 as BioData Admin and Registered User: the button is enabled and opens the dataset; counts agree (DS-2026-01001: 41 errors, 12 outliers, 7 red and 5 orange dots); Escape closes the summary without changing anything; Back to report returns to the same dataset with the role; an unknown dataset shows "No errors to map"; zero console errors. Typography measured against Explore's own card: the title is Barlow 16/600 like "Search the map", body 14/400, eyebrow 12/600 uppercase from `RecordPeekCard`.
  - **Not exercised live:** the restricted-block path (every template, so every dataset, is flora and none of the flora is restricted); the stacking of several records at one point (a dataset with one species has one point, so its errors sit on top of each other and the list is how to tell them apart).
  - **Open:** the second Explore layout has no dataset view (it is still a comparison option, 4.4); the record summary's eyebrow uses the existing `text-quaternary` (about 3.3:1) copied from `RecordPeekCard`; "Download error report" still has no coordinates (they are derived, so they are not in a file).
