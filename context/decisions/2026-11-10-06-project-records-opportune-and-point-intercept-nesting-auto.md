# 2026-11-10 - Project records: Opportune and Point intercept, nesting, auto-name, persistence, Duplicate previous

- **Nov 10 2026: the business's comments on adding an event, occurrence or observation to a project (Tranche 2 items left out).** Job: a person with edit access to a project builds its Survey records by hand. Principles at stake: 3 One system (the new types and the nesting go through the add menu and record form that already exist), 4 Tell the truth (no description invented for Point intercept), 6 Reveal in steps (Site dates stay out of view until asked for), 7 Design every state. Closest page: the project page's Project records tab, its Add menu (`record-quick-actions.tsx`) and the record form (`record-full-view.tsx`).
  **Two new event types, Opportune and Point intercept** (`survey-data.ts`, `record-rules.ts`, `search-data.ts`). They are in `SurveyEventType`, `SAMPLING_TYPES` (so the Add menu, the records filter and the sample switch take them), the system codes (`OP00501`, `PI00501`: proposed, the business gave none) and the Explore type icon map (`Car01` and `Target02`, neither used elsewhere; a record in the tree is marked by its kind's shape, not an icon per type, so no other icon was needed). They use the sampling events' own sections. Opportune carries the business's words, "A one-time visit, for example a road kill". Point intercept came with a name and no description, so it has none (0.3). Explore's seeded events have none of either type.
  **Nesting.** Any event can hold any event, to any depth, except a Site (still only under the project) and a Ramble inside a Block. `canContain` (`record-rules.ts`) is the one test: `childOptions` reads it, and so does the edit store's `addRecord` (no path that adds a record can break the rule). Nothing moves a record between parents today. A Visit used to hold no events and now can. An observation or occurrence can sit under any event or sub-event; an occurrence still holds exactly one observation of its type.
  **Auto-name.** A record saved with no name is named by its type and a sequence number: "Opportune 1", "Transect 2", "Individual occurrence 1", "Community observation 2" (`autoName`). n is one more than the records of the same kind and type already in the project (the seeded Transect counts, so the first one added is "Transect 2"), moved on past a name that is taken. The name is no longer a required field: it shows the name it will get as its placeholder, so what a blank gets is visible before saving (`card-editor.tsx`, `missingFor`, `fromDraft(draft, records)`). The name row of the record is kept in step.
  **Persistence** (`edit-store.tsx`). The records a person adds, and later edits and deletes of those, are in a zustand `persist` store on localStorage (`biodata-project-added-records`, by project id, `skipHydration` with `useRehydrate`, the same plumbing as the other stores). The seed's own records, the registration fields, attachments and edits to seeded records stay session only, as before. An added record whose parent is gone is not shown. To reset: clear that key, or Clear site data. Attachments added to a new record are not persisted (a file cannot be kept).
  **Site dates, optional.** A Site gets a "Temporal details" section (Start date, End date, Duration, Date accuracy), every row marked `optional` on the row (`MetaRow.optional`). It starts as "Not provided", so it is left out of view and out of the edit form like any empty concept, and comes back with Edit, Add section (the existing way to put back a section that is not on screen) or Manage concepts. A row marked optional is not locked on in Manage concepts, whatever its label (`field-visibility-store.ts`: "Start date" is otherwise a required label). Dates use the date field with a calendar (2.11); a Site's End date is checked against its own Start date, not the date the record was made.
  **Duplicate previous** (`duplicateOptions`, `duplicateRecord`; the row is in the Add menu, `record-quick-actions.tsx`; `records-explorer.tsx` starts it). In each kind's submenu, and in the menu's search, a "Duplicate previous <type>" entry (icon `Copy01`, 3.12) for each type that may be added there and has a record to copy: the last of its kind and type under the same parent, else the last in the project. A type with nothing to copy has no entry (2.12). It opens the add form as a copy: fields, date, location and species carried, new code, new sequence number. **The name is not carried** (names are generated), so it is blank and named like any new record; nothing inside the source is copied (no children, notes or attachments). Not built for a Project (Add Project is another task).
  **Sample switch (3.14).** The add form's samples have names and descriptions for both new types and the Site's optional dates (Start before End). Checked: Opportune, Point intercept and Site fill and save.
  **Verified (live, 1440x1000, scrollbars drawn, fresh context, BioData Admin, zero console errors):** Opportune twice under a Site, blank name, "Opportune 1" and "Opportune 2"; Point intercept under the project with a typed name; a Transect inside an Opportune and a Community observation inside that Transect, blank, "Transect 2" and "Community observation 2"; a Block's Events menu has no Ramble and no Site, an Opportune's has Ramble and Visit; Duplicate previous opportune under a Site, "Opportune 3"; after a reload all six are there once (34 records); Site, Edit, Add section, Temporal details, Start 1 Mar and End 15 Mar saved and shown, and an End before the Start shows "Can't be before the start date". `tsc`, `eslint` on `app/pages/project-detail` and `search-data.ts`, `check:contracts` pass.
  **Not verified.** Registered User and the other roles (edit access to this project is a BioData Admin here); a narrow window; touch; the Table view and the project's Species tab with the new types; Duplicate previous for an occurrence or observation (the code path is the same, not run); deleting an added record and reloading; two tabs open at once. `record-form.tsx` and the legacy `AddChildMenu` (unused, see 2026-11-10-02) were only kept compiling.
  **Open, for the designer (0.4).** (1) The description of Point intercept. (2) The codes `OP` and `PI` and the Opportune and Point intercept icons for Explore. (3) Whether edits and deletes of the seeded records should persist too (now only what was added does). (4) Whether a Visit inside an event, and a Visit inside a Visit, is meant ("any event can have any event" was taken at its word). (5) Whether the sequence number should count per parent instead of per project. (6) Whether the name should still be asked for on an existing record that is emptied (it is now named like a new one). Not committed.

- **Nov 10 2026, continuation: the business's own frames for Opportune and Point intercept.** The two types no longer use the sampling events' shared sections; they follow the business's "Event - Opportune" and "Event - Point Intercept" frames, as transcribed by the coordinator (`survey-data.ts` `frameEventSections`, picked by `eventSections` through `hasOwnFrame`).
  **Sections, in the frame's order.** Details (ID, name, Description, Source ID, Record status, Observers), Location information (the map, then Location method, Datum, Reliability, Sample site dimensions for an Opportune only, Location comment), Temporal details (Start date, End date, Date accuracy, Duration, Observation time) and Comments (Comment type, Comment). No Photopoint, IBRA, separate Observers or Custom properties section: the frames have none. Location method, Datum and Reliability start as "Not provided" for these two (the other events carry a placeholder GPS, GDA2020, 1, which would be a value nobody gave). Record status and Comment type are code lists the business has not supplied: they are `vocab` rows holding "Not provided" with nothing to pick (0.3), so they are empty dropdowns until the Control Vocabulary supplies the lists. Observation time is a text row: the product has no time field (the frame does not say which control).
  **Rules the frames carry.** (1) Location comment is compulsory (`MetaRow.required`): it cannot be hidden in Manage concepts (`field-visibility-store.ts`), is starred, shows "This field is required" inline and "Details missing" above (`missingFor`). (2) Start date: when none is given on an Opportune or Point intercept inside an event, it takes the parent's (`inheritsStartDate`: the form opens on the parent's date, an emptied field is not an error, and `fromDraft` fills it from the parent on save); under the project there is no parent and it is asked for as before. The frame's note is the rule and is not drawn as copy (2.12). (3) A Point intercept's geometry is one coordinate point: `LocationField` has an opt-in `pointOnly` (field-controls.tsx), which draws Latitude and Longitude (six decimals, no shapefile, draw, list or radius) and keeps the "must be inside" check against the project and the parent. The coordinator's "same `allowed` mechanism" is the list of areas a location must be inside; there was no way to restrict the picker's methods, and `GeoExtentPicker` is in `project-registration` (not mine), so the control is built beside `LocationField`. An opt-in `methods` prop on `GeoExtentPicker` would be the single home (1.6, 1.10) and is the designer's and Fork C's call. (4) A Point intercept must be a child event: never offered directly under the project and refused by `canContain` and the store's `addRecord`; it is offered under any event, an Opportune included. "Duplicate previous point intercept" follows (it comes from `childOptions`), so the project's menu has none. An Opportune stays allowed under the project.
  **Observers as a row.** The observers editor, the draft and the save now find the row by its term (`recordedBy`) wherever it is, so the same `ObserversControl` serves the Observers section of the other events and the Observers row in Details of these two (`record-form.tsx` `toDraft`, `fromDraft`, `isPlainRow`; `card-editor.tsx`; the record's side card in `record-full-view.tsx`). No second control.
  **Sample switch (3.14).** Both types are answered whole: Location comment, Source ID, Observation time, End after Start, observers, every concept shown; a Point intercept is sampled inside the parent it is being added to.
  **Verified (live, 1440x1000, scrollbars drawn, fresh context, BioData Admin, zero console errors).** The project's menu offers Opportune and not Point intercept (nor a duplicate of one); Opportune under the project has the four sections and no Photopoint, IBRA, Custom properties; saving it blank shows "Details missing" and the required message on Location comment, and saves once it is filled; with the sample on, every frame row is on screen, a Point intercept has no Sample site dimensions and a location that is Latitude and Longitude only; a latitude outside the parent Site is refused with the warning, one inside is saved (-35.0302, 138.7203) and shown in the location table; the start date opens as the Site's (2 Nov 2025) and an emptied one saves as 2 Nov 2025; an Opportune offers Point intercept, Ramble and Visit and no Site; Point intercept under an Opportune and Duplicate previous point intercept under a Site; edit shows Latitude and Longitude only; after a reload the added records are there once (31 records). `tsc`, `eslint` on `app/pages/project-detail` and `search-data.ts`, `check:contracts` pass.
  **Not verified.** Roles other than BioData Admin; narrow window and touch; the Table view and Species tab; editing an existing Opportune's Observers row end to end (the draft path is shared and compiled, not driven); Observation time, Record status and Comment type with real data (none exists).
  **Open, for the designer (0.4).** (1) The truncated notes on Geometry/Location ("Typically should have its own g...", and on Point intercept "Must be a child event, Optiona..."): the child-event rule is taken from the visible words; whether "Optional..." says the Point intercept is optional under its parent, or that something about its location is optional, is not readable. (2) The Record status and Comment type lists. (3) A time control for Observation time. (4) The meaning of the bold type on Location method, Datum, Reliability, Date accuracy (not read as required). (5) Whether `GeoExtentPicker` should take a `methods` prop instead of the extra control. (6) A new Opportune or Point intercept shows only what has a value or is required, like every record (Record status, Observation time, Comments and the rest come in through Add section or Manage concepts); whether these two should open with the whole frame shown is a convention change for the designer. Not committed.
