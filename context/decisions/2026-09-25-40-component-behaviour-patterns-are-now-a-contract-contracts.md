- **Sept 25 2026: component behaviour patterns are now a contract (CONTRACTS.md 1.9), and the Escape-clears-the-selection bug is fixed at the component, per designer feedback ("follow the correct behaviour pattern... this applies to all design system components... if it isn't there, add it").** Read as: the standing gap logged six times above ("pressing Escape in a `MultiSelect` clears its selection", never fixed) is a behaviour-pattern violation, and there was no clause that said components must behave as their standard pattern. **Cause:** react-aria's `ListBox` defaults `escapeKeyBehavior` to `"clearSelection"`, so Escape inside an open `MultiSelect` wiped everything chosen. **Fix, once, in the components:** `escapeKeyBehavior="none"` on the multiple-selection `ListBox` in `MultiSelect` and `TagSelect` (the only two in `components/**`), so every consumer (Explore's park and filter pickers, Add Project, the DSA and DLA forms and more) gets it with no call-site change. **Contract 1.9:** a component behaves as its WAI-ARIA pattern; Escape closes and never changes a committed value; selection applies live and closing keeps it; the keyboard is complete (Tab, Arrows, Enter, Space, focus back to the trigger); every state is real; a behaviour change is tested by keyboard on every screen that uses the component. Origin lines name this bug and `Tab`'s `badge={0}` "0". **Enforcement:** `AUTO §1.9a` (`scripts/check-contracts.mjs`) fails a multiple-selection `ListBox` in `components/**` without `escapeKeyBehavior`; verified it fires when the prop is removed and passes when restored. Adding a clause is not a loosening (9.4), but the change to the contract file and script is itself flagged in the next audit. **Not covered (no automatic check):** the other items in 1.9 are `REVIEW`. **Left as is on purpose:** Escape clearing a table or tree row selection is react-aria's standard grid and tree behaviour, not a popover, so it stays. Verified live on Explore option 3 (Location, 17 parks): two parks selected, Escape closes the popover and both stay selected (2 area chips), zero console errors; `tsc`, `eslint` and `npm run check:contracts` clean.
