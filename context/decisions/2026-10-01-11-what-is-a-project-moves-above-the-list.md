# 2026-10-01 - What is a project moves above the list as an explainer card

- **Oct 1 2026: What is a project moves above the list as an explainer card.** Page feedback on the Projects list (Registered User): the "What is a project?" content can be presented much better above the table, the way Nominate Sensitive Species presents its review steps, as a closable banner that, for the demo, comes back on every refresh; look at Mobbin for patterns. Mobbin (Airwallex's closable intro card, Felt's welcome banner with guide cards, Remote's info strip, Jira and Coda's heavier quickstart and tour) was proposed from and the designer agreed to: the nominations-style card, the four non-link guides dropped in favour of the one "Open resources and user guides" link, the same card for a public user, and the existing copy reused. New shared `ExplainerCard` (`app/pages/_shared/explainer-card.tsx`): a bordered card with a small heading, an optional lead, the subject as a row of steps (numbered for a sequence, an icon each for a structure), one link, and a close control; the closed state lives in the module, so it survives moving between screens in a visit (All projects to My projects does not bring it back) and returns on a reload. The Projects card ("What is a project?", inside `ProjectListContent` between the section header and the search) shows the structure Project, Site, Visit, Occurrence, Observation with the records-tree icons (now one map in `_shared/record-icons.ts`, re-exported by `record-inspector.tsx`) and one line per level cut from the existing copy (drafted from the BDBSA fact sheets, not sourced product copy, still to be content reviewed). It is shown to every role except BioData Admin (`showsProjectExplainer`, renamed from `showsProjectsGuide`), including a signed-out visitor; column 2 is now the All / My switch and Actions only, and `projects-guide.tsx` is deleted. Nominations' "How a nomination is reviewed" card now uses the same component, so it gains the close control. Contrast fixed in the shared card: the stepper fades an unfinished step to 60%, measured 2.9:1 for titles and 2.4:1 for descriptions; restored to full strength (7.5:1 and 5.3:1), which also lightens the nominations card the designer had liked. The contract: 3.10 gains where the information goes and a second origin, and `AUTO §3.10` now also flags a left-hand aside that renders a component whose own markup holds a heading, steps, alert, accordion or task card (the project block slipped past the old check because its headings were in a component's file; two occurrences of the same mistake, so the check was extended, section 0.8), proved with a synthetic violation; the new pattern is documented on `/patterns/banners` (live closable example), in `nav.ts`, the README and `ref-shell.md`. Verified live: Registered User (card, steps, link, close, My projects keeps it closed, reload brings it back, the table still fits the viewport), BioData Admin (none), Public user (shown), nominations (card and close), the docs example, 1100px wide (steps wrap, nothing breaks), zero console errors; tsc, eslint, check:contracts and the build pass. Open: the card pushes the table down about 240px, so on a short window the table shows fewer rows (closing it gives them back); the eyebrow label style is the app's existing section-label style at 3.4:1, left as is; the deleted guide descriptions (Getting started, Video tutorials, Policies, Downloads) are gone from the app until guide pages exist.
