# 2026-11-10 - Every form has the Pre-fill sample content switch: files and branches covered

- **Nov 10 2026: the switch on every form, and the sample covers files and branches.** The designer: "QOL updates: If there's a form, let's have a fill sample content toggle. Also, for file uploads, etc, let's add that to the scope of fill sample content. Let it cover branching questions as well. good ux." Until today only Add Project had the switch (16 Oct 2026, kept across a refresh on 30 Oct). It is Scaffold (1.5, 3.8): it previews a form, it is not product.
  **Shared pieces (lead).** `useSampleContent` (`app/_prototype-tools/sample-content.ts`) takes an optional `files: { sample, add, remove }`: switching on adds the sample's files as if the person had, switching off takes out the ones the sample added, by name, and leaves the person's own. `useFileQueue` has a new `removeByName`. New `app/_prototype-tools/sample-files.ts`: `sampleFile` (a file of a believable size and the right type, named "sample-..."), `sampleWorkbook` (a real xlsx, SheetJS loaded on use, for a form that reads the sheet) and `sampleEvidenceFiles`. The header comment of the hook states the two rules: a question that branches is answered down its fullest branch, and a file upload is filled.
  **Forms done** (each with its own `*-sample.ts` beside it; the form only wires the hook; six parallel passes, then checked together): the nomination form (species and location); the Upload dataset form; Add Project option 1 and 2 including the Datasets step; DLA request and DSA; Notification and Controlled Vocabulary; New user, New role and New permission; the four Taxonomy changes (Append, Split, Combine, Rename); the add-record form for the 13 record types (`record-full-view.tsx`); every project edit card; and the modals that take more than one answer or a file: DLA Approve, the project attachment and web link modal, Bulk attach, Create report, and the Conservation significance scoresheet on Site scores.
  **What "the fullest branch" meant in practice:** nomination, a subset with a Location area and an Evidence of presence attribute, the three answers and "Yes" with where and the files; dataset upload, a real workbook with two columns the vocabularies do not have (so the Custom concepts section appears), First Nations "Authorised" (so the approving-authority field appears), plus a PDF; Add Project, a third contact with role Other, focus area Other, Systematic with an Other methodology, restrictions "Yes" with all five kinds, permit type None required, and the Datasets step's files; DLA, two locations, one at Level 3 so its project checklist opens; DSA, Offline and System with two systems and a PDF; Notification, a weekly schedule (not an event) with To, CC and BCC, the log kept "until a date", and two attachments; Vocabulary, a Reference vocabulary with four entries, custom columns and an end date; Split, Combine and Rename on real seeded taxa with the renames they ask for.
  **Honest (0.3).** Placeholder people only, example.com addresses, real organisations and species from the build's own lists. Left empty on purpose because any value would be invented: permit numbers, the URI or DOI, and phone numbers (DLA uses the numbers the ACMA reserves for fiction). The approving-authority reference on the upload form is a placeholder.
  **A bug found on the way.** The Notification and Controlled Vocabulary shells each registered their own "Sample size" tool under the id `sample`, the id of the switch, and a tool of the same id replaces the other, so the switch never showed on those two forms. Both are now `sample-size`; nothing else under `app/pages` used that id.

Shown to bite with a throwaway form, then removed.

A live sweep at 1440x1000 with scrollbars drawn, a fresh browser context per form, all 16 full-page forms: the switch is on the bar; switching on fills it; switching off returns the starting state (the sample files go, the person's stay); switching on again refills; a reload with the switch left on fills at mount; zero console errors in all 16.
