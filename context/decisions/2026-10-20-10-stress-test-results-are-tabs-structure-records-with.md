# 2026-10-20 - Stress test results are tabs: Structure, Records with status, Summary

- **Oct 20 2026: Stress test results are tabs: Structure, Records with status, Summary.** Designer: "I need to quickly see which records have errors and which are valid ... The summary report upon ingestion could be a tab." Lab only (`app/proto/data-model-stress-test`).
  - **Layout.** The file bar (name, record count, "N valid", "N with errors") now sits above everything and stays visible on every tab. Beneath it, underline tabs with icons, as the project page's Datasets view does (borrowed, CONTRACTS 0.9; icons per 3.13): **Structure** (`Dataflow01`: the tree and the record card, as before), **Records** (`ClipboardCheck`, the Validation icon), **Summary** (`Grid01`, Overview: "How the tabs were read", the notes and the 3-tier download, shown only when the upload had more than one tab or file). `Dataflow01` is new to the 3.13 icon list; this is a lab, so the list in CONTRACTS.md is not changed here.
  - **Records tab.** Every record with a status badge (Valid, or N errors), its name, kind and type, the tab it came from, and its error messages inline (first two, then "+n more"). A filter above it: With errors (n), Valid (n), All (n); it opens on With errors when there are any, since that is what it is opened for. The Structure tree keeps no error styling, as the designer asked earlier; the checks show here. Choosing a row opens that record in the Structure tab, where its card lists every error. The "From" column appears only when records have a source, and shows the tab name alone when there is one file.
  - **Lazy.** The list pages at 100 rows with "Load N more"; the tab is built only when opened. On the 12,072-record workbook it opens in 0.27 s with 2,597 DOM nodes. The Structure panel stays mounted (hidden) while another tab is open so the tree keeps what was expanded and loaded; it builds only what is open, so this costs nothing measurable.
  - **Verified (ran).** `tsc`, `eslint` on the folder, `check:contracts` clean. Live in Chromium, no console errors: sample data (8 errors, 10 valid; filters show 8 / 10 / 18), Heathfield file (8 errors, the same 8 plant rows; Summary tab and download present; tree rows 54 before and after a tab round trip; opening an errored row lands on Structure with its error), the 12,072-record workbook. Not run: a keyboard pass over the tabs and the filter (react-aria tabs, not exercised by key) and the typography skills (§0.6 item 8; the table reuses the existing `Table`, `Badge` and the `text-xs text-error-primary` issue line from `RecordCard`).
  - **Open.** (1) Should the Records tab also offer search, or a filter by error kind (all "Association Dominance" rows at once)? With thousands of rows that is the next question. (2) Should the "N with errors" figure in the file bar jump to the Records tab, filtered? Not committed.
