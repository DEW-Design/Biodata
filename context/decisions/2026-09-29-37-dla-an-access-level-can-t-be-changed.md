# 2026-09-29 - DLA: an access level can't be changed once granted, per direct instruction ("User cannot change the type of access - if L2 is granted, L3 can't be asked - that has to be a new request")

- **Sept 29 2026: DLA: an access level can't be changed once granted, per direct instruction ("User cannot change the type of access - if L2 is granted, L3 can't be asked - that has to be a new request").** A request's own level (Level 2 or Level 3, per location) is a decision the business's workflow sheet already treats as final once made - "the status shall remain as Approved... until the date... becomes active" (`agreement-status.ts`) - so Approved and Active both mean the level is granted, not just Active. Getting the other level for that same location is a new DLA request, the same "Renew creates a new record" precedent this workflow already applies to a Closed agreement.
  - **The loophole this closed:** `canEdit` (`dla-detail.tsx`) used to include `approved`, so a requester could reopen `/pages/dla/<id>/edit` on an Approved request (level and grant period already decided by an admin) and flip a location's Level 2 to Level 3 - `saveDla` keeps an already-past-Draft request's own status unchanged on edit, so this would have landed silently, with no re-review at all. The edit route itself also had no status guard of its own, so even hiding the Edit button wouldn't have stopped a direct URL visit.
  - **Fix, one source of truth for both:** a new `isDlaEditable(status)` (`dla-data.ts`) - true for Draft/Submitted/Under Review/On Hold only - now backs both `dla-detail.tsx`'s own `canEdit` (the Edit action disappears once Approved) and a `useEffect` guard in `edit-dla-page.tsx` that redirects a direct visit to an Approved/Active request's edit URL back to its deep dive with a `toast.warning` explaining why, rather than only hiding the button.
  - **The deep dive says why, not just omits the button:** each `LocationCard` (Approved or Active only - Closed already has its own "Renew Licence" banner) now shows, under its License Category badge, "This is the granted level and can't be changed here. Need Level {the other one} instead? Submit a new request", linking to `/pages/dla/new`.
  - **Known related gap, not fixed (out of this task's scope, DLA only was asked for):** `dsa-detail.tsx` has the identical `canEdit` (includes `approved`) and `edit-dsa-page.tsx` has no status guard either - the same loophole exists for DSA and should get the same fix.
  - Verified `tsc --noEmit`/`eslint --max-warnings=0` clean on every touched file, `npm run check:contracts` clean, and live (Playwright, 1400x1000): an Approved request (`DLA-2026-00510`) shows the locked-level note and no Edit action; visiting its `/edit` URL directly redirects to the deep dive with the warning toast; an Under Review request (`DLA-2026-00502`) still opens its edit form normally. Zero console errors. Not committed.
