# 2026-10-23 - Behaviour is a component: contract 1.10, and the behaviours built outside components today

- **Oct 23 2026: Behaviour is a component, so it is built in `components/**`; contract 1.10 and checklist item 9.** The designer, after the agent reported that the one scrollbar (`2026-10-23-68`) lives in `app/_scrollbars`, outside `components/` and so unseen by the component check: "component behaviour falls under components. We need to make sure this is factored in. that's a gap, and we'll need to address it going forward."
  - **The gap, in the contracts' terms:** 1.1, 1.4 and 1.7 define a component by where its file is (`components/**`) and what it draws. The override, the inventory (`contracts/component-inventory.json`), the duplicate check, the doc page (5.3) and the behaviour patterns (1.9) all start there. A behaviour built in a screen, in `app/pages/_shared`, in an `app/_*` folder or in the layout is invisible to every one of them. Nothing in the contracts said that a scrollbar, a dismiss or a way of cutting text is a component; the agent put the scrollbar in `app/_scrollbars` and mounted it from the layout, `npm run check:contracts` passed, and the daily audit (which lists "new or changed components") could not see it.
  - **What was added (CONTRACTS.md; the scoped files regenerated):**
    1. **1.10 Behaviour is a component** (scope `build`, so it loads when anything under `app/**` or `components/**` is read): a behaviour more than one screen has or could have is built in `components/**`, tier `custom` until promoted, with the designer's override and a doc page; MUST NOT be built in a screen, `app/pages/_shared`, an `app/_*` folder or the layout, or written inline in a screen file; a screen takes it by a prop or an attribute; look in `components/**` first (0.9) and extend by an opt-in prop (1.6) rather than write a second; the root layout renders components from `components/**` only. Origin names this entry's trigger. Open items are named in the clause (below).
    2. **0.6 item 9:** the end-of-task checklist now asks where each behaviour lives, and the report says so.
    3. **`AUTO §1.10`:** `app/layout.tsx` fails the check if it renders a component imported from `@/app/**`, except the one open exception named in the check (`@/app/_scrollbars/drawn-scrollbars`). Shown to fail with the exception removed (it names the import), then restored.
    4. **`ref-ingest.md`** (new component workflow, step 1): "behaviour is a component", look in `components/**` first.
  - **What the check cannot do, said plainly:** it finds one thing, a component mounted from the layout. Which inline effect or `_shared` hook is a behaviour another screen could want is a judgement, so the rest is `REVIEW`, named in the clause as a recurring pattern: the first thing to look at in any new `useEffect` that listens on the document.
  - **Open, found while writing it, each for the designer's decision (0.4); nothing was moved, since a move is a new component and 1.4 needs the designer's explicit authorisation for each:**
    1. `DrawnScrollbars` (`app/_scrollbars/drawn-scrollbars.tsx`, 2.17): to `components/custom/` with an override record, an inventory entry and a doc page; its thumb colours would also move from the `gray-400` and `gray-500` primitives to a `--ui-*` token (2.1).
    2. **Two implementations of one behaviour (1.7), both built today:** `FittedText` (`app/pages/_shared/fitted-text.tsx`: text cut at a word, or a file name cut in the middle keeping its end, measured on a canvas, used by the result cards) and `Select`'s `truncateAtWords` and `labelEnd` plus `splitFileName` (the same two strategies, in CSS, in `components/base/select`). The second was built without looking at the first (0.9). One has to go, or one is built on the other; the CSS one has no measuring and no layout cost, the canvas one cuts at a word anywhere.
    3. `ScrollFade`, `useListToggle` and `ChunkHeading` (`app/pages/_shared/map-search`): behaviours of a scroller, a fold and a heading, built in the pattern layer.
    4. The parks step's dismiss on an outside press and on Escape, written inline in `observations-search.tsx` (`2026-10-23-67`): a popover behaviour that belongs in the popover or a dismissable component, so the coordinates and shapefile steps can take it by a prop.
  - **Checked:** `npm run contracts:rules` (the core index lists 1.10; item 9 is in 0.6), `npm run check:contracts` clean, the negative test above. No application code changed, so no browser pass was needed.
  - **Not done, so it is not read as more:** none of the open items was moved or merged; the clause does not yet make `npm run audit` list behaviours built outside `components/**` (it lists changed components only), and an audit line for "a `use client` module outside components that attaches a document listener" is the next check to add if the pattern recurs (0.8).
