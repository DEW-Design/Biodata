# 2026-09-30 - Controlled Vocabulary Order typed or picked, ID beside it, floating row actions

- **Sept 30 2026: Controlled Vocabulary Order typed or picked, ID beside it, floating row actions.** The designer: "call it as No. or ID and put it next to order. i told you order must be user input. From the dropdown (typeable and dropdown) on order if i say 3 the row must go to the third. or combine order and drag and drop"; and "Make this action column floating".
  - **Order is an input, combined with drag and drop:** each row's Order is a `ComboBox` (typeable and a dropdown) of the positions 1 to n, with a # icon. Picking a position, or typing one and pressing Enter or leaving the field, moves the row there and renumbers every row; anything that isn't a position puts the row's own number back. The drag handle and the row menu's Move up and Move down still work, and all three routes change the same row order (Order is still the row's position, `withDerivedOrder`). The field restarts at the new number after any move.
  - **ID next to Order:** an automatic identifier stays labelled "ID" (the designer offered "No. or ID") and now sits right after Order, muted, instead of at the end of the row. It never changes when a row moves.
  - **Floating actions:** the "..." column in both grids is sticky at the right edge (`sticky right-0`, its own background and a left border), so it stays in reach while the grid scrolls sideways and the columns pass under it.
  - **Verified:** `tsc`, `eslint`, `check:contracts` clean. Live Chrome as BioData Super Admin on Measurement's Entries: typing 3 and Enter in row 1's Order moved Range 1 to third (Order 3, still ID 1) with the rows above renumbered; typing 99 and Tab in row 4 restored 4; with Value widened so the grid overflows, at scroll position 0 the action cell's right edge sat at the container's right edge (1768 px), the values passing under it. Nothing was saved; the test column width was removed from the browser afterwards.
