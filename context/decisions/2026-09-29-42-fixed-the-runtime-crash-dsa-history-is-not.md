# 2026-09-29 - Fixed the runtime crash `dsa.history is not iterable` (`dsa-detail.tsx:403`), reported directly off the running dev server

- **Sept 29 2026: fixed the runtime crash `dsa.history is not iterable` (`dsa-detail.tsx:403`), reported directly off the running dev server.** Root cause: the new `history` field above was added to `Dsa`/`Dla`/`Nomination` after real records already sat persisted in localStorage under the old shape (this dev server's own browser included, from earlier sessions' testing) - `[...dsa.history]` (the Audit Log render), and `transition`'s own `history: [...d.history, ...]` in every store, both assume a real array, which a pre-`history` persisted record simply doesn't have.
  - **Fix, the persistence boundary, not the render site:** each of the three zustand `persist` configs (`dsa-store.ts`, `dla-store.ts`, `nomination-store.ts`) gained `version: 1` and a `migrate` that backfills `history: []` for any persisted record missing it, run once at rehydration - so every downstream reader (`transition`, `saveDsa`/`saveDla`/`saveNomination`, the Audit Log render) can keep trusting `history` is always a real array, rather than adding a defensive `?? []` at each of those call sites separately. An empty backfilled log, not a fabricated one (CONTRACTS §0.3) - there's no real history to recover for a record that predates the feature.
  - **Sibling-grepped:** the identical `[...x.history]`/`history: [...x.history, ...]` shape exists in all three stores (DSA, DLA, Nominations - the same pattern `dsa-store.ts` itself says it mirrors from `nomination-store.ts`), so all three got the same fix in one pass rather than waiting to hit the same crash a second and third time (CONTRACTS §0.8). `um-store.ts` (User Management) has no `history` field and wasn't affected.
  - Verified `tsc --noEmit`/`eslint --max-warnings=0` clean on all three touched store files, `npm run check:contracts` clean, and live (Playwright): seeded a legacy-shaped record with no `history` field directly into each of `biodata-dsa`/`biodata-dla`/`biodata-nominations` under the old `version: 0` shape, reloaded, and confirmed no crash on any of the three - DSA and DLA's own Audit Log tabs open to an honest empty log, zero console errors. (Unrelated: `tsc --noEmit` on the full project currently shows 4 pre-existing errors from a separate, still in-progress change elsewhere in this session - `DlaAgreementFile` gaining `size`/`dataUrl` not yet threaded through every seed/usage - not touched here.)
