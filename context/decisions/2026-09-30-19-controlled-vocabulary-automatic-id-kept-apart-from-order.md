# 2026-09-30 - Controlled Vocabulary automatic ID kept apart from Order, resizable text columns

- **Sept 30 2026: Controlled Vocabulary automatic ID kept apart from Order, resizable text columns.** The designer: "when we choose No. as identifier and when we change the order this kind of feels counter intuitive. How do we handle this? May be Number will correspond to Order? I'm not sure"; and "the table columns must be resizable. just the ones that needs resizing."
  - **Recommended, and built: the number is not the order.** Records keep an entry's identifier, so it must never change when a row moves; Order is the row's place in the list and changes with every move. Making the number follow the order would relabel entries that records already hold. So the two are kept apart instead: the automatic identifier is renamed "No." to "ID" everywhere (labels, History, validation messages, template instructions; uploads still read a "No." column), the Columns step says "An ID, given automatically ... It never changes, even when rows are moved: Order is what changes", and the grid reads Order first, beside the drag handle, with the ID muted at the end of the row. The vocabulary page's Entries table uses the same order. Easy to revisit if the designer prefers another arrangement.
  - **Resizable columns:** in both grids, the text columns (Code, Name, Title, Description, Value, custom) resize by the right edge of their header: drag it, or focus it (a `role="separator"` with its width as `aria-valuenow`) and use the arrow keys (16 px a step); a double click resets it; 112 to 640 px. The handle, Order, ID, "Available to users" and the menu are fixed. The tables are `table-fixed` with a spacer column that takes the spare width, so a resized column keeps exactly the width it is given. Widths last for the session on that form (not stored). The vocabulary page's read-only table is not resizable yet (the real `Table` would need the react-aria column-resizer, a component change).
  - **Verified:** `tsc`, `eslint`, `check:contracts` clean. Live Chrome as BioData Super Admin on Measurement's Entries: Order 1 to 8 first, ID muted at the end; "Move down" on the first row gave it Order 2 and kept ID 1; five ArrowRight presses on the Name column's edge widened it from 256 to 336 px (`aria-valuenow` 336). Nothing was saved.
  - **Not verified:** resizing and reordering by pointer. The browser tool's mouse drag doesn't deliver a pointer stream, so neither the column edge nor motion's row drag moved under it; both need a check by hand.
  - **Open:** whether column widths should be remembered per vocabulary; resizing on the vocabulary page's read-only table. Not committed.
