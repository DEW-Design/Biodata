# 2026-10-22 - On this page: constant weight and an inset focus ring

- **Oct 22 2026: On this page: constant weight and an inset focus ring.** The designer boxed the "On this page" column of the post-6-oct project page ("Let's resolve this") and asked for the `emil-ui-polish` pass; the screenshot does not say what is wrong, so the column was audited against that skill's checklist and measured in a live browser (1440x900, BioData Super Admin) instead of guessed at.

  **Found and fixed**, in `OnThisPage` (`app/pages/project-detail/project-tab.tsx`). It is the shared component, so the production project page (`/pages/project-detail`) and the other labs get the fix too (CONTRACTS 1.3); only the weight and the focus ring changed, not the layout.
  - **Weight changed with the state** (polish 2: "never change font weight on interaction"). The active link and the section the active link is in were `font-medium` (500) and the rest 400, so a link's width changed as the active one moved down the page. Measured: no row changed height or width at 1440 (the labels fit the 224px column), so it was not yet visibly moving, but a longer label would wrap. Now every link is 400 and the state is the colour (brand for the active link, primary for its section, tertiary for the rest) and the 2px bar. Measured after: all 11 links 400, row heights unchanged (32px for sections, 28px for cards), the active state still reads clearly.
  - **The focus ring was clipped.** The links run flush to the column's edges (0px each side) and the column scrolls (`overflow-y-auto`, so `overflow-x` computes to `auto` too), so the browser's default outline (1px, offset 1px) lost its left and right sides. It is now the design system's focus ring (`outline-focus-ring`, 2px) drawn inside the link (`-outline-offset-2`), as the notice rows do, and all four sides show.

  **Decided (by me):** the ring is the repo's own token (brand teal), as on every other control here, not the skill's "grey, black or white only": consistency across the app's controls over that one rule (CONTRACTS 2.1: the design system's tokens).

  **Not changed, and why.** Hit areas: the links are 28px and 32px tall, under the skill's 40px desktop target. They stack flush, so a larger target (a pseudo-element, or more padding) would overlap its neighbour or make a long list taller; this is a dense list, as in every docs sidebar, and is left for the designer (open). Hover and active transitions are colour only, no `transition: all`. There is no number that changes, no icon, no empty state in this column.

  **Verified.** `npx tsc --noEmit` and `npx eslint` clean on `project-tab.tsx`; `npm run check:contracts` passes. Live: the lab (all 11 links 400 after clicking each section; zero console errors) and the production page (400 throughout, the clicked link active, zero errors); keyboard focus draws a 2px inset ring, all four sides visible. **Not run:** `/emil-typography` and `/emil-design-foundations` (no new text or type layer; the 400 weight is the resting weight the links already had); the other roles (the column is the same for every role). Not committed.
