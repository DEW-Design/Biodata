# 2026-10-30 - Upload dataset from a new project: no dead links

- **Oct 30 2026: every way of uploading a dataset to a project made through Add Project now reaches an upload page.** The designer: "Some dead links when I try to upload dataset when I create a new project." Reproduced: on a project made in the browser, the header's Upload menu, "Upload dataset", went to `/pages/project-list/new-bd-5138/upload` and showed "This project isn't available" (in the deployed static export it would be a 404).
  - **Cause.** A static export cannot build a page for an id that only exists once someone creates it, so a project made in this browser has one fixed page (`/pages/project-detail/created?project=<id>`) and no `/pages/project-list/<id>/...` pages. Its project page was given that route; its upload page, and every link that builds a project's address by hand, were not. Six places built `/pages/project-list/${id}/...` themselves.
  - **What changed.**
    1. **One place builds a project's addresses** (`_shared/project-routes.ts`): `projectDetailsPath` sends a created project (its id starts with `new-`, now the one `CREATED_PROJECT_ID_PREFIX` the store also uses) to its fixed page; new `uploadPath(id)` and `projectTabPath(id, tab)` do the same for the upload page and a project's tabs. A built-in project's addresses are as they were.
    2. **An upload page for a created project:** `/pages/project-detail/created/upload?project=<id>`, partner of its page. The screen is shared (`_shared/dataset-upload/upload-screen.tsx`: the shell, the form, the toast and the way back), so a built-in project's route (`project-list/[id]/upload`) and this one draw the same thing. A created id that does not exist says "This project isn't available", and the page waits for localStorage before saying so.
    3. **Every entry point uses the helper:** the header's Upload menu (`ProjectCardActions`), `UploadDatasetButton`, the Add menu's "Which project is this dataset for?" (`ChooseProjectModal`, which also now **offers the projects made in the browser**, which it did not list at all), "Upload a corrected file" on the upload chip and on a dataset's page, and the custom concepts review's "Open datasets". The upload form's link to the project's restrictions and the upload page's crumb and way back already used `projectDetailsPath`, so they were dead for a created project too and are fixed by the same change.
    4. **A check, so it is not found by a person again (0.8).** `AUTO §4.6d`: a project's address built by hand (`/pages/project-list/${...`) under `app/pages`, outside `project-routes.ts`, fails. CONTRACTS 4.6 says it, with the origin, and the scoped rules were regenerated. Tested on the old line (flagged) and the helper call (not).
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the touched folders and `npm run check:contracts` pass. Live (Playwright, zero console errors), on a project made through Add Project: Upload > Upload dataset opens `/pages/project-detail/created/upload?project=new-bd-5138` with the form, its crumb (Projects / the project / Upload dataset) and the project link open the project, the form's link to the project's restrictions points at the project, a file uploaded and confirmed returns to the project with "Datasets 1"; Add > Dataset offers the new project beside the built-in ones and continues to its upload page; with the run set to fail, "Upload a corrected file" on the chip and on the dataset's page both open its upload page; a built-in project's upload page (`kangaroo-island`) is as before; a created id that does not exist says the project is not available. "Upload attachments" in the same menu stays on the project page (it is not a link; what it opens was not examined).
  - **Not checked.** The custom concepts review's "Open datasets" link (changed to the helper, the page that shows it was not opened); the deployed static export (`next build` would overwrite the running dev server's `.next`; the Pages build check on the pull request is that check, and it needs `/pages/project-detail/created/upload` to build, which a client page with a query parameter does as `/pages/project-detail/created` does).
  - **Open, for the designer (0.4).** The built-in projects' records have routes for each record (`project-details/occurrences/<id>`); a created project has no records yet, so none were given one. When a created project gets records from its datasets, their pages need the same treatment.
