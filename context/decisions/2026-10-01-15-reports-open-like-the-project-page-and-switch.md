# 2026-10-01 - Reports open like the project page and switch from the breadcrumb

- **Oct 1 2026: a report is a deep dive, so it follows the project page; the breadcrumb's section crumb becomes a switcher on every deep-dive page; the section is called "Reports" for every role. Per direct feedback ("why can't the reports follow the project-detail design?... Re-use patterns that already exist without inventing new patterns. The report name and metadata could be inside a gradient card"; "Once this has been changed to 'Reports' we need the up down chevron to switch between different report types... documented and applied across all instances where we do a deepdive into a deep page"; "cards need to be consistent with other card patterns"; "typography check required").** Corrects 2026-10-01-06, which built the reports with a plain section header.
  - **Sense check (answer to "why can't they"):** they can, and CONTRACTS 4.6 already said every record page is laid out like the project page; a report is a record whose content is a table. Nothing new was invented: `RecordBackLink`, `RecordHero` (eyebrow "Report", title, what it answers, facts Rows and Columns, `RecordActionBar onDark` at the top right), then the report's counts, then search, the attribute filter and the table. The plain `SectionHeader` and its count badge are gone (the count is the Rows fact, so a number is not shown twice). The report's actions moved from the toolbar into the hero (one white button, the rest in the "..." menu): Export CSV on Project Detail, Species Detail and Events, Occurrences and Observations; "Download error report" on Data Validation Error, with "Download source dataset" and "Map visualise" in the menu, disabled (uploaded files are never read). That also removed the validation toolbar's second row. `DataReport` (`report-table.tsx`) takes `actions` (nodes, or a function of the rows in view) and `facts`; `toolbarEnd` and `ExportCsvButton` were removed (`csvExportAction` in `report-columns.tsx` builds the action). The empty validation state uses the hero too.
  - **Count tiles:** the shared `MetricTile` (icon, label, count; the tile the project page's "Survey at a glance" and Explore use, measured identical: 6px radius, 8px 16px padding, 18px medium number, 14px label), not the larger dashboard `MetricCard`. `MetricTile` gained an opt-in read-only mode (no `onClick`: a plain block, no hover, no button role), default unchanged, project page and Explore re-checked. Every tile has an icon (the project page's for Events, Occurrences and Observations; `SPECIES_GROUP_ICON` for species groups; one each for the validation counts). Six tiles sit three across and two down. The space under the hero, between tile rows and under them before the Events tabs is fixed.
  - **One name, "Reports":** `REPORTS_SECTION_LABEL` is "Reports" for every role (the rail, column 2 and the breadcrumb). "Reports (Own Submissions)" and "Reports (All Users)" (the admin IA's wording, 2026-09-22-06 and 2026-09-30-17) are retired: who sees what is each report's rule, not part of the name. `REPORTS_ADMIN_SECTION_LABEL` is deleted and `sectionIcons` has one key. Open: the admin IA document still names "Reports (All Users)".
  - **The breadcrumb switcher on every deep-dive page (CONTRACTS 4.6 item 5, documented at `/patterns/navigation`):** the section crumb is `BreadcrumbSwitcher` (a searchable list of the collection's other records, the current one ticked, "View all <things>" fixed at the foot), through a thin wrapper per collection: `ProjectSwitcher` (existing), `ReportSwitcher` (new: the nine reports A-Z, "View all reports"), and new `dla-switcher`, `dsa-switcher`, `nomination-switcher`, `um-switcher` (users, roles and permissions by area). The DLA, DSA, nomination and User Management shells take a `recordId` (set by the six record routes): with it the crumb is the switcher, without it (a list, or a new or edit form, where `breadcrumbCurrent` is also set) it is the plain link it was. Each wrapper applies its list's own visibility rule (a reviewer sees every DLA request, everyone else their own; the panel sees every nomination; and so on), sorted A-Z (DLA and DSA by ID, which is their label). Tested per collection: caret, popup, current ticked, filter by name and ID, pick by Enter and click (role kept), Escape returns focus, View all, forms and restricted roles plain. Deliberately not changed: create and edit forms, upload, project registration, `observation-detail`, `flagged-concepts`, `project-detail/option-2`'s local switcher, `app/proto/**`.
  - **Accessibility bug found and fixed in the shared ComboBox (`listbox="inline"`, added in 2026-09-30-12):** while open, a react-aria ComboBox hides everything outside its input and its popover from assistive technology; an inline list has no popover, so the option list and the "View all" bar were `aria-hidden` (a screen reader would hear an empty field), and this affected the project switcher and the attribute filter too. Fixed once, in the component: the inline region takes the ComboBox's popover ref (so the list counts as inside), the region clears the ComboBox's `ButtonContext` for its content (otherwise a footer button is adopted as "Show suggestions" and leaves the tab order, as react-aria's Popover does for a floating list), and `listboxFooter` in inline mode now sits under the scrolling list, inside the region, instead of inside the scroller. The "View all" bar is passed as `listboxFooter` rather than sitting beside the ComboBox. Verified in the accessibility tree: dialog, expanded combobox, listbox with every option, and a "View all" button; Tab reaches it, the popup stays open, Escape returns focus; the attribute filter's list is now in the tree. Documented on the Select page. Popover mode is unchanged. Not fixed: the current item's "current" is an `aria-label` that react-aria's `aria-labelledby` overrides, so a screen reader does not announce it (the tick is decorative).
  - **Typography check on the Reports landing page (`/emil-typography`, `/emil-design-foundations`, measured with `getComputedStyle`):** page heading 18px semibold and subheading 14px regular match Template Finder and DLA exactly. The card titles were 18px semibold, the same rank as the page heading; the app's card title is `text-base font-semibold` (16px: Home's project and queue cards, the guest Home cards), so they are now 16px (line 24px). Description 14px regular, tertiary (5.3:1 on white), `text-wrap: balance`; "Open report" 14px semibold brand. Everything Barlow; no new type layer.
