# 2026-09-30 - BioData Super Admin role, Controlled Vocabulary on one route, calendar date fields

- **Sept 30 2026: BioData Super Admin role, Controlled Vocabulary on one route, calendar date fields.** Per the designer: a new role, BioData Super Admin, that "will see everything that the Biodata Admin has but CV is an additional one", with Controlled Vocabulary "a super admin feature only"; "Lets keep only option 3"; "always remember to use date fields with calendar input field from design system. Add it to contracts.md"; "Order must be the order in which the options are shown - this must be tied to the row order"; the Identifier and columns step "simplify this further make it intuitive"; the "Other source tables" gap "get rid of this"; "A draft vocab can be deleted"; the drag "is not giving a good visual feedback", use a light library, preferring one already available.
  - **Role:** `biodata-super-admin` heads `USER_ROLES` (seven roles). `isBiodataAdmin(role)` (`lib/user-role.ts`) is true for both admin roles and replaces every `role === "biodata-admin"` check (org pill, Home's admin content, field notes' reviewer and name), so the super admin never loses an admin's view. `hasFeatureAccess` passes the super admin always, and a BioData Admin for everything except `SUPER_ADMIN_ONLY` (`ctrlVocabManagement`). Nav: `biodataSuperAdminNav` is the admin tree plus Controlled Vocabulary after DSA; the admin tree no longer has it. The admin Home's Controlled Vocabulary quick action shows only with the feature. The Prototype tools bar, the `/pages` index and the tools lab list the role. Standing reference: `.claude/rules/ref-roles.md` (seven roles, the super-admin rule, `SUPER_ADMIN_ONLY`), and the `CONTEXT.md` index line for it now says Controlled Vocabulary is a BioData Super Admin feature only; `CONTEXT.md` itself stays an index (5.1).
  - **One route:** Options 1 and 2, their routes, the option switcher (`cv-options.tsx`) and Option 2's CSV import (`cv-import.tsx`) are deleted (4.4). Option 3 is `/pages/ctrl-vocab`; its behaviour is now simply the product (search inside entries, the findable categories, the template in Actions, Code or No., the Sample size tool). `CV_ROOT` in `cv-data.ts` is the one base path.
  - **Contract §2.11 "A date field has a calendar":** added to `CONTRACTS.md` (build scope, `contracts/rule-scopes.json`), with `AUTO §2.11` in `scripts/check-contracts.mjs` failing any `<InputDate` under `app/pages`; `npm run contracts:rules` regenerated the rule files. Every product date field moved to `InputDatePicker` in the same task: the Controlled Vocabulary form and Reactivate dialog, the DSA form, the DLA form and the DLA detail's dates. Changing the contracts and the check is an audited act (9.4), done on the designer's instruction.
  - **Order:** the row's position, 1 to n down the list, always shown and never typed (it was 1 to n within each Name, which left new rows with no order). Order is no longer an optional column (`auto` in `STANDARD_FIELDS`, `shownFields()`); Measurement reads 1 to 8.
  - **Columns step, simplified:** "Each entry is identified by" is two radio buttons with examples ("A code you type", "A number, given automatically"), in place of a dropdown; "Extra columns" lists only the three optional columns (Title, Description, Value), each with a one-line example, under one sentence saying every entry has a code or number, a name and its place in the list; "Your own columns" follows. The always-on checkboxes and "Always used" hints are gone.
  - **Removed:** the "Other source tables" gap marker in Details (designer instruction; the missing real table list stays an open item below, not a marker on screen).
  - **Delete a draft:** "Delete draft" (destructive, confirmed) in a draft's "..." menu; archive stays for anything that was live (REQ-18.6). `deletedIds` in the store keeps a deleted draft's ID from being given out again (REQ-18.1).
  - **Drag:** motion's `Reorder` (motion is already a dependency and used by the Accordion): the handle starts the drag, the row lifts (`shadow-lg`, `ring-1 ring-secondary`, raised) and follows the pointer, the other rows slide aside; reduced motion is respected (`MotionConfig reducedMotion="user"`). The native HTML drag it replaces is removed. The row menu's Move up and Move down remain the keyboard route.
