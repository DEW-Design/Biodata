# 2026-09-30 - Controlled Vocabulary Option 3 two steps Code or No and tracked templates

- **Sept 30 2026: Controlled Vocabulary Option 3: two steps, Code or No., tracked templates.** Follows 2026-09-30-14. Per the designer: "lets not do any preview CV option"; the template download and upload must be "smart" because the template "will be shared with other users to fill ... and then later the super admin will come back here to upload", so "there must be a track to go back (easily find CVs)"; "the code column can be code or No"; "instead of 3 steps we combine step 2 and 3"; "Create all the above as a new option".
  - **Options now:** the Preview option (the first Option 2) is deleted with its routes and `cv-preview.tsx`. The CSV import moved from Option 3 to Option 2 (`/pages/ctrl-vocab/option-2`). The new direction is Option 3 (`/pages/ctrl-vocab/option-3`). `cvFeatures(option)` in `cv-options.tsx` says which option switches on what.
  - **Two steps (Option 3):** Details, then "Fields and values" (Reference) or "Fields and source" (Descriptive). The columns are chosen right above the grid they shape, as the Figma drew "Customise Columns" beside "Fields and Values": an Identifier select, a Columns multi-select (optional standard columns) and "Add custom column", whose name is typed in its own grid header (or in the mapping table's row for Descriptive). Errors on custom columns belong to the second step.
  - **Code or No. (Option 3, model-wide):** `Cv.idKind` is `code` (typed, unique) or `number` (No., given automatically, one past the highest in use, read only, never reused since saved entries are never removed). Fixed once live. Switching a draft to No. numbers its rows 1, 2, 3 in order. Measurement is the numbered seed (the BRD numbers it 1 to 8). A numbered grid shows no second row counter, and its errors name rows by No. ("Name in No. 3"). The vocabulary page, the list and the History read "No." everywhere.
  - **Tracked template round trip (Option 3, Reference):** every download is a hand-out (`Cv.templates`: T1, T2, ... with who and when) written into the file's first row (vocabulary ID, name, hand-out, date), then an instruction row, the column names and the current entries. The way back: the list shows a task card per vocabulary still waiting (more than three become one summary with "Show them"), a "Template out" badge on the row, a Template filter ("Waiting for upload", `?template=out`), and "Upload filled template" beside "New vocabulary", which reads the vocabulary from the file itself, so a renamed file still lands in the right place. The vocabulary's page makes "Upload filled template" the next step while one is out, with one notice naming each hand-out, and offers "Download another template" and "Stop waiting for Tn" in the "..." menu. The form has Download and Upload beside the grid. Uploaded rows are matched by Code or No.: a match updates, a new code (or an empty No.) adds, an entry missing from the file is kept; rows are marked New or Updated and a summary says what changed; nothing is saved until the admin saves, and that save closes the hand-out named in the file (T2 closed, T1 still out) with "Filled template T2 uploaded" and every change in History. A new or draft vocabulary is saved as a draft before its template downloads, so the hand-out has somewhere to come back to; a live one downloads only with no unsaved changes. Guards: a file for another vocabulary is refused from a vocabulary's page and pointed to the list; archived and Descriptive vocabularies take no template.
