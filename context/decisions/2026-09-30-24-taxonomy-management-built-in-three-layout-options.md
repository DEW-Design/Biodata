# 2026-09-30 - Taxonomy Management built in three layout options

- **Sept 30 2026: Taxonomy Management built in three layout options.** Built from the Figma section "Taxonomy Management" (Biodata Wireframe Presentation, node 2537:137008: 25 frames, Flora and Fauna species tabs, Rename, Combine, Split, Append). Every Figma field is kept; spelling fixed only ("Offcial", "Indegenous", "New Higher Level Taxa", "Append Taxon" to "Append Species").
  - **Access:** new feature key `taxonomyManagement` (empty list, so BioData Admin and BioData Super Admin only, per the designer), a whole-page gate in `wholePageGates`, and a rail section "Taxonomy Management" after User Management in `biodataAdminNav` (and so the super admin's tree), icon `Dataflow03`.
  - **Option 1** (`/pages/taxonomy`, `/pages/taxonomy/<rename|combine|split|append>`): the Figma as drawn, in the shell. Column 2 is the Figma menu. Species View is first and the default, Taxonomy View second (the designer: hierarchy is secondary). Action screens render FormPage (4.1), so the X replaces Cancel and each Figma box is a FormRow. Commits with no review, as drawn.
  - **Option 2** (`/pages/taxonomy/option-2`, `/<id>`, `/change/<action>?from=<id>`): species first. A species table (4.2) with a Hierarchy view, a species record like the project page (4.6) edited in place (4.8), Synonyms as a tab instead of the "Synonyms Only" switch, and Rename / Combine with another taxon / Split in the record's "..." menu, opening the same Figma fields with the species and kingdom already filled in and one confirmation that says what will happen.
  - **Option 3** (`/pages/taxonomy/option-3`, `/new?type=&from=`, `/species`): a guided taxon change, the iNaturalist "taxon changes" pattern (swap, merge, split). Steps in column 2 (4.1): kind of change, taxa in, taxa out, then a before and after review with what will happen (synonyms, Linked Species parents and children, NSX code), then commit. A history table of committed changes is its home.
  - **Data:** the taxa are the existing `NSX_SPECIES` list (7 species); no NSX code is invented, and a taxon made by Combine, Split or Append shows "Assigned on commit" / "Not assigned yet". Ranks, authorities and the synonyms given are published names. Option lists only where public (yes/no, EPBC and SA NPW Act categories, the 13 SA plant regions, states); every other dropdown is empty until its Controlled Vocabulary is supplied. Figma's sample "Beach Sand Verbena / Gymnorhina tibicen" (a magpie's scientific name) was not reused.
  - **Contract hardening (0.8):** `divide-secondary` is not a defined utility and rendered a dark divider (the second time, see project-registration step 1's comment); added to the known-dead list in CONTRACTS.md 2.1 and `AUTO §2.1a`.
- **Open:** Flora's Main tab is not drawn (reuses the drawn Main, per the designer). Figma draws "Published?" twice on the Flora synonym. Combine draws New NSX Code as a dropdown (built as "keep one of the combined codes, or assign"). Attributes' "Personal Notifications" (user name, email) sits oddly on a species. Records made against a split taxon are not reassigned. Figma's eight fixed empty rows per table are three rows plus "Add row".
