# 2026-09-30 - Reports landing page with cards; the ingestion report is one of them

- **Sept 30 2026: `/pages/reports` is now a landing page of report cards, and the Data Ingestion Report Pre-Flight Validation moved to `/pages/reports/data-ingestion`, per direct request ("Dataset ingestion is a type of report. We need a reports landing page. There's a few reports that I need to feed to you. They could be cards sitting on there").** This corrects 2026-09-30-17, which put the one report at `/pages/reports`.
  - **The landing page:** `ReportsLanding` (`app/pages/_shared/reports/reports-landing.tsx`): a "Reports" section header, then a responsive grid of `ReportCard`s (1, 2 or 3 columns). The subheading reads "Reports across BioData SA." for BioData Admin and "Reports on your uploads and the projects you contribute to." for everyone else. Every signed-in role sees every card; what a role sees inside a report is that report's own rule.
  - **A report card** (`report-card.tsx`) is the existing `BentoCard` shell with a `FeaturedIcon`, the report's name, one line on what it answers, and "Open report". The whole card is the click target through a single stretched link on the title (a real link with a real name, so text stays selectable and a screen reader announces one link per report); the card border darkens on hover and the link takes the focus ring. Cards are data, not markup: `REPORTS` in `reports-data.ts` (id, title, description, icon, path).
  - **Adding a report** is one entry in `REPORTS`, a route under `/pages/reports/<id>`, and the page: the card, the breadcrumb and the "Back to reports" link follow. Only the report that exists is listed. The admin IA's "Application and System Reports" and "Audit Log Reports" are not shown until they are supplied and built.
  - **A report's own page** (`app/pages/reports/data-ingestion/page.tsx`) has the breadcrumb Home / Reports (Own Submissions or All Users) / the report's name (the section crumb links to the landing page), and a "Back to reports" link (`RecordBackLink`) above the header. Column 2 stays the section label alone: the reports are the landing page's cards, not a second list beside them (3.10).
  - **Links moved to the report:** the upload toast's "View report" and the project chip's "View in Reports" open `/pages/reports/data-ingestion?q=<dataset id>`. The rail item and Home's admin "Reports" quick action open the landing page. The `/pages` index lists both.
  - **The Filter popover's Template section** no longer has a search box (per the designer's question about it): I had marked it searchable, and with only 8 options that was needless. `ListFilterButton` is the app's shared filter (Projects, DSA, DLA, nominations, user management, the project tabs, Template Finder); it shows a search box only in a section marked searchable with more than 6 options, so Project, Template and Ingested by no longer show one here.
  - **Verified:** `tsc`, `eslint --max-warnings=0` on every touched file, `npm run check:contracts` and a production `next build` (both routes prerender) pass. Live with Playwright, zero console errors: the landing shows one card; clicking anywhere on it, and Enter on the focused link, open the report; the breadcrumb and the Back link work in both directions; the admin deep link with `?q=` finds the run; a public user gets the restriction on both routes; the filter popover has no search boxes.
  - **Open, for the designer:** the other reports (to be supplied), and what each card shows beyond its name and line (a count or a "needs attention" number would need each report's data; none was added).
