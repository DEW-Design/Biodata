# 2026-11-11 - The header Add menu is contextual: a project's own things to add come first

- **Nov 11 2026: The header Add menu is contextual: a project's own things to add come first.** The designer, with a screenshot of the Add menu open on a project (User, Project, Dataset, the agreements, Controlled vocabulary, Notification): "Can we make the + Add button contextual? Add on the project page would be: Add a dataset, event, occ, obs, add restrictions, etc... can you figure this out for me?"

  **The job and the principles (0.10).** A signed-in person on a project wants to add something to that project, from whichever tab they are on. One system (the one Add button of 3.5 stays the one; the types open beside their kind as a record's own Add menu does), Make it obvious (a heading says where the things go), Reveal in steps (the 15 record types sit behind three kinds). They pull against Say less: every item is already a control somewhere on the page (below).

  **What changed.**
  - `lib/create-context.ts` (new): a page says what can be added on it (`useCreateContext({ title, items, onAction, replaces })`); the menu reads it (`useCurrentCreateContext`). Set while the page is on screen, cleared when it leaves. Items are data (id, label, icon, optional children); picking goes back to the page through `onAction(itemId, childId)`.
  - `app/pages/_shared/create-menu.tsx`: with a context, the menu is the page's heading and items, a divider, then the general list without the items the page replaces. An item with children opens them in a submenu (`SubmenuTrigger`, the pattern of `record-quick-actions.tsx`). With no context the menu is as it was.
  - `app/pages/project-detail/project-detail-template.tsx` registers, under "This project": Dataset (the project's upload page; roles with `datasetUpload`), Attachments (the bulk upload modal), Events, Occurrences and Observations (the types from `childOptions(null, [])`, so Point intercept is not offered directly under a project), and Restriction. The general Dataset, which asks which project, is replaced by the project's own.
  - Picking a record type opens the Project records tab and starts the new record full screen, as the toolbar's own "Add record" does (`RecordsExplorer` has a `ref` handle, `add(option)`). Picking Restriction opens the Overview tab and "Add restriction" (`ProjectTab` has a `ref` handle, `addRestriction()`, and reports `onEditingChange`). The tab is switched with `flushSync` so its view is mounted before it is asked.
  - Restriction is offered on the page's own test: the role can edit, a kind is still left to add (`hasRestrictionToAdd`, now the one test for the tab's button and the menu), and no Overview card is being edited.
  - CONTRACTS 3.5 says the menu is contextual and how a page joins it; `lib/create-context.ts` is in the shell scope; `/patterns/navigation` names it.

  **Decided by the agent, for the designer to confirm (0.4).** The heading "This project" (new wording). The labels are nouns under "Add", as the general list's are, and the three kinds are plural, as in a record's "Add inside" menu. No heading over the general list, only a divider. Attachments is included (the request's "etc": the page's Upload menu has it). The context is offered on the project's own page (its tabs), not on a dataset's page or the flagged concepts review, where the menu is the general list.

  **Override named (0.1).** 3.12 "one control per action": each item is also on the page (the card's Upload menu, the records toolbar's Upload dataset and Add record, the section's Add restriction). The designer asked for them in the header menu; nothing on the page was removed. Whether the page's own controls stay is open.

  **Verified.** `tsc`, `eslint` on the six touched files and `check:contracts` clean. Live, 1440 by 1000, zero console errors: the menu as Registered User, Privileged User and BioData Admin on Adelaide Hills and as Registered User on Kangaroo Island; no Add button for a public user; the Projects list, a dataset's page and the review screen show the general list. Events lists Site, Visit, Transect, Quadrat, Block, Ramble, Trap, Opportune, Custom event; Occurrences Individual, Population; Observations Individual, Population, Non-biotic, Community. Events then Site from the Overview tab: Project records is selected and "New site" is open full screen; Cancel closes it on Project records. Restriction from the Species tab: Overview is selected, the "Add a restriction" card is open and in view, and the menu no longer lists Restriction while it is. Attachments opens "Upload attachments"; Dataset goes to `/pages/project-list/adelaide-hills/upload` with the role kept. Keyboard: Enter opens, the arrows move, Right opens a submenu on its first type, Left returns, Enter picks, Escape closes one level. At 768 wide the submenu opens to the left of the menu and both are on screen. Type: the heading is Barlow 12px/16px 600 in `text-quaternary`, the classes of the record menu's "Add inside" heading.

  **Not checked.** Touch, 320 wide, a screen reader, a project created in this browser, a project that already has every kind of restriction (Restriction should not be listed), the other four roles.

  **Still open.** (1) The heading's grey measures about 3.4 to 1 on white, under the 4.5 that small text needs; the record menu's "Add inside" heading has the same classes, so both would change together. (2) An Overview card being edited loses its unsaved changes without asking when the tab changes; that is how the tabs already behave, and picking a record type from the menu changes the tab too. (3) Whether the page's own Upload, Add record and Add restriction controls stay now that the header has them. (4) Which pages come next: a record's own page (add inside this record), User Management (Role, Permission), the dataset page. (5) A submenu's accessible name is its trigger's ("Events"), not "Add events", as in the record menu. Not committed.
