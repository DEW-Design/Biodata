# 2026-10-15 - Taxonomy Report: the Reports landing's new report, with the Taxonomy list detail report as its first tab

- **Oct 15 2026: Taxonomy Report.** The designer: "Biodata taxonomy report has multiple reports within it, so we'll have the structure similar to the events, observations and occurrence report. The one I've shared is one of many. ... Reports home -> Taxonomy Report. When the user clicks this report, they see the report: one tab with 'Taxonomy list detail report' with all the info I've shared. Remember, based on the metadata, the content within it changes as well." Supplied: the sheet's 53 column headings and a screenshot of the metadata that sits above them ("BioData - Taxonomy list Detail Report"; Species Code & Name, NSX Code, Common Name, Family, Group, Genus, Date as Start Date - End Date).

  **Where it is.** One new card on the Reports landing, "Taxonomy Report", under a new category "Taxonomy" (`reports-data.ts`, `reports-nav.tsx`), opening `/pages/reports/taxonomy`. It is built like the Events, Occurrences and Observations Report (`records-report.tsx`): the shared `DataReport` (the report hero, the toolbar, the Filter menu and chips, the Columns chooser, the table, the numbered pagination), with underline tabs under the hero, one tab for each report inside it (`?tab=list-detail`). There is one tab so far, "Taxonomy list detail report" (`taxonomy-report.tsx`; rows and parameters in `taxonomy-report-data.ts`). The next sheets are new entries in `TABS`.

  **The metadata above the columns.** The sheet's seven parameter rows are fields above the table, in the sheet's order: Species code & name, NSX code and Common name (text, matching part of the value), Family, Group and Genus (a Select over what the taxa hold, starting on All), and Start date and End date (the design system's date field with a calendar, both empty, 2.11). Changing one changes the rows, the hero's Flora and Fauna counts and the export. They are also written above the columns of Export CSV and Export XLSX, as the sheet has them: the title row "BioData - Taxonomy list Detail Report", the seven parameter rows with the values chosen (blank where none), a blank row, then the column headings. When the parameters leave nothing, the table says "No taxa match" and "Show all taxa" clears the parameters as well as the search and filters.

  **The columns.** All 53 of the sheet's, in its order, one row per taxon, read from the taxa Taxonomy Management holds (`useTaxa`): so a rename, a combine or an appended taxon appears in the report. Flora and Fauna name some facts differently, so a column reads whichever the taxon has (Synonym? from Flora's "Synonym?" or the inverse of Fauna's "Non Synonym?", Native in SA? from "Indigenous?", Occurs in SA? from "In SA?", Endemic in SA? from "Endemic To S.A.?"). Current concept? is the taxon's own current flag, which a Combine or Split clears. SA regions, Aus / World, Ref herb, Attributes and Common name come from the taxon's tabs; Linked species (parents, children) are the linked taxa's names. Columns the app has no value for (Major group, For census?, For BS?, Syn qualifiers partly?, Questionably?, As MS?, Phrase, ID certain?, Established in SA?, Collected last 50 yrs?, the Hybrid columns, Published?, Matches CC?, Date, How created?, Life span, Species status and the attribute, region and herbarium tables) are in the table and left empty, because Taxonomy Management's sample taxa hold none: they fill as taxa are edited. The first column, NSX code, is pinned.

  **Departures from the sheet, on purpose (listed in the file's header too).** Labels are sentence case and spelled out ("Curr Concept?" is "Current concept?", "Estab in SA?" is "Established in SA?"), and the sheet's typos are fixed ("Auther2", "Pratly?", "Questionalbly?", "Secies Status"), as the other reports did. "Common Name" is in the sheet twice (third, and after Species status): both are kept in place, the first the taxon's common name, the second every common name it has. "Genus/Sp" is kept as the sheet has it and shows the genus. The sheet's trailing blank column is not drawn. The Filter menu offers the facets the parameters do not (Kingdom, Synonym?, Current concept?, Occurs in SA?, Native in SA?, Endemic in SA?, Hybrid?, Created by), so no question is asked twice (4.2d).

  **Shared code changed, additive and opt-in (1.6).** `DataReport` gained `exportPreamble` (rows above the column headings in the export) and `narrowed` (the report's parameters have already narrowed `rows`: an empty result is "No ... match" with a way back, not "No ... yet"); `reportExportActions`, `downloadCsv` and `downloadXlsx` take an optional preamble. With neither set, every other report is unchanged: the two shared export functions write the same rows as before.

  **Access.** Every role that has Reports opens it (the same as the Species Detail Report); a public user gets the Reports restriction. No `feature` is set. Taxonomy Management itself is BioData Admin and above; see open below.

  **Open for the designer (CONTRACTS 0.4):**
  1. **Who sees the Taxonomy Report.** Built for every signed-in role. If it should follow Taxonomy Management (BioData Admin and above), it takes `feature: "taxonomyManagement"` in `reports-data.ts`, one line.
  2. **The Date parameter.** The sheet does not say which date. It currently keeps a taxon that has any of its Date, Created on, Renamed on or Modified on days inside the range. Say if it should be one of them.
  3. **The Group parameter.** It filters the species group (Plants, Mammals, Birds ...) as Taxonomy Management's "Show only" names it; the sheet's "Major group" column is the botanical Major Group field and is separate, and empty. Say if Group means that field instead.
  4. **"NSX description"** shows the scientific name (the NSX code's description). Say if it is something else.
  5. **Synonyms as rows.** One row per taxon; a taxon's synonym names are not rows of their own. The "Synonym?" column is Yes only on a taxon that is itself a synonym. Say if synonym names should be rows.
  6. **The category "Taxonomy"** is new, with one report in it; the alternative is Project data, which it is not.
  7. **The second "Common name" column**, and "Genus/Sp", as above.

  Type: no new type layer (2.9). The labels and hints are the design system's `Input`, `Select` and `InputDatePicker`; the tab, hero, toolbar and table are the Events, Occurrences and Observations Report's. Borrowed from: that report (tabs, `wrapBody`, `DataReport`), the Species Detail Report (columns and the sentence-case, spelled-out departures list) and the project scope Select (a control above the table that narrows its rows).

The breadcrumb's report switcher lists "Taxonomy Report" and switching to another report works.
