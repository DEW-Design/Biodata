- **Oct 16 2026: the Fauna Taxonomy Report.** The designer: "Let's start to build the fauna taxonomy report. Remember, same UI structure as the flora report", with two sheets (title and metadata as a screenshot, columns as text) and more to follow. Built as one report on the Reports page, **Fauna Taxonomy Report** (`/pages/reports/fauna-taxonomy`, BioData Admin and Super Admin only, `taxonomyManagement` as the Flora report), in the Taxonomy category beside the Flora one, with two tabs so far:
  - **List detail**, from "BioData - Fauna Taxonomy list Detail Report": one row per Fauna taxon, the sheet's 30 columns in its order (NSX code ... Modified date). Its metadata (Species Code & Name, NSX Code, Common Name, Family, Group, Genus, Date) is the table's own search and Filter, as in the Flora report (CONTRACTS 4.6 item 4): the typed lines are the search, Family, Group (the species group: Bird, Mammal ...), Genus and the date are Filter attributes, and the Filter also offers Indigenous?, Current? and Created by. It is written above the columns of Export CSV and XLSX.
  - **Species status**, from "BioData - Fauna Taxonomy list - Species Status": one row per Fauna taxon that holds a status, the sheet's 18 columns (SA, Australian, NPW Act and EPBC Act code, description and comment, then created and modified). Metadata: Species Code & Name, NSX Code, SA Status Desc, Australian Status Desc, NPW Act Status Desc and Date; the Filter also offers the EPBC Act description and who created or modified it. With no status held it shows one mock Example record, as the Flora tabs do (CONTRACTS 4.2e).
  The tab strip, scrolling and tab panel are now one component, `TaxonomyTabs` (`taxonomy-tabs-shell.tsx`), which the Flora report was refitted to (nothing on it changed: 10 tabs, same rows) and the Fauna report uses; "same UI structure" is the same code. `useSheetTab` takes an optional report title and subtitle. Rows come through `useFaunaTaxa` (`taxonomy-fauna.ts`), so a Flora taxon is in neither Fauna tab, as a Fauna taxon is in none of the Flora tabs.

  **Placeholder data (CONTRACTS 0.3, prototype).** The seed Fauna taxa had no status and no distribution, so `tx-data.ts` gains placeholder Species Status values on three of the five (Isoodon obesulus: SA Endangered, Australian Endangered, NPW Act and EPBC Act Endangered; Trichosurus vulpecula: SA and NPW Act Vulnerable; Malurus cyaneus: Australian Least Concern) and placeholder Australian Distribution (SA, Vic, NSW) and Regional Data (Southern Lofty, Kangaroo Island) rows on all five. They are not assessments, and no identifier is invented (the National Species Index No, Taxonomic sequence, Sub family and Official? stay empty). The taxonomy store is version 5: a browser that holds taxa from before gains the rows and values only where a taxon has none of its own, and keeps every edit (checked with a version 4 store). Taxonomy Management's Fauna Species Status, Australian Distribution and Regional Data tabs now show these values.

  **Departures from the sheets, each in the file's header comment.** Labels are sentence case and spelled out ("Creation By" is "Created by", "Common Name Seq" is "Common name seq", "Auther" is "author"). The Species Status sheet lists "Australian Status Desc" twice, once after the Australian status comment and once before "NPW Act Status Desc": the second is read as the **NPW Act status code**, the one column that group lacks. The NPW Act and EPBC Act codes are categories from a list ("Endangered"), so their description is the code itself unless the taxon gives other text; the SA and Australian codes are free codes with the text beside them. Common name, its seq and its type are those of the Common Name tab's row for the taxon's listed name. Species status, Australian distribution, Regional data, Species reference and Attributes are the values of the tab of that name, joined.
