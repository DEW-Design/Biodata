# 2026-09-30 - Breadcrumb project switcher is now the searchable ComboBox

- **Sept 30 2026: the breadcrumb project switcher is rebuilt on the design system's `ComboBox`, per the designer ("this has to be a searchable component. We have that in the design system. Please double check - combobox").** It was a plain `Dropdown` menu (2026-09-30-08), so there was nothing to type into. `Select.ComboBox` (`components/base/select/combobox.tsx`) already existed, with `Select.Item` carrying supporting text, so no component was added or changed (1.1, 1.4).
  - **How it works:** the `Projects ⇅` crumb is unchanged at rest. Pressing it (mouse, or Enter or Space) turns it into the ComboBox's search field in the same place ("Search projects", size sm, 384px wide), with the list open beneath it, aligned to the field. The list is A-Z with the project ID after each name; the current project is ticked. About six rows show and the list scrolls inside (`popoverSize="md"`); "View all projects" is the last item, kept at the bottom of the list (`sticky bottom-0`) whatever is typed and reachable by keyboard.
    - **Search** matches the name or the ID, in any case and ignoring surrounding spaces ("hills", "BD-51", "5137", "atlas"). With nothing matching, only "View all projects" remains.
    - **Closing:** Escape, a choice, or a click elsewhere puts the crumb back; after Escape or a choice focus returns to the crumb (a click elsewhere leaves focus where the click put it). Choosing a project opens its page; choosing the current project just closes.
  - **Two fixes found while testing:** (1) focusing the field on the same render as the list is built left the list closed, because a ComboBox that opens on focus will not open onto an empty collection. The field is focused one frame later instead of with `autoFocus`. (2) The filter lowercased the item text but not what was typed, so "BD-51" found nothing; both sides are lowercased.
  - **Code:** `app/pages/_shared/breadcrumb-switcher.tsx` (generic) and `project-switcher.tsx` (adds "Search projects"). Still page-shared, not a design-system component, so no override entry.
  - **Verified:** `tsc`, `eslint --max-warnings=0` on both files and `npm run check:contracts` pass. Live at 1708x934, zero console errors: opens with five rows and the current one ticked; typing filters by name and ID; Escape closes and returns focus to the crumb; Enter opens from the crumb; keyboard (type, Arrow Down, Enter) and mouse picks open the project; "View all projects" works by mouse and keyboard; click outside closes; field and list share left and right edges; with extra rows the list scrolls inside and the bar stays fixed; the same on a record page as a public user and on the project page as BioData Admin.
