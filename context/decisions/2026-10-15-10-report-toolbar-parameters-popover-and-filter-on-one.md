# 2026-10-15 - Report toolbar: Parameters popover and Filter on one row, rolled across every report, documented as a pattern

- **Oct 15 2026: Report toolbar, from the lab into production.** The designer, after comparing the four options of `/proto/report-controls` (`2026-10-15-09-*`): "Option B as base with Option D's parameters button popover might work best - this combo to be rolled over to the reports production, please. Let's apply this across all reports, btw. This should be documented as a pattern too." Asked which split the combo means (B's Filter holds the sheet's parameters, D's popover holds them, or each holds some), the designer chose: **the popover holds all of a report's parameters; the Filter menu keeps only the other facets.**

  **The pattern.** A report's controls are one toolbar row: the search, a **Parameters** button, the Filter button and, at the right, the Columns button. The gradient identity card stays (B's header; the slim header of the lab is not adopted, 4.6 is unchanged on the card). What a report is **run on** (a project, a dataset, a species by its code, a date range) is its Parameters: a popover of the report's own fields, a count on the button and a chip beside it for each parameter that is set. What you **narrow the rows by** is a Filter attribute (4.2d), and a control is never in both. A report with no parameters has no Parameters button (2.12). The table keeps at least 24rem, about 7 rows (`min-h-96`), so where the controls take more the page scrolls and the table does not shrink. The export still writes the sheet's title and parameter rows above the columns where the sheet has them.

  **Across every report.** All thirteen reports are drawn by `DataReport`, so the toolbar and the floor apply to all of them. Four have parameters and now show the button: the Flora Taxonomy Report (each tab's sheet parameters, two columns), Data Validation Error (Project and Dataset, one column), Species Detail and Events, Occurrences and Observations (Project, one column; a chip "Project: ..." when one is chosen, none for All projects). The other nine (Data Ingestion, Post Ingestion, Sensitive and Restriction, Voucher ID Update, SpecimenDB Refresh, Project Detail, DLA, DSA and Project Audit Log) have none and show no button. Checked live: all thirteen load with zero console errors, and the button is on those four and no other.

A calendar opened inside it closes on Escape without closing the popover.
  - `DataReport` (`report-table.tsx`): `parameters` replaces `scopeControl` (removed: `tsc` fails any report still passing it); the table's floor is `min-h-96` instead of `min-h-48` for every report; the lab's function form of `exportPreamble` and `tableFloor` are gone.
  - `report-scope-select.tsx`: the project scope is now `scopeParameters(...)`, a labelled Select in the popover and a "Project: ..." chip.
  - Data Validation Error: the Project and Dataset selects are the Parameters (the chips show the project code and the dataset ID, always set, so no Reset). Its two explored layouts (selects in a row under the card, selects in the toolbar) are gone with the `LayoutOptionSwitcher`, the `layout` prop and the route `/pages/reports/data-validation-error/option-2`, and its `/pages` index line (4.4: when a direction is chosen the others are deleted). `/proto/layouts` (the 2 Oct lab of the same question, `2026-10-02-10-*`) still runs on the new toolbar; its own options (slim header, folding column 2, facet panel) are not chosen and the lab is left for the designer to retire.
