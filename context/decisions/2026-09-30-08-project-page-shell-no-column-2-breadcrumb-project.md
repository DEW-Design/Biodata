# 2026-09-30 - Project page shell: no column 2, breadcrumb project switcher, legal links in the rail

- **Sept 30 2026: the three shell changes approved in 2026-09-30-07 are built, plus the hero fixes, per direct request from the designer ("Proceed with the changes I asked. Also, the caret up and down icon in the breadcrumb, action that too").**
  - **No column 2 on the project page.** The project page template, its record pages (`ProjectRecordView`) and the not-found state render rail and main only, for every user type. This is the **override of CONTRACTS 3.7** approved in 2026-09-30-07; it is now written into 3.7 as a scoped exception and is not a precedent (0.1). The sidebar toggle is gone; "Back to projects" stays. The `?view=review` screen keeps its own column 2 (the flagged-concepts list), since it is a different screen state.
    - **Knock-on, raised:** on a record page the project's records tree used to be in column 2. With it gone, the way back to the records is the "Back to <project>" link above the record, then the Survey records tab. Say if record pages need a records tree back in some other form.
    - **Removed:** `ProjectsSidebar` is no longer rendered on project pages (still used by the Projects list and Home). `ProjectDetailsView`'s tree code (`renderEventNode`, `pathForTreeKey`) is deleted with the column.
  - **Breadcrumb project switcher.** The "Projects" crumb is now `Projects ⇅` (the up-down caret, `ChevronSelectorVertical`, the same icon as the org pill). It opens a list of the projects in the Projects list, A-Z, each with its project ID, the current one ticked and read out as "current". The list shows about six rows (`max-h-[17.5rem]`) and scrolls inside; a bar fixed at the bottom says "View all projects" and goes to the list. Picking a project opens its page.
    - **Built as:** `app/pages/_shared/breadcrumb-switcher.tsx` (generic: label, items, current, onSelect, view-all) and `app/pages/_shared/project-switcher.tsx` (the projects). Composed from the real `Dropdown` (a Menu): keyboard complete, Escape closes without choosing, focus returns to the crumb (1.9). The footer is a sticky last menu item, so it is reachable by keyboard.
    - **Not a design-system component:** it lives in `app/pages/_shared`, composed from real DEW parts, like `ProjectCardActions` and `ProjectsSidebar`; nothing was added under `components/**`, so no override entry or inventory change was needed (1.4). If it should be promoted into the design system, that is a 1.4 step for the designer.
    - **Where else:** the designer asked for the same behaviour on other parts of the webapp. Only the project pages have it so far. `BreadcrumbSwitcher` is ready for the record pages of DLA, DSA, nominations and user management; which of those, and the order of the list, is still to confirm (built A-Z across all projects).
    - **Order and scope:** the list is every project in the Projects list, A-Z, whatever the person's My/All scope. It has four rows today, so the scroll and the fixed bar were checked by adding rows in the page for the test, not with real data.
  - **Legal links in the rail.** Terms, Privacy and Help are icons at the foot of column 1 (`PrimaryRail`, one icon each in `nav-icons.ts`: `File05`, `ShieldTick`, `HelpCircle`), with a tooltip, on every screen and every user type. `SidebarFooterLinks` and its 22 uses are deleted, so column 2 no longer ends with a text block anywhere. `CONTRACTS.md` 3.2 (renamed "One rail, one icon map, legal links in the rail") and 3.10, `AUTO 3.5` in `scripts/check-contracts.mjs` (now allows the text only in `primary-rail.tsx`), the navigation pattern doc page and `ref-shell.md` were updated, and the rule files regenerated (`npm run contracts:rules`). Changing the check is a designer decision (9.4), taken here.
    - **They do nothing yet:** there are no terms, privacy or help pages, so each icon is a labelled, non-interactive icon whose tooltip says "Not available in this preview yet", the same honest treatment as the disabled template downloads (2.10). They were inert text before.
    - **Correction to 2026-09-30-07:** it said the mobile menu needed a home for them. Column 2 was already hidden below `lg`, so the mobile menu never had them; nothing was added there.
  - **Export CSV and Create report** moved into the hero's "..." menu (`ProjectCardActions`), acting on this project. Create report: a signed-in person gets the "Reports aren't wired up yet" toast, a guest gets the sign-up invite, as the old Actions group did.
  - **Status pill baseline.** The hero's Status badge was a block-level flex, so it took its own line and its text sat 2.5px above the other values. It is now inline and aligned to the baseline; measured, it is within 0.5px of the other values (was 2.5px).
