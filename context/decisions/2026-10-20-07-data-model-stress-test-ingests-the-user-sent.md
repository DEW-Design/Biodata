# 2026-10-20 - Data model stress test ingests the user-sent Ramble form, builds the 3-tier rows, loads lazily, Site id is ABC-NN-NN

- **Oct 20 2026: Data model stress test ingests the user-sent Ramble form, builds the 3-tier rows, loads lazily, Site id is ABC-NN-NN.** Brief, three parts: ingest the template users fill in and send to BDBSA (the DEW Ramble survey form), break it into the 3-tier sheet BDBSA's automation produces and build the structure from that; keep the page fast with thousands of records (lazy load); and a Site id shown as "Site ALT-12-1" must read "Site ALT-12-01". Lab only (`app/proto`), no product screen touched. Follows `2026-10-20-06` (every tab of a workbook).
  - **The form.** `template-ingest.ts` (new, pure, no imports) recognises the Ramble form by its title and its species table, and the Fauna list, Other comments and Instructions tabs beside it. The top block is read by label (a label that meets another label first has no value, so a blank Observer 2 does not borrow the Easting label); the species tables by their merged header cells. It returns SITE, VISIT, SPECIES FLORA, SPECIES FAUNA rows with the column names a real BDBSA tab carries, plus one OBSERVATIONS row. Those go through the pipeline that already existed (tab name, linking by coordinates and visit date, the Occurrence / Observation split); nothing here builds a tree.
  - **Checked against the real submission.** "Heathfield Council Depot Ramble Oct 2019.xlsx" holds the filled-in form and BDBSA's own SITE, VISIT, SPECIES and SPECIES FAUNA tabs for it. Site zone, easting, northing, property and location comment, and the visit date, equal BDBSA's. All 264 plant rows and both animal rows line up one for one with BDBSA's rows: same NSX code, species comment and source id (FIMS id, a dash, a two-digit sequence); dominant storey equal on all. The three plants with no NSX code (Arum sp., Unidentified sp., Yucca sp.) are blank in both.
  - **Decided without being asked (confirm or reverse).** (1) Vegetation information (veg type, structure, condition, habitat comments) becomes one Observation:Community under the Visit, as the schema says (Vegetation Conditions, SA Structural Formation, Observation Comment are Community fields); BDBSA's own VISIT tab holds the same answers as Visit columns. (2) In a file that has both the form and BDBSA's converted tabs, the converted tabs are left out and said so, because they describe the same records. (3) Hidden tabs (a species list of 8,518 names, an observer list) are listed and never read. (4) Words stay words: GDA94, Degraded Natural, Open Forest, "Observed-no method stated", not BDBSA's codes (4, 4, 6, 6); one submission gives a few pairs, not a table. (5) Cover abundance (264 rows) and the Other comments tab are not carried, as BDBSA's own conversion leaves them out; both are counted in a note on the screen. (6) Survey # is not on the form (BDBSA assigns 653 against FIMS 615), so it stays blank and the Project id with it.
  - **Download 3-tier workbook** on the tab report writes the converted tabs as an .xlsx; uploading it again ingests to the same tree.
  - **Also changed in the shared pipeline.** A species row now becomes an Occurrence labelled by the species name, which keeps the species, common name, source id and voucher; the Observation under it keeps the ecological detail only. "Number Observed" stays on the Observation only where its type has the field (Population); before, it was reported as another type's field on every Individual and Community row. The plant code "P" reads as Flora. Header matching ignores a slash ("Camp/Map", "Quad/Site", "Patch/Quad", as BDBSA's SITE tab heads them). "No ID column found" is gone (a Site, Visit or species row legitimately has none; a record that ends with no id is still "Missing ID"). Zone, Easting, Northing on a Site or Visit are kept and flagged for review instead of reported as another record type's fields, since the Site and Visit templates have no field for them and the traceback needs them.
  - **Site id.** ABC-NN-NN: the last number is padded to two digits, so ALT-12-1 reads ALT-12-01 whether it came from Camp/Map, Quad/Site and Patch/Quad or was written in an ID column; a Visit that points at "ALT-12-1" still finds it. Only the last number is padded, as asked; a one-digit Quad/Site is left as written.
  - **Lazy load.** The Resolved tree builds a record's children only while it is expanded (a collapsed record says it has children), shows at most 50 children under one parent with a "Load N more" row, and opens to the Sites only (it used to open every Visit). The tree, nested counts and tab report are memoised. Past 500 records the ingested JSON is built when "Show ingested JSON" is pressed. Measured in Chromium on 12,072 records (12 Sites, 60 Visits, 6,000 species rows): first paint 607 ms with 1,891 DOM nodes and 77 rows, against 4.1 s, 71,344 nodes and 3,137 rows before; expanding a Visit and loading its next 50 each took under a second including a 400 ms wait. Opening the JSON for that set takes about 3.9 s (28 MB of text), which is why it waits to be asked.
  - **Verified (ran).** `npx tsc --noEmit`, `eslint` on the folder, `npm run check:contracts`: clean. Live, no console errors: the Heathfield file (535 records, 527 valid, 8 with errors, about 650 ms), the 12,072-record workbook, the earlier tab fixtures, three BDBSA-style CSVs, Site id fixtures with both spellings. Not run: the typography skills (§0.6 item 8; the new text reuses the existing `text-xs text-tertiary` note row, the table cell text and the summary-bar sizes), a keyboard pass over the new "Load more" row and chevrons (react-aria handles them; not exercised by key), and no second form type (only the Ramble form exists as a sample).
  - **Finding for the data model, not a bug here.** The 8 records with errors are exactly the 8 plant rows with a dominant storey (O, U, E; 7 rows) or "released / revegetated" (1 row). Both fields are Individual and Population fields in `FIELD_SCHEMA`; a plant on a Ramble is a Community observation. Either Community gets them or the plant rows are not Community.
