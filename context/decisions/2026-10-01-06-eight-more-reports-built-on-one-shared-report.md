# 2026-10-01 - Eight more reports built on one shared report table

- **Oct 1 2026: the other eight reports of the wireframe section (Figma `YMproGZfrFB5jUqPHPxMhk`, node `2520:114161`) are built under Reports, following how the first one was brought in, per direct request ("Based on how we built the first report, let's build out the other reports as well... Carefully sift through all the reports").** The section holds eleven frames, each a report screen beside a "Columns" list (every column the report has): the Data Ingestion Pre-Flight Validation (built on Sept 30, 2026-09-30-17), Project Dataset Post Ingestion, Project Sensitive and Restriction, Voucher ID Update, Data Validation Error, SpecimenDB Refresh, Project Detail, Species Detail and three "Events, Occurrences and Observations" frames. The three Events frames are one report: they share a title and draw one tab row (Events | Occurrences | Observations), differing only in the table, so they are one report with three tabs. That makes nine reports, nine cards on `/pages/reports`.
  - **One table for all of them:** `app/pages/_shared/reports/report-table.tsx` (`DataReport`) is the first report's pattern as a component (CONTRACTS 4.2 and 4.2d/4.2e): section header with the count, `ToolbarSearch`, the attribute filter and its chips, the table in a `TableCard` with a sticky header and the first column pinned, numbered pagination, the table fitted to the viewport, `ListEmptyState` told apart as "nothing yet" and "nothing matches". Every column of each wireframe's Columns list is a column, scrolling sideways. A report is its columns and its rows. `report-columns.tsx` has the column builders (a column also says how it reads as plain text, which is what Export CSV writes) and `ExportCsvButton`; `report-page.tsx` is the route wrapper; `report-projects.ts` is the one who-sees-what rule; `report-scope-select.tsx` is the project scope Select. `DataReport` takes `belowHeader` and `toolbarEnd` as nodes or as functions of the rows in view, a `resetKey` (clears search, filters, sort and page without remounting, so a tab list keeps its focus) and a `wrapBody` (so the body can be a tab panel). A worker first wrote these as a second file, `report-view.tsx`; that duplicated `DataReport`, so it was folded into `report-table.tsx` and deleted (1.6).
  - **Reports and where their rows come from (nothing is invented where the app holds a fact; an empty cell is left empty, 2.3):**
    - `post-ingestion`: the same runs as the ingestion report (`use-ingestion-runs.ts`, real uploads plus the sample history, one rule for who sees what), with the project's own facts beside each (28 columns).
    - `sensitive-restriction`: one row per restriction: the project's restrictions state, the accepted and under-review nominations (read from the nominations store, so a nomination accepted in the app appears), and Explore's Level 2 species (32 columns).
    - `voucher-id-update` and `specimendb-refresh`: one shared specimen list (`specimen-records.ts`) built from the survey records' vouchers, `NSX_SPECIES` and Explore's species, so a voucher reads the same in both; the museum or herbarium side is a copy with a few deliberate differences (listed in a source comment, never in a rendered field). 21 and 93 columns (the Figma list has 93 rows, not 95).
    - `data-validation-error`: one dataset at a time, chosen with "Select project" and "Select dataset"; error rows are generated deterministically from the simulated run (their number is the run's failure count), so the tiles and the table agree exactly. "Download error report" is a real CSV; "Download source dataset" and "Map visualise" are shown disabled ("Not available in this preview yet"), because uploaded files are never read.
    - `project-detail`, `species-detail`, `events-occurrences-observations`: from each project's own page seed (Adelaide Hills' rich seed, `seedFromExplore` for the others), so a report and a project page cannot disagree; counts were compared against the project page for every project. Export CSV writes exactly the rows in the table.
  - **Who sees what:** BioData Admin reports across every project on the platform; everyone else across the projects they contribute to (and, for the ingestion-based reports, their own uploads). A public user gets the Reports shell and its restriction. The restriction copy no longer says "uploads" (it is now "reports on your uploads and the projects you contribute to").

    - Only the three wireframes that draw an export get one. Project scope ("All Projects") is a Select above the tiles on Species Detail and Events, Occurrences and Observations; Project Detail has none (its rows are the projects). The Events report shows the wireframe's four tiles (Datasets, Events, Occurrences, Observations) and plain tabs. The count tiles are the shared `MetricTile` (icon, label, count) in the compact grid the project page's "Survey at a glance" and Explore use, not the larger dashboard card (designer feedback, 1 Oct 2026: "cards need to be consistent with other card patterns"); `MetricTile` gained an opt-in read-only mode (no `onClick`: a plain block, no hover), its default unchanged.     - The wireframes' people and Victorian places are not used (0.3); the people are the placeholder cast and the species and places South Australian.
