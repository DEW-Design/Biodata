# 2026-10-25 - Nominations: existing restrictions as a table with status; a restriction is a whole nomination

- **Oct 25 2026: Nominations: existing restrictions as a table with status; a restriction is a whole nomination.** Follows `2026-10-25-08-*` and replaces its per-attribute "Already protected" list. The designer, with a screenshot of the Review step's table: "I want a view like this to show what is already restricted if there is any restriction already set for that species along with the status if its nominated or nomination accepted. Refer to the status we have already developed." The species dropdown shows each species' status; picking an already restricted one shows what is restricted. "Note that the location is to define where this species [is] found. For example restrict all pigeons found within Adelaide hills that['s] sex is male and has any other attribute."
  - **A restriction is a whole nomination:** the species where it is found (its Location areas, else anywhere) and with every attribute it names, all of which a record must match. `restrictionWhere`, `restrictionConditions`, `restrictionSummary` (`nomination-data.ts`) write it. 08's per-attribute split (one removable rule per attribute) contradicted this and is gone: `currentProtections` is replaced by `existingRestrictions` (accepted and not removed by a later accepted nomination, plus open ones; drafts left out; open first).
  - **Dropdown:** each species' status is its open nomination's (Submitted, Under review, Returned for more information), else Accepted when a restriction is in force, else Restricted (a project holds its records as licence-only), all from `nominationStatusMeta`.
  - **Species step:** once chosen, "Already restricted" and `ExistingRestrictionsTable` (`nomination-restrictions.tsx`, the Review table's pattern): Nomination, Where, Restricted (one condition per line), Status badge. Replaces 08's brand alert. The open-nomination error and the project licence-only warning stay.
  - **What to protect:** the same table, titled "Already restricted", with the design system Table's own row selection (checkbox column, `selectionBehavior="toggle"`) on accepted rows to suggest removing a whole restriction; open rows are disabled. A checkbox drawn inside a cell did not work: the table's grid took the press. Removals use the main reason (08's per-removal own reason is dropped). The Attributes description now says a record must match every attribute and Location is where the species is found that the restriction applies to.
  - The table is `bodyScrollable` with a sticky header to meet `AUTO §4.2b` rather than adding the file to the check's embedded-table exemptions (that would loosen a check, 9.4). In the form nothing bounds its height, so the rows keep their natural height (measured: table 124px, wrapper 124px, nothing clipped).
  - **Stored:** `NominationRemoval` is `{ key: nomination id, summary }`. `currentSpeciesRating` leaves out an accepted nomination that a later accepted one removed. Review and both record pages show a removal as the nomination's id, "Suggested removal" and its summary.
  - **Open:** (1) the rating engine (`mergeRatings`, `ratingFromNomination`) still rates and merges attributes one by one, not as one combined restriction; whether a restriction should carry one rating is for the designer; (2) the form still lists Location as one of the attributes; whether "where" should become its own field above the attributes is for the designer; (3) a species with an open nomination still cannot be nominated again; (4) version 3's admin "Already protected" block on the record is unchanged.
