# 2026-11-02 - MultiSelect: selections as pills inside the field, the count and Select all in the popover, Done in the footer

- **Nov 2 2026: MultiSelect shows what is chosen inside the field, and the popover is rearranged.** The designer, with a screenshot of an open MultiSelect ("3 selected", then the list, Reset and Select all): "The user has to click out to see what they've added. Let's have pills inside the field showing the selections. Also, selection counts - remove and add it in the dropdown popup. instead of select all, let's have done. and move select all to the top right. Let's polish this a bit." Run through `/refine-prompt`; the refined prompt and its assumptions are below.
  - **The problem.** Since 25 Oct (`2026-10-25-13`) the selections were listed as badges under the field. The popover opens over exactly that place, so the only way to read the choice was to dismiss it. That entry left one thing open: the trigger said "3 selected" above the badges that listed them (a fact in two treatments, 4.3).
  - **Changed (`components/base/select/multi-select.tsx`, once, so every caller has it, 1.3).** (1) The selections are `BadgeWithButton` pills (gray, sentence case, the badge the designer chose on 25 Oct) inside the field. They wrap, a long name is cut with an ellipsis at the field's edge, and each pill's x removes it; focus then moves to the pill now in its place, the one before it, or the field (1.9 item 3). (2) The field no longer says "N selected" when it shows pills. (3) The popover has a row under the search field: the count on the left, Select all on the right (`tertiary`, `CheckDone01`, the action's one icon, 3.12). (4) The footer is Reset on the left and Done on the right (`primary`, `Check`): Done only closes the popover and focus returns to the field; the choice applies as it is made, so there is no Apply (1.9 item 2). Escape and a press outside still keep the selection. (5) The field is now a box with the trigger button covering it and the pills over it, because a pill's remove button cannot sit inside another button. A press on a pill's label opens the list, a press on its x removes it. The trigger's accessible name says what is chosen ("Assign to, 3 selected") since the pills are outside it. With the field disabled the pills are `inert`.
  - **No layout shift when the first pill arrives.** The field is 36px (sm), 40px (md) or 44px (lg) empty, and the same with one pill: the pill is 28px or 32px and the vertical padding is 4px (6px for lg) so the rows below do not move. Measured: md field 40px empty and with one pill, 76px with three pills in two rows; sm field 36px, 100px with three long names (one per row). The popover follows the field as it grows: it sat 4px under the field's bottom edge after each pill was added with the list open.
  - **Prop changes.** `MultiSelectFooter` takes `onDone` and no longer `onSelectAll` (nothing outside the component used `MultiSelect.Footer`); `showFooter` now covers the count row and the footer; `showSelectedBadges` (default true) now means pills in the field. `selectedCountFormatter` formats the count in the popover, and the trigger's text when pills are off. `concept-rows.tsx` (Add Project's concept values) and `cv-grids.tsx` (Controlled Vocabulary's column mapping) passed a `selectedCountFormatter` that listed the chosen names in the trigger; the pills do that now, so both were removed (and `columnLabel`, unused after it, from the `cv-grids.tsx` import). Single mode is unchanged: no pills, no count row, no footer.
  - **One field keeps its count.** Explore's Parks field passes `showSelectedBadges={false}` because each chosen park is already a removable chip under the search field (4.3). With no pills it would otherwise say nothing about a selection, so it keeps "N selected" as its text and the popover shows the count too. That is the same number twice, in the field and in the list; it can go if the designer wants the field to say "Choose one or more parks" whatever is chosen.
  - **Assumed (refine-prompt).** (a) The count and Select all share one row between the search field and the list, rather than above the search or beside it. (b) Done is the primary button of the popover. (c) The change applies to every MultiSelect, as the 25 Oct badges did ("on every MultiSelect"), not behind an opt-in.
  - **Docs.** `/components/select`, Multi-select: the paragraph names the pills, the count row, Reset and Done, and `showSelectedBadges={false}`.
  - **Checked (0.6).** `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` pass. Live, at 1440px, zero console errors: the Select doc page (open, add three pills with the list open, Select all, Done, remove by click and by keyboard, Escape, Reset; a press on a pill label opens the list); the keyboard order (Enter opens with focus in the search, Tab runs Select all, Reset, Done; Tab from the field reaches each pill's x; the 2px brand ring on keyboard focus); Explore's Parks field (pills off, "3 selected" in the field, the count row and Done in the list); the Flagged concepts project filter (three long project names, one cut with an ellipsis, the formatter's "3 projects" in the count row); the Notifications form's Event field (single mode unchanged, picks and closes). Computed: the count line 14px/400 Barlow, tertiary, tabular figures (the popover's own supporting-text treatment, so no new type layer, 2.9); pills 14px/600, sentence case, 32px; Done and Select all 36px; the pill sits 12px from the field's left edge (the placeholder's own offset, and more than the field's 8px corner, so the two curves do not meet, 2.13).
  - **Not checked.** The other callers, which pass through the same component but were not walked: Add Project's concept rows and Restrictions step, the DSA form's scopes, Controlled Vocabulary's mapping grid, the record edit fields, Taxonomy and Vouchers actions, the dataset ingestion lab's species results; the lg size (no caller uses it); a disabled field; touch; a screen reader.
  - **Found, not fixed (0.7).** Select all and Reset do nothing for a caller that passes no `onSelectAll` or `onReset`: Explore's Parks and the Flagged concepts project filter are two, and the Select all button is now at the top of the list, where a dead button is easier to see.
