# 2026-09-30 - Project switcher: a popup with the ComboBox search inside, not a morphing crumb

- **Sept 30 2026: correction to 2026-09-30-11, per the designer ("why did you delete the popup? The popup with the search box is what I meant. Let's pick the correct component").** The design system's `ComboBox` was the right component, but I had used it by turning the crumb itself into the search field, which removed the popup. The switcher is again a popup opened from the `Projects ⇅` crumb; the search box is inside it.
  - **The popup:** one card (384px, left-aligned to the crumb, 12px below it). At the top, the design system `Select.ComboBox` as the search box ("Search projects", size sm). Under it, the list: A-Z, each project with its ID after the name, the current one ticked, about six rows showing (`popoverSize="md"`, 256px) and the rest scrolling inside. A bar fixed at the bottom, "View all projects" with an arrow, separated by a rule; it is a real button, reached by Tab from the search box.
    - **Search** matches the name or the ID, in any case and ignoring surrounding spaces. With no match the list is empty.
    - **Keyboard:** Enter or Space on the crumb opens it with focus in the search box; typing filters; Arrow Down moves through the list; Enter picks; Tab reaches "View all projects"; Escape closes and returns focus to the crumb. **Mouse:** a click on a project opens it, a click outside closes. Choosing the current project just closes.
  - **Component change (additive, 1.6):** `Select.ComboBox` gained `listbox?: "popover" | "inline"` (default `"popover"`, so every existing caller is unchanged). `"inline"` draws the list in place, straight under the field and scrolling inside itself, for a ComboBox that already sits in a card or popup. To keep an inline list populated, a small `KeepOpen` helper inside `components/base/select/combobox.tsx` opens the list on mount and again when it closes (a ComboBox only builds its visible items while open). It does not re-open after a search that matches nothing (a manual open shows every item, which would undo the filter). Documented in the Select docs page (Combobox section).
    - **Flow-through (1.3):** the other `ComboBox` uses (the header search, the "Add > Dataset" project picker, the species picker and the DLA location picker) use the default popover and were not touched. Live check on the first two: the header search still floats its list, the project picker still lists its options.
  - **Bugs found while building it:** (1) the ComboBox reports an empty selection when it opens or is tabbed out of, and my handler treated that as a choice and closed the popup: only a real choice closes it now. (2) A controlled `selectedKey` fought typing (typing clears the selection, the controlled value snapped back, and Enter re-confirmed the current project); the tick is now an icon on the current row, with a spacer icon on the others so the labels line up, and the selection is plain state. (3) The lowercase-only filter from 2026-09-30-11 is kept (both sides lowercased).
  - **Verified:** `tsc`, `eslint --max-warnings=0` on every touched file, `npm run check:contracts` and a production `next build` pass. Live at 1708x934 with zero console errors: the list is populated on open, on repeated opens and on fresh loads (3 loads x 3 opens); name and ID search; keyboard pick, Escape (with and without text), Tab to "View all projects" and Enter; mouse pick, mouse "View all projects", click outside; popup left edge equals the crumb's, 384px wide; with extra rows the list scrolls inside (256px) and the bar stays fixed.
