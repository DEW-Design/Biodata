# 2026-11-06 - Explore option 2 Table toggle

- **Nov 6 2026: Explore option 2 Table toggle.** The designer asked for a variation of the map search where the Species Detail Report's table can be read with the filters, and a toggle between map and table, as an option called "Table toggle".
  - **References.** tableandmap.com (US National Parks): map stacked over a resizable table, a fixed sidebar; the designer named its cost, screen space. Mobbin: the account is not Pro, so the search ("map table") showed three locked tiles and nothing was read from it. Fulcrum (map over table, drag to resize, double-click to flip to side by side), Placemark (a table that fills the screen with the map as a small floating panel), Cloudscape split view (a table of more than five columns gets the width). Interaction and structure only, no styling (2.6).
  - **What was built.** `/pages/observations/option-2`, listed in the Layout tool as "Option 2, Table toggle" beside option 1 (`app/pages/observations/layout-switcher.tsx`, 4.4). A Map and Table switch (the design system's `button-border` tabs, full width, Map01 and Table icons) sits in the search card, the one thing on screen in both views, so it never moves. Map is option 1 as it is. Table docks the same card (440px) on the left as the filter (keyword, Add area, the area chips), with a locator map at its foot (the rows' dots in one colour, a restricted record as its block, the row under the pointer lit), and gives the rest of the width to `DataReport` with the Species Detail Report's columns, Filter attributes and Columns chooser. Drawing a shape from Table goes to Map first. Under 768px the card and the table stack and the locator map steps aside.
  - **The rows.** The Species Detail Report's rows (`speciesRowsFor`) for the projects the search found, kept to the search areas (a restricted record by its block); with no search, every published project's rows. So the table holds what the map plots, in the report's words (2.15), and every role sees it under its own record access (`seedFromExplore`). The report page itself still shows only the projects the role can report on (`reportProjectsFor`).
  - **One search.** The card's field is the table's search (`DataReport search`), so the screen has one search box (4.6). A guest's export in Table view opens the sign-up prompt, as Map's Export data does (`DataReport actions`).
  - **Shared code, opt-in only (1.6).** `DataReport`: `header="none"`, `search`, `actions`, `onRowHover`; every report page is unchanged. `SpeciesRow` carries `lat`, `lon`, `blockKm` (not columns). `reportBundleFor(project, role)`. The report's columns, row id, search text and attributes are exported from `species-detail-report.tsx` and used by both.
  - **Open, for the designer.** (1) Should the table follow Explore's scope (every record the search finds, as built) or the report's (only the projects the role can report on)? (2) With no search the table shows the whole state while the map shows nothing: keep, or show nothing in both? (3) The report's group tiles (Plants, Mammals ...) are left out to give the table the height; the Class filter covers them. (4) The locator map follows the search and keyword, not the table's Filter. (5) Switching back to Map re-fits the map to the areas; the zoom from before is not kept. (6) Whether to add a third state, map over table (Fulcrum), was not built, to keep a toggle as asked.

- **Nov 6 2026 (later): Table toggle redesigned on the designer's direction.** "Have a floating toggle which says map only and table toggle. When the table toggle is selected we show the map and table with the option to expand compress map and table sections like what we did in projects pages (tree view and details)."
  - **Supersedes** the in-card Map / Table switch, the docked card and the locator map above (removed).
  - **The toggle.** A floating segmented switch at the top of the map's right-hand column, above the zoom buttons (in the same flex layout as the other map panels, so it never covers one, 2.8), labelled "Map only" (Map01) and "Map and table" (Table), named "Results view" for a screen reader. Named for what each shows, in sentence case; "table toggle" was the designer's name for the option, not UI copy.
  - **Map only** is option 1's screen. **Map and table** stacks the map (search card, toggle, zoom, key) over the Species Detail Report's table, split by a horizontal handle: drag it, Up and Down, double-click back to 50%. The map keeps at least 240px and the table 280px. The table has the project page's full screen control (`FullscreenToggle`, Maximize02 and Minimize02) at the right of its toolbar. The map has no full screen of its own: that is "Map only" (one control per outcome, 3.12). In this view the card keeps the area chips and drops its count and list (the table is the results, 4.3). Pointing at a row lights its dot on the map, matched by the record's id (`occurrence:<id>`); whether Adelaide Hills' hand-written seed uses the same ids as the map's dots was not checked.
  - **New component, designer override (1.4, 1.10).** The designer chose to make the project page's resize handle a component: `components/custom/split-handle/split-handle.tsx` (`SplitHandle`: orientation, label, value, onMove, onStep, onReset), OVR-027 in `contracts/overrides.json`, added to the inventory (nothing else in the baseline changed), documented at `/custom-components/split-handle` and listed in `lib/nav.ts`. `records-explorer.tsx` now uses it in place of its inline handle, so there is one implementation (1.7). Open: the handle is 16px across and has no `hit-area` (2.16), as before; an extension would cover the panes' edges.
