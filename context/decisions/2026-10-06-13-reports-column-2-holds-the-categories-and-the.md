# 2026-10-06 - Reports column 2 holds the categories, and the category tabs leave the page

- **Oct 6 2026: the Reports landing's column 2 was the section's name ("Reports") and nothing under it. From the designer: "column-2 on reports needs to be sorted out too, btw!" (after the Taxonomy column 2 label, `2026-10-06-10-*`).**
  - **What it is now (`ReportsNav`, `app/pages/_shared/reports/reports-nav.tsx`):** the label "Categories" (what the items group by, as on Notification Management and Controlled Vocabulary), then "All reports" (the section's own icon), "Favourites" (the star) and each category with its icon, every item with a count: for BioData Admin All reports 11, Favourites 0, Uploads 3, Specimens and restrictions 3, Project data 3, Agreements 2. A category with no report for the role is not listed. It is the same vertical `Tabs` (`button-brand`) as the other columns 2, so 3.10 (navigation only: no information, no actions) and 3.11 (an icon on every item) hold. It is in the mobile menu too (`MobileNavTrigger` children).
  - **The category tabs that were in main are gone.** They were the same choice drawn twice once column 2 holds it, so main keeps only the header, the Cards / Table switch and the content. The choice is the URL's `?category=` (`favourites` or a category id; none or anything else is All), so a link or a reload keeps it. The header's count follows the choice (Uploads shows 3), the cards under All stay grouped under their category headings, the table's page number goes back to 1 when another item is chosen.
  - **Role-aware:** the counts and the list use the reports the role is offered (`reportsFor`, `2026-10-06-03-*`), so a Registered User sees All reports 10 and Agreements 1 and no DSA report; a public user still gets the shell with the sign-up message and the label only.
  - **A report's own page is unchanged:** it has no column 2 (the rule from `2026-10-06-12-*`: a record page uses the full width), and the breadcrumb's report switcher is its navigation.
  - **Not an exception to 4.2d.** The Template Finder's column 2 (`2026-10-05-04-*`) draws the list's Filter menu as places and needed an exception; the reports' categories are not part of the Filter menu (reports have their own attribute filter inside each report), so nothing is shown twice and no exception is needed.
  - **Verified live (Playwright, 1708x1024, zero console errors):** BioData Admin: All reports, Uploads (3 cards, Uploads selected), Favourites (the empty state), Agreements (both cards); Registered User on `?category=agreements` (one card); a report page has no sidebar; a public user sees the label only. `tsc`, eslint on `app/pages/_shared/reports` and `check:contracts` pass.
