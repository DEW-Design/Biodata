# 2026-10-21 - Data model: the four Observation types follow the 21 Oct record-page frames

- **Oct 21 2026: Data model: the four Observation types follow the 21 Oct record-page frames.** Designer sent four screenshots, one per type: Observation Population, Individual, Community, Non-biotic. Unlike the six types of `2026-10-21-02`, these already had field lists (from earlier frames), so this reconciles the config with what the frames now draw. Lab and config only.
  - **What the frames changed.** (1) Code and description are one field: Life Form, Collection Method, Strata, Macro Habitat, Micro Habitat and Cover/Abundance ("Life Form & Desc" ...), and Disturbance Impact and Upper Stratum ("Disturbance Impact (Code & Desc)"). The schema had a code field and a separate description field for each. (2) Tree Health (Crown Extent, Crown Extent Score, Crown Density, Crown Density Score, Extent of Reproduction, Extent Bark Cracking, DBH, Leaf Die off, New Tip Growth, Epicormic Growth, Mistletoe Load, Leaf Damage) is a section of the Individual frame; it was Community's. (3) Every type gains "Observation Name". (4) Individual and Population no longer have the Zone, Easting, Northing, Latitude, Longitude table; Community and Non-biotic still do. (5) Community has no "Observation Comment" and gains "Upper Stratum (Code & Desc)". Counts now: Population 32, Individual 51, Community 45, Non-biotic 48 (were 42, 48, 57, 48).
  - **Names.** A name the frame spells differently only in spacing or case is the existing name ("Is Annual Herb ?" is "Is Annual Herb?"). No unit in a name, as decided before ("Crown Extent", "DBH"; the unit stays in `FIELD_UNITS`, which moves with Tree Health to Individual). "Association Dominace" in the frames is read as Association Dominance. Weight and Height stay as fixed fields; the frame's Measurements table (Type, Value, Unit, with Tail Length and Left Arm Length as rows) is an open list and has no fields of its own. Assemblage Information and Overstorey Measurements are open lists too; Overstorey's calculated averages are fields, as before.
  - **Aliases** (`FIELD_ALIASES`): a column called "Life Form" or "Collection Method" or "Strata" ... still reads as the merged field, so a file or converter written before the frames keeps mapping. Matched like any field name (case, spacing, punctuation ignored); the old names also still count as known names of the template they belong to.
  - **BDBSA mapping follows the fields.** The confirmed code stays on the merged field ("Life Form & Desc": MUIRCODE; METHODNR, STRATANR, MACROHABNR, MICROHABNR, COVCODE). The description halves you reported on 20/10 (MUIRDESC, METHODDESC, STRATADESC, MACROHABDESC, MICROHABDESC) are now on the merged field's 20/10 column, with a note that it is the description half. Tree Health's confirmed codes moved to Individual. The Latitude and Longitude entries (LATITUDE1, LONGITUDE1) were removed with the fields on Individual. New fields read "Not yet checked".
  - **Pipeline.** (a) Where an Observation's own template has no coordinate field (Individual, Population), the Zone, Easting, Northing, Latitude, Longitude and visit-date columns are used to find its Visit and then dropped from the record. (b) A species comment goes to "Occurrence Comment" on the Occurrence when the Observation type has no comment field (Community now); an Individual or Population Observation keeps "Observation Comment". Without this, 70 of the 264 Heathfield plants would have failed on the missing Community comment (76 errors, from 8). (c) The sample data's Community row uses Canopy Type and Projected Foliage Cover in place of Crown Extent and DBH (Individual fields now), and "Life Form" and "Cover/Abundance" take their new names.
  - **Page and gaps.** `/config/data-model` and the Excel template show the new lists. Four known gaps added (merged code and description; Tree Health moved and Community's missing comment; no coordinates on Individual and Population; tables and typos in the frames), and one existing gap reworded for Tree Health.
  - **Verified (ran).** `tsc`, `eslint` on the touched folders, `check:contracts`: clean; every crosswalk, reported-code and unit entry points at a real field. Live in Chromium, no console errors: Heathfield and the example Ramble 526 valid, 8 errors (the same 8 plants: dominant storey and planted or released, on Community); BAM 64, RAM-VA1 14, Bioblitz 904, all 0 errors; sample data 10 valid, 8 errors; sample workbook 17, 2; the CSV trio; the 12,072-record workbook 0.69 s. In the Heathfield JSON, the fauna "Collection Method" reads as "Collection Method & Desc": "Sign-diggings", and the plants' species comments are on the Occurrence. Parsing the JSON confirms Individual (51 fields) and Population (32) records carry no Easting while the 264 Community records (45 fields) do. Not run: a keyboard pass, the typography skills.
