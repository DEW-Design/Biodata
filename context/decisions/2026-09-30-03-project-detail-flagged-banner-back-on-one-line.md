# 2026-09-30 - Project detail: flagged banner back on one line, Survey at a glance as four boxes, every embedded map gets Full screen, a Datasets report page

- **Sept 30 2026: Project detail: flagged banner back on one line, Survey at a glance as four boxes, every embedded map gets Full screen, a Datasets report page.** Per designer feedback off three screenshots of `/pages/project-detail`.
  - **Flagged concepts banner (Survey records) is one line again.** The sai-wips alert rework made `AlertFullWidth contained` a stacked card (title, description, then the action underneath), which pushed "Review" onto its own line. Fixed in the component, not at the call site (CONTRACTS 1.6, 1.9): a new opt-in `inline` prop on the contained card puts the title and description on one line and the actions at the right, wrapping under only when the card is too narrow. Default unchanged for every other caller. The call site dropped its own border, background and padding classes, since the contained card owns its look. The Alert doc page's API table and Contained section show `inline`.
  - **Survey at a glance is four boxes:** Survey records (Events, Occurrences, Observations in one box, each count opens Survey records filtered to that kind), Artefacts and attachments, Datasets (the count, plus an Upload link to the project's upload page, hidden for public users; the box opens the Datasets page), and Questionable records (records with at least one open flagged concept, from `useFlagCounts`; opens Survey records with the "Has flagged concepts" filter on). The two single counts are `MetricTile`; the other two are composed with MetricTile's exact border, padding and type so all four read as one set. 2 x 2 below 1800px, one row above it.
  - **Every map inside a page gets Full screen.** `RecordMap`'s existing "Full screen" button (top left, clear of the zoom buttons, opening a full-screen modal with "Exit full screen") was generalised into `app/pages/_shared/map-search/expandable-map.tsx` (`ExpandableMap`) and used on: the project's Geographic extent, the record inspector's location, `RecordMap` itself, a nomination's obscured areas (`AreasMap`), and DLA's "Add a Location" draw map. The DLA one passes its Draw circle / Draw polygon buttons into the full-screen bar and opens above its own modal (`overModal`, `MODAL_Z_INDEX`). The registration location picker keeps its own expand (unchanged).
  - **A Datasets report page** at `/pages/project-detail?view=datasets` (same route, like `?view=review`), `datasets-view.tsx`. No dataset list page existed in this repo or on any branch, so it was built new: back link, section header with count and Upload dataset, the upload in progress (or the latest one that needs attention) with its progress, stages and problems, then search and a table (dataset, file, uploader, date, records added, workflow status). A row opens the dataset (`&dataset=<id>`) laid out as a record page (4.6): identity card, then Validation (pre-flight validation and ingestion), Details (files, rows, licence, classification, First Nations) and History tabs. The progress/stages/problems block was extracted from the upload chip's popover into `IngestionDetail` (`ingestion-views.tsx`) so the chip and the page share it.
  - **Sample data:** three earlier uploads to BD-5039 (`SAMPLE_DATASETS`, one per ending: approved, partly added and under review, validation failed), uploaded by the placeholder people, so the report has a history. Uploads made in the browser come from the dataset store as before.
  - Verified: `tsc --noEmit`, `eslint --max-warnings=0` on every touched file, `npm run check:contracts` clean. Live Playwright pass at 1600 x 1000 as BioData Admin, Registered User and Public User: banner on one line with Review at the right, the four boxes, Questionable records opening Survey records at "6 of 28 records match", the extent map's Full screen and Exit, the Datasets list (3 rows, then 4 with a seeded live upload showing "Uploading now" at 28%), a dataset's page, and DLA's draw map full screen over its modal with the draw buttons.
