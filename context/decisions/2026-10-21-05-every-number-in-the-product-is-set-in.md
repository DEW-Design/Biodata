# 2026-10-21 - Every number in the product is set in tabular figures

- **Oct 21 2026: Every number in the product is set in tabular figures.** Designer, after `2026-10-21-04` set it on the data model pages only: "Not on datamodel but in general across all number usages." This supersedes the page-level change in that entry.
  - **Changed.** `font-variant-numeric: tabular-nums` is set on `body` in `app/globals.css` (with a comment naming the reason). It inherits, so every page, doc page, component and portaled overlay (modals, popovers, menus render inside `body`) is covered, and a screen added later needs nothing. Form fields reset `font` to inherit, which carries it in. The two page-level `tabular-nums` classes added in `2026-10-21-04` (the stress test root, the data model page root) are removed: one source for the rule, not three. The 142 existing `tabular-nums` classes elsewhere in the app are left alone: they say the same thing and removing them is churn.
  - **Why it works, measured.** Barlow (product text) and Geist (doc chrome and Scaffold) both have real tabular figures: at 40px, "1111" and "0000" are 84.33px and 84.33px in Barlow (56.38px and 90.41px proportional), and 96px and 96px in Geist (56.64px and 107.28px). Fredoka, which sets only the biodata home wordmark, was not loaded on the page used for the measurement, so it is unchecked; the wordmark has no digits.
  - **Verified (ran, in Chromium).** 16 screens (the home page, biodata-home, dashboard, project list, project detail, DLA, DSA, observations, taxonomy, reports, the post-6-oct lab, the stress test, the data model page, and the Table, Input and Typography doc pages): 300 elements containing digits, inputs included, every one computes to `tabular-nums`; none are the exceptions (monospace is exempt, and none were found carrying digits). The stress test layout checks of `2026-10-21-04` (tabs, filters, "Load more" width) were run again on the page-level version and passed; the global rule applies the same property from the body. `tsc` clean.
  - **What changes visually.** Digits take the width of the widest digit: a "1" has more space around it, so a column of numbers lines up on the right and a changing count holds its width, and a figure in running text or a large display number is slightly wider than before. Nothing else.
  - **Not covered.** A screen shown only to a role not previewed here, and a screen that loads after an interaction (a modal or a menu not opened), were not walked. They inherit the rule, but I did not look at them. A component that sets its own `font-variant-numeric` (a `normal-nums` or `slashed-zero` class) would override it; none was found carrying digits. The Emil typography skills (§0.6 item 8) were not run. Not committed.
