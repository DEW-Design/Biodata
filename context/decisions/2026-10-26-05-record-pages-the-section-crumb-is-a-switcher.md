# 2026-10-26 - Record pages: the section crumb is a switcher on notifications, taxonomy, vouchers and vocabulary

- **Oct 26 2026: a record page's section crumb is the collection's switcher (the label with an up-down caret, opening a searchable list of the other records and "View all ...") on every collection that has a record page. Four were still a plain link, and an `AUTO` check now stops it.** The designer, with a screenshot of a notification's page (the crumb "Notification Management" with no caret): "missing chevron up and down treatment. Please make sure breadcrumbs are consistent."
  - **Principles at stake (0.10):** 3 One system (CONTRACTS 4.6 item 5 already said every record page's section crumb is a `BreadcrumbSwitcher`; the project, DLA, DSA, nomination, user, role, permission and report pages had it), 5 Make it obvious (the caret is what says the crumb opens something). They agree.
  - **What changed.** Four thin wrappers over `BreadcrumbSwitcher`, each built like `DlaSwitcher` (no new component, so no override):

    | Collection | Wrapper | Lists | Label and addon | "View all" | Where it shows |
    | --- | --- | --- | --- | --- | --- |
    | Notification Management | `NotificationSwitcher` (`nt-switcher.tsx`) | every notification, A-Z | its name, its ID beside it | View all notifications | a notification's page |
    | Taxonomy Management | `TaxonSwitcher` (`tx-switcher.tsx`) | every taxon of every rank, A-Z (146 rows) | its name, the common name beside a species and the rank beside a higher taxon | View all taxa | a taxon's page |
    | Voucher Management | `BatchSwitcher` (`vm-switcher.tsx`) | every scan batch, newest first | "Batch 1012", its source beside it | View all batches | a batch's page and a record's page in it (the crumbs after it, "Herbarium / Batch 1012", stay links) |
    | Controlled Vocabulary | `VocabularySwitcher` (`cv-switcher.tsx`) | every vocabulary, A-Z | its name, its ID beside it | View all vocabularies | a vocabulary's page |

    Each shell takes the record it shows (`recordId` on `NtShell` and `TxShell`, `batchId` on `VmShell`, `CvShell`'s existing `currentId`) and draws the switcher in place of the link; the new and edit forms and the lists keep the plain crumb, as the DLA, DSA and nomination shells do. The wrappers read the same stores the lists do, so a record the list shows is in the switcher (a draft notification included).
  - **A second occurrence, so a check (0.8).** CONTRACTS 4.6 said "one is due if a record page ships with a plain section crumb again". It had: `AUTO §4.6b` is added (`scripts/check-contracts.mjs`): a shell that defines `recordPage` and renders no `*Switcher` fails. The layout and version tools on the Prototype bar (`NtOptionSwitcher`, `VmOptionSwitcher`, `VersionSwitcher`) do not count, since they hid the gap in two of the four shells. Tested on the nine shells that define `recordPage`: at HEAD it flags exactly the four (notifications, taxonomy, vouchers, vocabulary) and none of the five that had a switcher; now it flags none. 4.6 gained the MUST (a collection with a record page has the switcher on it), the origin and the enforcement line, and the scoped rule files were regenerated (`npm run contracts:rules`).
  - **Checked.** `npx tsc --noEmit` clean; `npx eslint` clean on the four shared folders; `npm run check:contracts` passes. Live (Playwright, 1500 x 900, zero console errors): on a notification, a species taxon, a higher taxon, a voucher batch, a voucher record and a vocabulary the crumb is a button with the label and a caret; its computed type is the DLA reference's (14px, weight 400, `rgb(112, 107, 104)`, 32px tall); it opens a search box, the list with the current record ticked (13 notifications, 146 taxa, 12 batches, 18 vocabularies) and the "View all" bar; picking a record opens it with the role kept; the notification, taxonomy rename and vocabulary new forms and the notifications list keep the plain crumb.
  - **Not checked.** A touch pass of the popups, and the narrow layout; a role with no access to the collection (the shells already show no switcher and no record name to it, so the switcher is behind the same `canManage` test as the link). Other crumbs that are not a collection's record page (Flagged concepts, the dataset upload flow, the template finder) were not changed.
  - **Open, for the designer (0.4).** The Taxonomy switcher lists all 146 nodes, every rank and the ones no longer current; if it should list only the current ones, as the list's default filter does, it is one filter in `tx-switcher.tsx`.
