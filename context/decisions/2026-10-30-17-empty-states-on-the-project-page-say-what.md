# 2026-10-30 - Empty states on the project page say what is missing and how to fill it

- **Oct 30 2026: the project page's empty states are real empty states.** The designer, with a screenshot of the draft's Published by and Project managers cards (a name and a badge and white space; Project managers had nothing but its badge): "empty states need to be much, much better." The screenshot is two cards; the same fault was across the page, so the page's empties were done together (the sibling check, 0.6 item 5).
  - **Job and principles (0.10).** Someone opens a new or draft project and has to see what is missing, why it matters, and how to fill it, and a viewer who cannot fill it has to be told what is missing without being offered a button. Principles: 7 Design every state (nothing yet, nothing matches, an editor and a viewer), 5 Make it obvious, 4 Tell the truth ("No species match" was said of a project with no species at all), 1 Say less (a search, a Filter and a view switch with nothing to act on), 3 One system (the Records tab's empty state is the pattern: `ListEmptyState`, one line, the way forward). They agree.
  - **What changed.**
    1. **The shared `ListEmptyState` has a `compact` variant (opt-in) and an action icon.** `compact` is the same shape for a card with nothing in it (a smaller icon and heading, no minimum height, the heading one level under the card's); `action.icon` lets an add say `Plus` (3.12) where the default is still the reset arrow. Every existing caller is unchanged (the DLA list still draws an 18px, 600-weight h2).
    2. **Overview cards.** *Published by* with no contact named shows the organisation and then "No contact named"; *Project managers* with none shows "No project managers yet"; *Geographic extent* with nothing drawn or chosen shows "No geographic extent yet". Each says what is missing in one line and, for a person who can edit, has the action that opens the card's own editor ("Add contact", "Add project manager", "Add geographic extent"); a viewer gets the same heading and a line that says it has not been done, with no button. The lines are from the form's own words: "the people to contact about it" and "the area this project's data collection covers" (Add Project), and "Only a Project Manager or a BioData Admin can change access" and the restrictions' "Project Managers and BioData Admins can view and edit" (the access and restrictions pages). A contact or manager the form left blank no longer counts as one.
    3. **Species, Artefacts and Datasets tabs: nothing yet is told apart from nothing matches (4.2e).** With nothing at all the tab says so in the Records tab's card, and drops the tiles, the search, the Filter and the view switch, which had nothing to act on: "No species yet" (a species appears once an occurrence is in Project records; Upload dataset), "No artefacts yet" (what attaches one; Upload attachments, for a signed-in person, opening the same bulk dialog as the header's Upload menu), "No datasets yet" (Upload dataset). With data and a search or filter that finds nothing, each says "No species / artefacts / datasets / records match" and offers the reset ("Show all ..."), which clears the search, the filter and the group. The Records tab's no-match text was a bare line and is now the same.
    4. The bulk attachments dialog is the template's now (it was the hero's), so the hero's menu and the Artefacts tab's button open one dialog.
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` pass. Live (Playwright, zero console errors): the draft project (Flinders Ranges Reptile Atlas) as BioData Admin shows the three cards with their actions ("Add project manager" opens the card's editor) and as Public User shows the same text with no button; a new project's Species, Artefacts and Datasets tabs show the one card and one action each, with no search or Filter of their own; "Upload attachments" opens the dialog and "Upload dataset" opens the new project's upload page; on Adelaide Hills a search with no result shows "No species / artefacts / records match" and "Show all ..." brings the list back.
