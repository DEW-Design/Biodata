# 2026-09-28 - Nominate Sensitive Species built, per direct request, from the Master Flows lo-fi

- **Sept 28 2026: Nominate Sensitive Species built, per direct request, from the Master Flows lo-fi** (Figma `YMproGZfrFB5jUqPHPxMhk`, node `1401:10936`: one form screen in four states). The lo-fi fixed the content and the flow; it was fitted into the shell, not copied (CONTRACTS 2.5).
  - **Designer decisions:**
    1. "Attribute" is the word used here, as the lo-fi says; the project flow keeps "concept".
    2. **Location means a set of areas (drawn, uploaded, picked or entered) whose records get obscured**, not a precision setting.
    3. One species per nomination for the MVP; bulk nomination is in the Backlog.
    4. The review side is in scope, with the statuses I suggested: Draft, Submitted, Under Review, Returned for more information, Accepted, Rejected.
    5. Every signed-in role can nominate; a guest gets the restriction and sign-up invite, as with DLA.
  - **Routes (the DLA "list, record, form" pattern):**
    - `/pages/nominations`: Section header, search, a contextual Filter (Status, Species group, Protection, Nominated by, Updated), a sortable table that fits the viewport. The panel (`nominationReview`, BioData Admin) switches between My and All nominations; everyone else sees only their own, and column 2 instead shows how a nomination is reviewed (the real Progress steps component). Someone else's draft is never shown to the panel.
    - `/pages/nominations/new` and `/pages/nominations/<id>/edit`: `FormPage` with four sections in column 2: Species (the lo-fi's left-hand picker moved into main: search, "Show only" group checkboxes, a list grouped by group with photos and Restricted or Nominated badges), What to protect (All data or Specific attributes, then the attribute rows), Justification, and Review. Mandatory details block Continue for the section being left only. A draft needs only the species.
    - `/pages/nominations/<id>`: the gradient identity card (photo, name, ID, nominator, submitted date, status), one `RecordActionBar`, a status banner, what's protected (areas listed and on a map), the justification and the status history.
  - **Workflow:** the nominator saves a draft or submits; can edit until the panel starts; resubmits after a return. The panel starts a review, then Accepts (confirm), Rejects (reason required) or Returns for more information (note required). Each step is recorded in the history. State is a persisted zustand store (`biodata-nominations`).
  - **Reused, not rebuilt:** the attribute editor is the project flow's `ConceptRows` (two additive props, `noun` and `renderBelow`, and a new `areas` value type); adding an area reuses DLA's `AddLocationModal`; the map is Explore's `SAMap`; the reason modals are the shared `RejectModal` (now with optional title, description and labels, defaults unchanged). New files are page-shared under `app/pages/_shared/nominations/`, not `components/**`, so no override was needed.
  - **Wired in:** the nav item is a real link (`key: "nominations"`); "Sensitive species nomination" is in the Add menu; the role switcher sends a guest previewing a nomination to Home; Home's "Nominate Sensitive Species" and "Request new DLA" quick actions are live (the DLA one was still disabled although DLA is built); Home's Southern Bell Frog task links to its nomination (seed NSS-2026-00001), and the Continue strip now only picks a task you can continue.
  - **Content:** real species from the shared dataset, no fish (none in it, so no Fish filter); no NSX code (not in our data); the lo-fi's Axolotl and Poison Dart Frog placeholders are not used. Seeds use the placeholder cast and the BDBSA organisations.
  - **Fixed on the way, a real bug:** `search-data.ts` imported `projects` through `project-list-content.tsx`, a `"use client"` file, so any server module reaching it (a route's `generateStaticParams`) got a client reference and crashed. It now imports from `project-list-data.ts`, as `dla-data.ts` already did.
  - **Verified:** `tsc`, `eslint --max-warnings=0` on every touched file, `npm run check:contracts`, and the real Pages build (`PAGES_BASE_PATH=/Biodata next build`, all nomination routes prerendered). Live Playwright pass: registered list (3 own, no switcher), a full new nomination (blocked Continue on species, areas and justification; Malleefowl with its restriction warning; a national park area; Sex attribute; map; review; submit), admin list with the waiting banner, Start review, Return with a note, the nominator's returned banner and Update and resubmit (opens on Review, back to Submitted, 5 history entries), Accept on a seed, guest restriction, persistence across reload, Add menu and Home links, and a regression pass over Explore, DLA, DSA, Add Project option 2 and the admin dashboard.
