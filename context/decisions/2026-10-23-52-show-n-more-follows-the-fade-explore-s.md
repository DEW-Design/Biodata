# 2026-10-23 - Show N more follows the fade: Explore's list, and every short list on a map card

- **Oct 23 2026: Show N more follows the fade: Explore's list, and every short list on a map card.** The designer, with a screenshot of Explore's Species list fading out at its foot with nothing to press: "can we have show x records here? That would be good - so there's no guessing work for the user. If there's a gradient at the bottom denoting more records, we should have the show x more button - like the one we have on the data validation error map visualise panel."
  - **The gap.** `MapResultList` showed its pinned "Show N more" only while rows were not yet drawn (more than 25). A list of 12 or 14 rows is drawn whole, so it scrolled inside the card, faded at its foot (that is the fade's job) and offered no number and no button: the same fade, on Map visualise's 15-row Metadata tab, had none either.
  - **The rule now (one component, so every card has it):** wherever the list fades there is a Show N more, and N is true. While rows are not drawn yet it says how many the press draws, up to 25, as before. Once every row is drawn it says **how many rows are not yet fully in view** (a row cut by the fade, a row under the button, a row below), counted from the list's own scroll, and the press scrolls to the first of them (a heading that starts its group first), moving focus to it for a keyboard press. It goes when the end of the list is in view, and a list that fits has neither the fade nor the button. The count follows the card's height: 12 in a 700px window, 4 in a 1300px one, none when everything fits.
  - **Measured live (Playwright, Super Admin):** Explore's Species tab (14 rows, 5 in view): "Show 9 more"; one press scrolls and it reads "Show 3 more"; a second goes to the end and both the button and the fade are gone; back at the top it is "Show 9 more" again; scrolling to the end by hand also removes it. The Projects tab (5 rows) fits: no fade, no button. A keyboard Enter on the button focused the first row it brought into view. Map visualise: All errors and Business rule "Show 25 more" (rows still to draw, as before), Coordinate mismatch (29 rows) "Show 4 more", Metadata (15 rows) "Show 9 more", which is the new case. The docs demo (56 rows): "Show 25 more", then "Show 6 more". Zero console errors. `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` clean.
  - **Where it is:** `app/pages/_shared/map-search/result-list.tsx` (the list measures itself, a frame after each render and on scroll, resize and a change of rows; the pinned button, the padding under the last row and the fully faded stretch under the button all follow the same `more`). `/patterns/map-list-card` states the rule. No change to a caller: Explore's results, Map visualise and the docs demo take it.
  - **A limit, so it is not read as more than it is:** the count is rows, from their positions, so it moves as the list is scrolled (a row half in view is counted as not in view), and "Show 12 more" on a long drawn list scrolls one screenful, not twelve rows' worth: it then reads the remainder. A list longer than 25 reads as before until its last rows are drawn. The pinned button's own bistable edge (a row ending within the button's 52px) was handled by counting those rows as not in view while the button is up; it was not stress-tested by scrolling slowly across that edge in a real trackpad session.
  - **Not checked:** a real touch device, Safari, a screen reader reading the button as the count changes (its text is "Show N more"; the list is not announced).
