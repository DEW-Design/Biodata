# 2026-10-15 - Flora Taxonomy Report: seven more sheets (Reg Herb Data to Species Synonym), the new name, and the tab strip that fits

- **Oct 15 2026: Flora Taxonomy Report, sheets four to ten.** The designer sent seven more sheets with their metadata (screenshots) and columns, and, on the Reports landing page, the page feedback "Flora Taxonomy Report. There's also a horizontal overflow in the report detail page. Please fix." Follows `2026-10-15-05-*` to `-07-*`; the report stays BioData Admin and Super Admin only.

  **The name.** The report is "Flora Taxonomy Report": the landing card, the report's hero, its breadcrumb and the `/pages` index. One constant (`TAXONOMY_REPORT_TITLE`, `taxonomy-report-title.ts`, its own file so the landing's list of reports does not load the taxonomy data to name it) is used by the report list, the page and every tab. The route, the report's id (`taxonomy`) and the feature are unchanged. The sheets' own titles ("BioData - Taxonomy list - SA Regions" and the rest) are still the first row of each export.

  **The seven sheets** are tabs 4 to 10, each in the way of the first three (the parameters of the sheet's metadata as fields above its table, narrowing the rows and the hero counts, and written above the columns of Export CSV and Export XLSX under the sheet's title): `?tab=ref-herb`, `attributes`, `audit-log`, `rename`, `split`, `append`, `synonym`.
  - **Reg Herb Data** ("BioData - Taxonomy list - Reg Herb Data", 10 columns; parameters Species Code & Name, NSX Code, Common Name, Area (SAReg/State/OS), Date): one row for each row of a taxon's Reference Herb Data table (Flora). A row has no date of its own, so the Date parameter reads the taxon's days (its Date, created, renamed, modified). "Taxon Voucher" is "Taxon voucher?" as the table has it.
  - **Species Attributes** ("... - Species Attributes", 17 columns; Species Code & Name, NSX Code, Common Name, Region Group, Region Group, Attributes type "Current or Official", Date): one row for each row of a taxon's Attributes table. The sheet names "Region Group" twice, in the parameters and the columns; the second is read as Region name, the field after Region Group in the Attributes table. Attributes type is a choice of Current or Official over the two flags; Date reads the Date of assessment (written "10 Aug 2026", not as the ISO day the date field stores). "Attributes is Current" and "Attributes is Officical" are "Attribute is current?" and "Attribute is official?".
  - **Audit Log** ("BioData - Taxonomy list Audit Log Report", 16 columns; NSX Code, Species Code & Name, Common Name, Audit log Duration, Modified By, Modified Date "Date Timelines"): one row for each thing done to a taxon, oldest first, numbered from 1. The rows are what the app knows: each change committed in Taxonomy Management (`useChanges`: Rename, Combine, Split, Append) and the days and people a taxon records (Created On and By, Renamed, Edited or Modified On and By), a taxon's own record being left out where a change on the same taxon the same Adelaide day already says it, so one Rename is one row. Modified Date is the app's own Last 7, 30 and 90 days. The app keeps no field-by-field history, no source and no second or third person to comment: Source Type, Source and the later User and Comments columns (three pairs in the sheet, in its order and under its labels) are drawn and empty, and the sheet's blank column is not drawn.
  - **Rename Species**, **Split Species**, **Append Species** ("BioData - Rename Species | Taxonomy list Management Report" and so on; parameters NSX Code, Species Name, Common Name, Created On as two dates, Created By): one row for each species a committed change produced, read from the change log, oldest first. The names are read from the change itself, so a later rename of the same taxon does not rewrite an earlier row. Rename shows the species as it was before under NSX Desc and the new name in New Genus, New Species and the infraspecific columns; Split shows the species split under "Species to Split" and one row for each species it made; Append shows the new species with its family, order and major group. Created By and Created On are the change's person and Adelaide time; Modified By and Modified On are empty, because the app records no editor of a change. "Infraspecific 3 Rank" at the end of Split's infraspecific columns is read as "Infraspecific 3" (the pattern is Rank n, Infraspecific n).
  - **Species Synonym** (28 columns): one row for each name a taxon was known by. A synonym carries no NSX code, family or order of its own here, so those shown are the taxon's it is a synonym of; the creator is not recorded, so Created By is empty; Fauna's synonyms carry a creation and a modified date, Flora's carry a Date.
  - In every sheet the sheets' blank columns are not drawn, labels are sentence case and spelled out, and the Filter menu offers the facets the parameters do not (CONTRACTS 4.2d). The sample person in the sheets' parameter cells ("Smith, Felicity") is not used: Created By and Modified By are chosen from the people the rows hold.

  **Structure.** `useSheetTab` (`taxonomy-sheet-tab.tsx`) turns a sheet (its title, columns, rows, parameters and how they narrow the rows) into a tab, so the seven new sheets are data and columns and not seven copies of the same wiring; the first three tabs were written before it and could move to it. Data: `taxonomy-herb-attributes-data.ts`, `taxonomy-audit-data.ts`, `taxonomy-management-data.ts`; tabs: `taxonomy-herb-attributes-tabs.tsx`, `taxonomy-audit-tab.tsx`, `taxonomy-management-tabs.tsx`. The parameter parts gained `ParamChoice` (a fixed list) and a `labels` option on `DateParams`. Nothing in the design system or the shared report code changed in this task.
