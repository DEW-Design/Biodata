# 2026-10-23 - Dropdowns on a toolbar name themselves: Select inlineLabel on the Data Validation Error Report

- **Oct 23 2026: Dropdowns on a toolbar name themselves.** The designer, with a crop of the Data Validation Error Report's two dropdowns (one showing "B... Flinders Ranges Reptile Atlas", the other "flinders_bushland_assessment_0..."): "as a user, how would i know what fields these are? seems a bit odd." (refined with `/refine-prompt`: the table and the prompt were shown with the reply).
  - **Principles at stake (0.10):** 5 Make it obvious (a person knows what a control is without opening it), 1 Say less (a label that costs a second row of toolbar is a cost to the table), 3 One system (the design system's `Select`, extended once). They pull a little apart on where the label goes, see the assumption below.
  - **The fault:** the two dropdowns on 23 Oct (`2026-10-23-63`) were named only by `aria-label`, which is for assistive technology: a sighted person saw two values side by side, a project's name and a file's, and nothing said which was which ("Placeholder ... cannot replace a label", "when affordance is missing, users guess"). The crop is the first build, before that day's fix to the cut text (the code is no longer cut first); the live report was measured before this change and already showed "BD-5137 · Flinders Ranges Reptile Atlas".
  - **The change:**
    1. **`Select` has an opt-in `inlineLabel`** (additive, default unchanged, 1.6): a short label drawn inside the trigger before the value, in the Select's own secondary-text treatment (14px, 400, `text-tertiary`, the same as its `supportingText`), the value staying 14px/500 primary. It is `aria-hidden` and becomes the control's accessible name when there is no `aria-label`, so it is read once: the name is "BD-5137 · Flinders Ranges Reptile Atlas Project" (Playwright's accessibility snapshot). The API table on `/components/select` has the row.
    2. **The report's two dropdowns** use it: "Project" and "Dataset", then the value (code or id first). The trigger stays 36px, the row stays one line.
    3. **Width:** 256px at the least, growing into the spare room of the row up to 384px (`grow`, `max-w-[min(24rem,100%)]`), because the label takes about 52px and the dataset's file name was cut to "flinde...". Measured, the two triggers are 384px at 1686, 353px at 1440 and 273px at 1280, one row (all controls on one y) at each; the project name is shown whole at 1686 and cut at its end at 1440 and 1280, the code and the label never.
    4. **Text updated with it:** CONTRACTS 4.6 (the exception said "an `aria-label` and no label above"), the comment on `parameters.inline`, `/patterns/report-toolbar`; `.claude/rules` regenerated.
  - **Assumed, to confirm:** the label sits **inside** the trigger and not above it. The designer asked for one row beside Filter (`-63`), and a label above would take about 26px more of a toolbar on a page that gives the table its height (4.6: "content might be more important than controls"). If a label above is wanted, it is the Select's existing `label` prop and the row aligns to the bottom; say so.
  - **Sibling grep (0.6 item 5):** of the standalone `Select`s under `app/pages` named only by `aria-label`, the ones in table cells, editor rows and forms sit under a column header or a row label and were left. One other stood alone beside a search: "Open screens as" on the screens index (`/pages`). It now has `inlineLabel` and is 320px wide (it was 256px and cut "Public user (signed out)"; measured now 320 by 36, nothing cut). This was not asked for; it is the same fault, one line.
  - **Checked live (Playwright; zero console errors):** Super Admin at 1686, 1440 and 1280 wide; Registered User (2 dropdowns, the same labels); keyboard (Enter on Project, ArrowDown, Enter chose the other project and the report followed); the open list, looked at in a screenshot; `/components/select` and the screens index load. `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` clean.
  - **Not checked:** touch, Safari, a screen reader other than through the accessibility tree. The Project dropdown with one project only and the Dataset with one dataset (nothing to choose, 2.12) is still the open question from `-63`.
  - **Open, for the designer:** whether the label should sit above the field instead; whether the other reports that may take `inline` should show their fields with the same label; and whether a cut value should show its full text on hover (the design system's `Select` has no tooltip for it).
