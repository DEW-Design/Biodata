# 2026-10-02 - Add Project: survey type, methodology from the vocabulary, team in the owner step, species list, per-concept justification, projects kept in localStorage

- **Oct 2 2026: Add Project: survey type, methodology from the vocabulary, team in the owner step, species list, per-concept justification, projects kept in localStorage.** The designer, on annotated screenshots of Add Project (second layout), the Restrict a species panel and the final screen, in one batch.
  - **Step 2 renamed** "Data Collection and Methodology" (was "... and Storage") in both layouts' step titles, the rail's Create Project steps, the project page's section and contents list, and the project edit labels.
  - **Survey type** (Biological Survey / Native Vegetation Survey): a required horizontal radio pair above "Method of data collection", on both layouts, the project page (a row) and its edit form. Stored as `DataCollectionState.surveyType`. **Template filtering by survey type is not built:** no template says which survey type it belongs to, and the mapping is not invented (0.3).
  - **Methodology** replaces "Method details": a `Select` over the active entries of the Survey method controlled vocabulary (BIODATA-102, `methodology-fields.tsx`, shared by Add Project, both layouts, and the project edit form). The chosen entry's name is stored in `methodDetails`; older free text still displays as its own choice. The vocabulary holds 6 entries; the designer said there are 11 methods, which are not in the repo, so they are not invented.
  - **Data owner step:** the Organisation / Individual radios sit side by side (also on the project edit form); "Add another contact" contacts carry an optional Organisation (`ContactPerson.organisation`); the Project team section (Your role, Project managers) is part of the Data owner section, so the flow is 5 sections plus one per restriction kind. The project edit form's owner card checks only the owner half (`missingOwnerFields`), its managers card the rest.
  - **Other restrictions hidden for now:** `OFFERED_RESTRICTION_TYPES` leaves it out of Add Project (both layouts) and of "Add restriction" on the project page. A project that already has one still shows it.
  - **Species restrictions:** every species is listed (search, count, a Restrict button per row; Edit and remove once restricted) instead of the combo box. Restrict opens the same panel with the species fixed. Save is never disabled: pressing it with something missing shows what, on the field.
  - **In the panel:** the From date defaults to today and is mandatory (shared `ConceptRows`, so the nomination form's Date observed does the same); the Observer / Contributor trigger names the people chosen instead of "N selected" (`MultiSelect` trigger text now truncates, additive); Permit Number takes a value (text); every concept gives its own justification (species with "Selected concepts", and Project metadata; "All concepts" keeps one). `metadata.justification` is gone from the state; the project page and the sensitive restriction report read each concept's own.
  - **Final screen:** "Learn How" (a disabled button) and "Skip and Go to Project" are replaced by one primary "Go to Project" (trailing arrow) that opens the new project.
  - **Projects kept in localStorage:** Create project saves the submitted form (`created-projects-store.ts`, key `biodata-created-projects`, dates and the restriction set serialised by `form-storage.ts`, the logo not kept). A created project has its own number (the highest in use plus one), is Active, and opens at `/pages/project-detail/created?project=<id>`: one fixed route, because a static export cannot make a page for an id that only exists once someone creates it. The project page template takes a `seed` and joins its `?view=` queries onto a base path that already has a query. The Projects list, its filters and the breadcrumb switcher include created projects; the header search, DLA, the reports and Explore do not.
