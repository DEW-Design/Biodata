# 2026-10-15 - Flora Taxonomy Report: the sheets' metadata is the table search and Filter, no Parameters

- **Oct 15 2026: no doubling up.** The designer, off a screenshot of the Parameters popover on the report's List detail tab: "thinking out loud - doesn't make sense to have two different search bars as the table search bit already takes care of this. And filters too. I feel like parameters are doubling up. We need to fix this." Reverses the choice in `2026-10-15-10-*` for the taxonomy sheets ("the popover holds all of them"), which the designer made before seeing the popover beside the search and the Filter.

  **What was doubled.** A sheet's typed metadata (Species Code & Name, NSX Code, Common Name, Herbarium No) was a text field in the popover and the table's search, which already matches a code, a name and a common name. Its chosen metadata (Family, Group, Genus, Region, State/OS Area, Area, Region Group, Region Name, Attributes type, Modified By, Created By) and its dates were selects and date fields in the popover and attributes of the Filter menu.

  **Now.** A taxonomy sheet has no Parameters. Its metadata is the table's own controls (`taxonomy-sheet-tab.tsx`, `FilterSpec`): a typed line is the **search**; a line chosen from a list and the sheet's date are attributes of the one **Filter** menu, first in it and named as the sheet names them, with the Filter's icons, searchable lists, date presets (Last 7, 30, 90 days), custom range and removable chips. The export still writes the sheet's title and its metadata lines above the columns, now read from the search and the filters in view (the search beside the first typed line; a filter's chosen values or range beside its line). Checked: Family Myrtaceae with the search "gum" wrote `"Species code & name","gum"` and `"Family","Myrtaceae"`.
  - **Per sheet** (the Filter's first attributes): List detail Family, Group (Major group), Genus, Date; SA regions Region, Date; Aus / World State/OS area, Date; Reg herb data Area, Date; Species attributes Region group, Region name, Attributes type, Date; Audit log Modified by and Audit log duration (the Filter's presets and custom range are also Modified Date, "Date Timelines": one question, written under Audit log duration); Rename, Split, Append and Species synonym Created by, Created on. An attribute with no value in the rows is not offered (Group, until a taxon has a Major group).
  - **Search covers more.** Each sheet's search text now includes the sheet's typed lines (Aus / World, Reg herb data, Species attributes and the management sheets also the common names; SA regions the Herbarium number), and its placeholder says so.
  - **Removed, nothing left behind:** the parameter state, fields and matchers of every tab and its data file, the Taxonomy Report's popover, `taxonomy-report-parts.tsx` (the parameter fields and grid), `taxonomy-aus-world-data.ts`, `DataReport`'s `narrowed` prop, and the popover's `columns` option (every report that has Parameters has one column: a project, a dataset). `DataReport`'s `exportPreamble` may again be a function of the search and the filters.
  - **The Parameters button stays where it says something the search and the Filter cannot:** Data Validation Error (project and dataset), Species Detail and Events, Occurrences and Observations (project). Checked on all thirteen reports: the button is on those three and nowhere else, and the Flora Taxonomy Report has none. The first tab's date filter keeps a row whose days overlap the range, as in `2026-10-15-09-*`.

  **The rule, now in the contract and the pattern page.** CONTRACTS 4.6 item 4: a parameter is what the report is run on and neither the search nor the Filter can say (a project, a dataset); a code or a name is the search; a choice from a list or a date range is the Filter; a control is never in two of the three, and a report must not ask for the same thing twice; a sheet's metadata is the table's search and Filter, written above the columns of the exports. `/patterns/report-toolbar` (rule 1 and "Used by") says the same; `report-parameters.tsx`'s header comment records why. `npm run contracts:rules` regenerated the shell rules.

  **Open for the designer (CONTRACTS 0.4):** (1) a sheet's exact-match lines (an NSX code typed exactly, "Species Code & Name" as one field) are now a free-text search: "M01" finds every code containing it, as the search always did; say if an exact NSX-code match is wanted. (2) Whether Species Detail's and Events' project scope, which the Filter could carry as a Project attribute, should be a filter too (the reports' tiles count the project's records, so it was kept a parameter). (3) The items still standing in `-05-*` to `-11-*`.
