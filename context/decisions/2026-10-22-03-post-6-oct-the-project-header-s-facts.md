# 2026-10-22 - post-6-oct: the project header's facts are disclosed on request

- **Oct 22 2026: post-6-oct: the project header's facts are disclosed on request.** The designer, with two screenshots of the Project records tab: the top of the page (the eyebrow, the title, the five facts, the tabs and the notices row) "takes so much space, leaving the user to scroll through the important stuff at the bottom"; could it be progressive disclosure. Measured at 1440x900: the records explorer's search started 386px down the window.

  **What changed (lab only, CONTRACTS 5.4).** `ProjectHeader` in `app/proto/post-6-oct/project-workspace.tsx` takes `open` and `onToggle`. Closed, it is one line: the title (same h1, Barlow 24px 600), the status badge (the one fact people check first) and a chevron toggle that follows the title ("Show project details" / "Hide project details", `aria-expanded`, `aria-controls`, a DEW `Tooltip`, the chevron turning over as the notices row's does). The "PROJECT" eyebrow and the five facts (Project ID, Start Date, End Date, Status, Published by) are shown only when open, so the status is never stated twice (CONTRACTS 4.3). The state is kept in `Views`, per tab and not in the header, as the notices' is, so a choice survives moving between tabs.
  - **Defaults:** the Overview starts open (its facts are said nowhere else on the page and are what the tab is for); Project records, Species and Artefacts and attachments start closed, so their content is what is on screen.
  - **Result:** on Project records the explorer's search starts at 310px instead of 386px, 76px back to the records.
  - The tabs and the notices row are unchanged: the tabs are the navigation, and the notices row is already one line and is where a failed upload is told.

  **Decided (by me, flagged for the designer):** the per-tab defaults above; the status stays visible when closed; the toggle sits beside the title, not at the far edge; the toggle is instant, with no height animation (the notices row's list is instant too); the 32px between the header and the tabs (Figma 484:3929) is kept.

  **Open.** (1) Whether the Overview should also start closed (the whole project page then opens on its sections). (2) A header that condenses as the page scrolls, or sticky tabs, would save more and is a different pattern (sticky positioning), not built. (3) The notices row still costs about 70px on a project with notices; it could sit inside the same disclosure or become a badge on the toggle. (4) Whether Project ID should also stay visible when closed, as it is in the breadcrumb of other screens (it is not in this one).
