# 2026-10-01 - Reports: column chooser, categories, favourites and last opened

- **Oct 1 2026: on the designer's answers to the Mobbin review ("Column chooser?", "Grouped into categories, yep", "Favourites, row-level actions in the 3 dot menu", "Last opened would be nice as well") and "Make sure you apply this pattern across other reports as well". Follows 2026-10-01-20.**
  - **Every report now follows the same pattern, the first included.** The Data Ingestion Report Pre-Flight Validation was the one report still drawn by hand (plain header, its own table, a count badge). It is now `DataIngestionReport` (`data-ingestion-report.tsx`) on the shared `DataReport`: the gradient card with Scope, Latest record, Rows and Columns, the same 21 columns, nine filters, search, deep link (`?q=`), live clock and downloads; the route uses `ReportPage` like the others. Built by a worker and checked live, including a real upload whose row moved through its statuses on its own and a toast "View report" link. The unused `IngestionReport` component was removed; `useIngestionReport` and `IngestionReportView` stay only for the throwaway filter lab (`/proto/filter-options`, which still draws the old table) and go with it. The other reports already had the pattern (2026-10-01-15, -18, -20). Reports with no export in their wireframe (Data Ingestion, Post Ingestion, Sensitive and Restriction, Voucher ID Update, SpecimenDB Refresh) have no "..." menu: none was invented.
  - **The Columns chooser (`column-chooser.tsx`, in `DataReport`'s toolbar, right end):** the wireframes draw a column icon at the right end of every table and a "Columns" panel (drag handle, checkbox, Apply). Built from react-aria `GridList` with its drag and drop and the design system's `CheckboxBase`, no new component: one popover, search (a report can have 93 columns), every column's checkbox and handle (drag, or keyboard: Enter on the handle, Tab to a drop target, Enter), the first column pinned and always shown (a locked row), "N of M shown" and Reset, and the button reads "Columns" or "Columns · N hidden". Defaults follow the wireframe (every checkbox was ticked) and report 1 (all columns): every column starts shown. It applies as each is chosen: the wireframe's Apply button is not built (1.9 item 2: no hidden Apply). The chosen set starts over when a report's columns change (another tab). Not saved across reloads (per page view). Export CSV still writes every column, in the report's own order. CONTRACTS 4.6 item 4 says this.
  - **Bugs caught while building it, worth knowing:** react-aria caches each table row's and list row's render per item, so a changing column list needs `dependencies` on `Table.Body` (else "Cell count must match column count") and the list needs the hidden set (else every toggle starts from an old copy); a `GridList` cannot switch drag and drop on and off (it is keyed on search); and dragging a selected row drags the whole selection, so visibility is plain checkboxes, not the list's selection. `GridList`'s Escape is not cleared-selection any more (no selection), so Escape closes the popover and changes nothing (1.9 item 1, checked: 45 columns before and after).
  - **Landing: categories, favourites, last opened, row actions.** `REPORT_CATEGORIES` (`reports-data.ts`): **Uploads** (Data Ingestion, Post Ingestion, Data Validation Error), **Specimens and restrictions** (Sensitive and Restriction, Voucher ID Update, SpecimenDB Refresh) and **Project data** (Project Detail, Species Detail, Events, Occurrences and Observations). The category names are the build's; the grouping was the designer's ("yep"). Tabs: All, Favourites, then the categories; in All the cards sit under small category headings. Each report has a star (Favourites tab lists the starred ones; an empty Favourites says "No favourite reports yet") and a "..." menu on its card and its row: Open report, Add to or Remove from favourites, Copy link (the real URL with the role kept, on the clipboard, with a "Link copied" toast). The star and the menu sit above the card's stretched link, and in the table they do not open the row. "Last opened" is recorded when a report is opened (`ReportPage`, after the saved state is read so it never overwrites it) and shown on the card ("Opened 1 Oct 2026 09:12", or "Not opened yet") and as a sortable column. Favourites and opened times are kept per browser (`reports-store.ts`, zustand persist like the other small stores): there is no account or backend.
  - **The landing's table** follows the Mobbin review: the description sits under the name in one cell (rows stay one or two lines), then Category (a gray badge) and Last opened, with the star first and the menu last; Report, Category and Last opened sort.
  - **Verified:** `tsc`, `eslint --max-warnings=0` on the reports folder, the lab and the docs page, `npm run check:contracts`. Live with Playwright at 1440x900, zero console errors: the chooser (hide, show back in place, search leaving 2 rows for "code" with the handles hidden while searching, Reset, keyboard drag moving one column, Escape closing without changing anything and returning focus to the button, Space toggling a checkbox, the set starting over on a new tab); the landing (tabs, grouped cards, stars surviving a reload, Favourites tab, both "..." menus, Copy link putting the URL on the clipboard, row star and menu not navigating, last opened recorded and sorted).
