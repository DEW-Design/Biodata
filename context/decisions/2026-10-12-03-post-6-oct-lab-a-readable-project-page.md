# 2026-10-12 - Post 6 Oct lab: a readable project page and full-page Search

- **Oct 12 2026: Post 6 Oct lab: a readable project page and full-page Search.** The designer, on `/proto/post-6-oct`: leave the rail's Alert card out for now (it is mainly for public users); polish the project-detail page ("too fragmented ... the project details are too overwhelming"), thinking of a citizen or researcher who has come to read it; and make Search a full-page view opened as a tab. Still strictly a prototype. Follows `2026-10-12-02-post-6-oct-lab-the-linear-style-shell.md`.

  **Rail card:** removed from the rail. The bell keeps the role's tasks, so nothing else changed; the card's code and counting rule stay in `attention.tsx` for when it returns.

  **Project page, new default view "Overview" (`project-overview.tsx`).** The page it replaces was about fourteen bordered cards, each a table of label and value rows with an Edit button; the abstract sat in row four of the fourth card. The Overview shows the same fields (none dropped) as one white sheet in the order a reader asks, sections divided by a line: About (the abstract as the lead, then full title and URI or DOI), In this project (records, events, occurrences, observations as four figures that open the records view, then rows for species, artefacts, and for the roles that have them datasets and flagged concepts), Where (a full-width map, centre and radius, the coordinate table behind a disclosure), How the data was collected (survey type, method, focus areas, targeted species, methodology, limitations and biases, permits), Using this data (open, or restricted with each restriction, what it withholds and why, in plain words) and Contacts (publisher, contacts and managers with mailto links). A fact is shown once: status, dates and publisher stay in the title block. Empty facts are left out. "On this page" is kept, level with the title. The page as it was is the "Edit details" view (not for a public user), so a reader never meets an Edit button; Project records, Species and Artefacts are unchanged.

  **Type and surfaces (CONTRACTS 2.9):** nothing new. Section heading `text-lg semibold` (the project page's `Section`), title `text-2xl semibold` and the small uppercase label (`RecordHero`, "On this page"), lead `text-base` (used 60 times in `app/pages`), facts and prose `text-sm`, prose held to `max-w-prose`, tabular figures on counts, `text-pretty` on paragraphs. The Overview is one sheet (`rounded-xl`, inside the panel's `rounded-2xl` less its padding) instead of a card per group.

  **Search is a page:** the rail's search button opens a "Search" tab (one tab, found again if open). The page is a large field (focused on open), underline tabs All, Projects and Species with counts, results in two titled groups (a project: name, code and organisation, status; a species: its group icon, common and scientific name, and the projects that recorded it, each opening as a tab), the typed text in bold, and "Search all records for ... in Explore" for the rest. With nothing typed it lists every project and the first eight species. Same data and visibility rules as the header search (`GlobalSearch`, whose species index and matcher are now exported so the page does not copy them).

  **Shared files touched, additive only:** `project-tab.tsx` exports `OnThisPage`, `TocItem` and `RESTRICTION_DESCRIPTIONS` (and keeps the `lead` prop from the first pass); `global-search.tsx` exports `SpeciesEntry`, `buildSpeciesIndex` and `matchesSpecies`. No behaviour changed on any real page.

  **Open for the designer (CONTRACTS 0.4):** whether the Overview should replace the real project page's default (and where editing then lives: a view, as here, or a button); the datasets upload status, which a contributor sees on the real page, is a row that links out here; whether contacts' emails should be shown to a signed-out reader (the real page shows them, so this does too); what "Where" should name (the data has a centre and radius, no place name); the Overview for the other record pages; a mobile layout.
