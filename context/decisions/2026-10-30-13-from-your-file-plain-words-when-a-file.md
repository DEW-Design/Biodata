# 2026-10-30 - From your file: plain words when a file has nothing to read, no log lines

- **Oct 30 2026: the "From your file" group of the Datasets step no longer prints reader messages.** The designer, with a screenshot of the line "40 tabs not recognised as a site, visit or species list, so not read." under the group: "what's with this kind of copy?" It is a log line written for whoever builds the reader: it counts tabs a person did not know were being checked, says "not recognised" and "not read" without saying what that means for them, and gives nothing to do. A workbook with 40 tabs mostly has lookup lists and calculators, so the count alarmed and told nothing. The miss is mine: it was copy I wrote with no source (0.3) and did not judge as a person's words before showing it.
  - **What changed.**
    1. **The note is gone** from the reader (`file-facts.ts` no longer has `notes`) and from the card. A file with some facts shows the table of what it states, each fact "Not in the file" where it does not state one; how many other tabs there were is not said.
    2. **A file with nothing to read says so once, in a sentence, and has no table:** "Nothing in this file could be read as sites, visits or species, so nothing is filled in from it." ("these files" and "them" for several). Five rows of "Not in the file" under a heading said the same thing five times (4.3).
    3. **The "Read as" row** shows only when the file was recognised as something a person knows (the DEW Ramble survey form, a BDBSA return, a sample matrix). For a file read by its tabs it said "its tabs, by their names and columns", which is reader talk, so the row is left out.
    4. **A file that cannot be opened** reads "<name> could not be read as a workbook." (it was "<name>: This file could not be read as a workbook.", the file named twice).
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the touched folders and `npm run check:contracts` pass. Live (Playwright, zero console errors): a 40-tab workbook of calculators (made for the check) and a text file renamed .xlsx each show the one sentence and no table; the Ramble form, the BAM workbook and the Bioblitz workbook read as before (dates, sites, visits, records, species, "Read as"); a one-tab Site file and my test file read by their tabs show the table with no "Read as" row.
  - **Not checked.** The sentence with two files added at once, one with nothing in it (the table of the other is shown and the sentence is not; read from the code, not run); a screen reader.
  - **For the designer (0.4).** The same question the copy raised and the file answers: when a file has nothing the reader understands, the upload still goes ahead through the normal checks, and the project's other steps are asked as usual. Is that right, or should a file nothing could be read from be flagged to the person before they go on?
