# 2026-10-30 - Geographic extent picker: Draw on the Map is the default, and the map is a square

- **Oct 30 2026: the geographic extent picker opens on "Draw on the Map", and its map is a square the width of the picker.** The designer, with a screenshot of the picker on "Choose from a List": "can we please get the first tab selected by default - draw on a map? Also, can we increase the size of the map so that the user can comfortably draw? make it a square. The height should be equal to current width thanks."
  - **What was wrong.** Two things, one of them a bug that hid behind the first.
    1. **The screenshot was the sample content.** "Pre-fill sample content" set the extent's method to "list" (Coorong National Park), so the form opened on the list. That is changed: the sample now draws the same circle on the map (method "map"), so a demo opens on the first tab with the area showing.
    2. **A new form only looked as if the first tab was selected.** The picker drew "Draw on the Map" as selected when the value had no method (`value.method ?? "map"`), but the value itself kept `method: null`, and drawing did not set it. A shape drawn on a blank form was not counted: reproduced live, a circle drawn on the Geographic extent step of a blank Add Project and Continue pressed gave "Details missing: Geographic extent". The only way past was to click another tab and back. The nomination form had the same trap (it drops an extent with no method).
  - **What changed.**
    1. `emptyGeoExtent()` starts with `method: "map"`: the first tab is selected in the value, for every form that starts an extent (Add Project, a location restriction, a nomination's location). A shape drawn on the map sets `method: "map"` too (the picker's three draw handlers), which also covers an extent saved with no method.
    2. **The map is a square** (`aspect-square w-full`, was `h-64`, 256px): in the picker's inline map and in the Expand-dialog variant Add Project uses. At Add Project's width that is 718 by 718px (254px before); in a location restriction's narrower card it is 668 by 668. The Expand button, zoom buttons and the draw tools are where they were.
    3. Two readers that used "has a method" to mean "has an extent" now ask `isGeoExtentComplete`: the review's Geographic extent row and the project page's Extent row. With the first method in a new extent, "has a method" is always true, and an unfinished one would have read "Not yet defined" where it used to read "Not provided".
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` pass. Live (Playwright, 1716 x 1030, zero console errors): a blank Add Project (option 1 and option 2) opens the step on "Draw on the Map", the map measures 718 x 718, a circle drawn on it counts and Continue goes on to the next section; with Pre-fill sample content the same tab is selected with the Coorong circle drawn; in Add Project's location restriction the picker opens on "Draw on the Map" with a 668 x 668 map.
  - **Not checked.** The nomination form's location step, the project page's edit form and the record location picker (`field-controls.tsx`): they use the same component and `emptyGeoExtent`, but their pages were not opened. Touch and narrow windows (a square the width of a phone's column is nearly full height there).
  - **Trade-off, for the designer (0.4).** A square at Add Project's width is taller than the visible form on a 1030px-tall window (about 718px of map under the tabs and the draw buttons), so the page scrolls to see the whole map, and the draw buttons scroll off above it. "Expand" opens it larger if that is awkward. A cap (the square, but no taller than the window) would keep it in view; say if you want it.
  - **Open.** The map still opens at the whole of South Australia (the circle in the blank-form test was a few hundred kilometres wide at that zoom); the bigger map is easier to draw on, but not what zoom it starts at: not asked, not changed.
