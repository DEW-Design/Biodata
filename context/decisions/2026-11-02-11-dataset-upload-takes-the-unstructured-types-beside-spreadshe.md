# 2026-11-02 - Dataset upload takes the unstructured types beside spreadsheets: one queue, no type choice

- **Nov 2 2026: a dataset upload takes spreadsheets and the unstructured types together.** The designer, with a screenshot of Add Project's dataset step (BAM Site.xlsx complete in the queue, then the red line "Only .XLS and .XLSX files can be uploaded. Not added: DEW Newsletter Draft_v0.3.pdf."): "that shouldn't happen - as mentioned, dataset upload can have a few unstructured data types - the ones i mentioned before." The types are the ones of `2026-11-02-07`: PDF, images (JPG, PNG, GIF, RAW), Word, audio and video, 10 MB each, skipping pre-flight and going to post-flight validation on Fluree.
  - **What was wrong.** `2026-11-02-07` made unstructured data a choice: the upload form asked "Type of data" (radio, locked once a file was in the queue), and a queue took one kind or the other. Add Project's dataset step (option 2), which the same entry left as spreadsheets only, turned a PDF away with a hard-coded message. A person who had a spreadsheet and its documents could not add them to one upload.
  - **Changed.** (1) `useFileQueue` and `UploadDropzone` (`upload-dropzone.tsx`) take `accepts` ("spreadsheets", the default, or "everything") in place of `kind`. With "everything" the file picker offers the spreadsheets and every unstructured extension, a file of any other type is turned away ("Only .XLS, .XLSX, PDF, image, Word, audio and video files can be uploaded"), and a file other than a spreadsheet over 10 MB is turned away with its own reason ("Files other than spreadsheets can be up to 10 MB each"). The 10 MB limit stays off spreadsheets, as it was. Only a spreadsheet is read for headings. (2) The upload form (`upload-form.tsx`) and Add Project's dataset step (`with-dataset/dataset-step.tsx`) both use "everything". The "Type of data" choice and `dataKindOptions` are gone; the recommended templates always show; the step's "From your file" card shows only when a spreadsheet is in the queue (a PDF has no facts to read). (3) A dataset's kind is read from its files (`kindOfFiles`, `dataset-data.ts`): unstructured when there are files and none is a spreadsheet, structured otherwise. So a spreadsheet with a PDF beside it is a structured dataset, its run is the structured run, and its row count (`subjectOf`) comes from the spreadsheets' size alone; a set of PDFs and images is stored as unstructured, with the flow of `2026-11-02-07` unchanged (Files added, Processing (post-flight)). (4) The instructions are four steps in the numbered circles: formats for data, the templates, the unstructured types up to 10 MB each, and that those files skip pre-flight and go to post-flight validation on Fluree. They are the designer's own sentences from `2026-11-02-07`, joined into one list.
  - **Assumed (0.3, 0.4).** A mixed dataset runs as one structured dataset: the unstructured files in it ride along and are not given a run stage of their own. So a mixed dataset's status follows its spreadsheets (Pre-flight validation in progress first), where "skip pre-flight, go straight to post-flight on Fluree" is the designer's rule for a file that is unstructured. The list of extensions is still the one of `2026-11-02-07` (not confirmed).
