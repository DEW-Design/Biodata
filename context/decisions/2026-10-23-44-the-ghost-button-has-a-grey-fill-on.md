# 2026-10-23 - The ghost button has a grey fill on hover, in the design system and across production

- **Oct 23 2026: The ghost button has a grey fill on hover, in the design system and across production.** The designer, with a screenshot of "Back to Data Validation Error Report" (an arrow and grey text, nothing around it) and one of Conductor's ghost buttons ("Sonnet 5.5 Extra high" and a chevron, a soft rounded fill when pointed at): "this ghost button, can we have a grey fill on hover? Like the conductor pattern here. You implement this change directly on the design system, then bring it over to all components in production." Assumed: "the ghost button" is a control with nothing around it at rest (a text link, a link-style button, a quiet trigger), which in the design system is **Link grey**; Tertiary already has a grey hover fill, and the fill taken is Tertiary's own (`bg-primary_hover`, gray-50), so every ghost control hovers the same.
  - **In the design system (`components/base/buttons/button.tsx`):** `Button color="link-gray"` is the ghost button: no padding before (`p-0!`), now `px-1.5! py-0.5!` with `-mx-1.5 -my-0.5`, `rounded-md` and `hover:bg-primary_hover hover:text-tertiary_hover`. The padding gives the fill room and the negative margin takes it back, so the text sits exactly where it sat and nothing around it moves (measured: the back link's arrow at x 97 and the card's eyebrow at x 97, as before). The hover **underline is gone**: a fill and an underline together say "this is pressable" twice (2.12). The Button docs say so (Variants) and the token anatomy table has a Link grey row. The 39 Link grey buttons across the product (Hide list, New search, Edit search, Clear all, the sign-in screens' "Back to log in" and the rest) take it with no change at the call site.
  - **Brought to the controls that are the same thing but are not that component:** `RecordBackLink` (the record pages' back link; the pictured control), `BreadcrumbSwitcher`'s trigger, the profile menu's avatar trigger, every header breadcrumb link (set once on the header's crumb group, with the hit area), and the dropdown's "..." button (`Dropdown.DotsButton`, which only changed colour). Each takes padding with an equal negative margin where it needed room, so none moved.
  - **Checked live (Playwright; BioData Super Admin, a mouse):** on Map visualise the back link, Hide list and a header crumb are transparent at rest and `rgb(248, 248, 247)` on hover; Hide list's text decoration is none; screenshots of the back link and Hide list on hover show the rounded fill hugging the text with the arrow still under the eyebrow's left edge. Zero console errors; `npx tsc --noEmit`, `npx eslint` on every touched file and `npm run check:contracts` clean.
  - **Not verified:** each of the 39 Link grey buttons on its own screen (the sign-in screens and the forms were not opened), a Link grey on a dark surface (none was found; on a dark card the gray-50 fill would be wrong, and a dark variant would be a design decision), Safari. Not committed.
  - **Open:** Link colour (the brand ghost) has no fill; it keeps its underline on hover. The designer's picture was grey, so only grey was changed. The fill is gray-50; Conductor's is stronger on a dark window, and `bg-tertiary` (gray-100) is one step more visible if gray-50 reads as too light on the white cards (it is the rail's hover): a token swap in one place.
