# 2026-10-25 - New project restriction kinds, expected restriction level, managers and admins can edit restrictions

- **Oct 25 2026: New project restriction kinds, expected restriction level, managers and admins can edit restrictions.** Designer requests on Add Project's Privacy and Restrictions step.
  - **Kinds offered**, in this order: Embargo; Restrict data based on Species ("Select any species that you want restricted for your project"); Restrict data based on Cultural Sensitivities (new, `cultural`); Restrict data based on Locations; Restrict all records within this Project (new, `all`, replacing Project Metadata in the list). Project Metadata and Other are no longer offered; a project that holds one still shows and edits it (`OFFERED_RESTRICTION_TYPES`).
  - **Expectations data restrictions** (`ExpectationSelect`, `restriction-fields.tsx`): Obfuscate location to 1 km, Obfuscate location to 10 km, Government access only, with the hint that it is an expectation only and a BioData Admin decides after an internal review. Optional. Asked on each species (above its justification), each location, cultural sensitivities and all records.
  - **Embargo:** a new optional field, "Data sensitivities after the embargo ends", using the designer's wording as its prompt (`embargo.afterEmbargo`).
  - **Cultural sensitivities:** Indigenous Information Authority, IIA contact details and Justification (required), and the expected restriction (`restrictions.cultural`).
  - **All records:** the expected restriction and a required Justification (`restrictions.allRecords`).
  - **Locations:** each location is a card on the section itself (name, expected restriction, justification); "Add location" sits at the foot and opens the map selector in a side panel, which now holds the picker only. A place chosen from the list names the card.
  - **Who can edit:** a notice on the Restrictions section, shown once restrictions are switched on: "Project Managers and BioData Admins can view and edit these restrictions".
  - The new kinds appear on the project page's Privacy and restrictions cards, the edit drawer, the audit diff and the post-ingestion report's sensitive type. `cultural` and `allRecords` are optional on `RestrictionsState` so stored projects still read (`culturalOf`, `allRecordsOf`).
  - **Open:** the project manager's control over the project (full control by role, or a page where the manager sets what each project contact can do) is to be worked out with the designer, not built; the descriptions for the two new kinds and the cultural notice line on the project page were drafted, not supplied; whether the expected restriction is required.
