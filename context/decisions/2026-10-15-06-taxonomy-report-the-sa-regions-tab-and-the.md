# 2026-10-15 - Taxonomy Report: the SA Regions tab, and the report is BioData Admin and Super Admin only

- **Oct 15 2026: Taxonomy Report, second sheet, and who sees it.** The designer: "BioData admin and super admin only for now." and a second sheet, "BioData - Taxonomy list - SA Regions", with its metadata (Species Code & Name, NSX Code, Region, Herbarium No, Date as Start Date - End Date, from a screenshot) and its 25 columns: NSX Code, NSX Desc, Region, Description, Include Census?, BS Accept?, Native in Reg?, Estab in Reg?, ID Certain?, Dsn Certain?, Cons Stat., Colln < 50yrs, Name Match, Herbarium No, Herb Voucher Initials, Surname, Coll. No, Is Ref Hb Voucher?, Is Taxon Voucher?, Comment, Adherb Name, Reg Created By, Reg Creation Date, Reg Edited By, Reg Edit Date. Follows `2026-10-15-05-*`, which settles its first open item.

  **Access (settles item 1 of `2026-10-15-05-*`).** The Taxonomy Report carries `feature: "taxonomyManagement"` in `reports-data.ts`, the feature Taxonomy Management itself uses, which passes BioData Admin and BioData Super Admin and no other role. The Reports landing, the category tabs, the report switcher, Create a report and My reports do not offer it to any other role, and opening `/pages/reports/taxonomy` as another signed-in role shows "This report is not available to your role" (`ReportPage`). `ref-roles.md` lists it beside the other individually gated reports; the `/pages` screen index says "BioData Admin".

  **The tab.** "Taxonomy list - SA regions" (`?tab=sa-regions`, icon `Map02`, the one Taxonomy Management's own SA Regions tab uses), built as the first tab is: its own file (`taxonomy-sa-regions-tab.tsx`, rows and parameters in `taxonomy-sa-regions-data.ts`), the parameters as fields above the table in the sheet's order (Species code & name, NSX code and Herbarium no typed and matching part of the value; Region chosen from the regions the rows hold; Start date and End date with a calendar, both empty), narrowing the rows, the hero's counts (Taxa and Regions) and the export, which writes "BioData - Taxonomy list - SA Regions" and the five parameter rows above the column headings. A row is one region record of one taxon, read from the taxon's SA Regions table in Taxonomy Management (`tables.saRegions`, columns `DISTRIBUTION_COLUMNS`), so the report and the taxon's own tab cannot disagree; a Fauna taxon's regions are its Regional Data (a region and a comment). A taxon with no region has no row. All 25 columns are in the sheet's order, the first pinned; the Filter menu offers the Yes or No columns and who created or edited the record, none of which the parameters cover.

  **Shared structure.** The Taxonomy Report is now a shell (`taxonomy-report.tsx`) over one file for each tab (`taxonomy-list-detail-tab.tsx`, `taxonomy-sa-regions-tab.tsx`) and the parameter fields they share (`taxonomy-report-parts.tsx`). Each tab is a hook returning its report props and its parameter fields; the shell holds every tab's state and renders one `DataReport` per branch, so the report and the tab list stay on screen across tabs and keep keyboard focus, as in the Events, Occurrences and Observations Report. The next sheets are an entry in `TABS` and a tab file. The first tab's behaviour is unchanged. `taxonomy-report-data.ts` exports `has`, `inDateRange`, `isoDay`, `joined` and `dateRangeText` for the second tab.

  **Departures from the sheet, on purpose** (the tab file's header lists them): sentence case; "Estab" spelled out ("Established in Reg?"), "Cons Stat." is "Conservation status", "Colln < 50yrs" is "Collection < 50 yrs", "Coll. No" is "Collection no", "Herb Voucher Initials" is "Herb voucher initials"; "Reg" is kept as the sheet has it (it names the region in "Native in Reg?" and, as far as the app says, the record in "Reg Created By"); "Dsn certain?" is kept as the app has it. The Date parameter reads the region record's own days, its Reg creation date and Reg edit date.

  **Sample data added, shared with Taxonomy Management.** The seed taxa held no SA Regions rows, so the tab would only ever have shown an empty state. `tx-data.ts` now gives the two Flora taxa placeholder rows (`SAMPLE_REGIONS`: Eucalyptus leucoxylon in the Southern Lofty, Kangaroo Island and Murray regions; Xanthorrhoea semiplana in the Southern Lofty and Kangaroo Island), from the State Herbarium's region list already in the file. They hold only what is safe to hold as placeholder (CONTRACTS 0.3): the region, Yes for native, established, ID certain and Dsn certain, the placeholder people (Olivia Wyatt, Phoenix Baker, Lana Steiner) and the placeholder dates already used for those taxa. The Herbarium number, voucher, census, BS and conservation fields and the free text are empty, because no identifier is invented and their lists have not arrived. Which regions a species is in is a placeholder, not botany; the designer's own data replaces it. The taxon's own SA Regions tab shows the same rows. The taxonomy store (`tx-store.ts`) went from version 1 to 2 with a `migrate`: a browser that already holds taxa keeps every edit and gains the rows only where a Flora seed taxon has no SA Regions table of its own yet; checked with a stored version 1 taxon carrying an edit. This touches two files the mohan-wips branch owns (additive: a function, a map and a store version); a merge of that branch back would meet them, and the store version is the line to watch.
