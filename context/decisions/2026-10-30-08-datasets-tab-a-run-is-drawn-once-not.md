# 2026-10-30 - Datasets tab: a run is drawn once, not again in a card above the table

- **Oct 30 2026: the Datasets tab no longer has an "Uploading now" / "Latest upload" card above its table.** The designer, with a screenshot of a project mid-upload (the header chip "Uploading files, 69%" open, and the tab behind it): "here's my problem with the design of the datasets tab. Why double up on the same info?" The screenshot shows it: the chip's popover and the card beneath it drew the same run, the same progress bar, the same three stages and the same nine custom concepts, and the upload's row sat in the table below the card as well.
  - **Why it was doubled (my miss, 0.7).** Nothing was designed twice on purpose. The card came with the old Datasets page ("the same progress, stages and problems as the project card's upload chip", its header comment said so), and when I made the page a tab (`2026-10-30-03`) I kept it. The chip is the designer's own earlier choice (a chip in the card's actions, opening the detail). The same `IngestionDetail` was then drawn in three places: the chip's popover, the tab's card, and the dataset's own Validation tab.
  - **Principles at stake (0.10, CONTRACTS 4.3):** 1 Say less (never restate a fact in two treatments on one screen), 3 One system (a list page is the list: search, then table, as the Artefacts tab and every collection). They agree.
  - **What changed.** The card, its "View dataset" link and the helper that chose it (`currentUpload`) are gone from `datasets-view.tsx`. The tab is the intro line, the search and the table; the dataset that is running is its row, with its status (and "In progress" under Records added), and the row opens its page. A run is now drawn in two places, for two different jobs: the **chip in the header**, which is there on every tab while a run goes on and stays, with its problems and its next step, until the next upload when one did not go in ("Not ingested", "Partly added"); and the **dataset's own Validation tab**, its permanent record. Neither was touched.
  - **Where a run that needs attention is now found.** On the chip (it stays, red, until the next upload), on the row's status in the tab ("Validation failed"), and on the dataset's page, whose card carries the next step ("Upload a corrected file", "Try again", `2026-10-30-04`). The tab's card used to be the fourth.
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the file and `npm run check:contracts` pass. Live (Playwright, zero console errors): a project made through Add Project option 2 with a real file (the Heathfield Ramble workbook), opened on its Datasets tab while the run goes on: the tab has no card, its one row reads "Pre-flight validation in progress", and with the chip's popover open "Checking against the data model" is on the page once (it was twice); with the run set to fail (the bar's "Upload result") the tab's row reads "Validation failed", the chip reads "Not ingested", and the row opens a page with "Upload a corrected file".
  - **Not checked.** The finished "Partly added" state to the end (the run was still going when the check ended); touch and narrow windows.
  - **Not changed, and open for the designer (0.4).** (1) **Two words for one status.** The chip says "Not ingested" where the tab's row and the dataset's page say "Validation failed" (the dataset page's Validation card already drops its own second vocabulary, `2026-10-30-04`). Should the chip use the dataset's status word? (2) **The chip's popover and the Validation tab still draw the same run**, one live and one a record. If one of them should go too, the chip (which shows the run while you stay on any tab) or the Validation tab (the record that stays after the chip has gone), that is a call for you. (3) The chip's list of custom concepts runs to 86 rows for a real workbook (the Heathfield file) and scrolls inside the popover; a count with a link to the dataset's page would say less.
