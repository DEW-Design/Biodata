# 2026-09-30 - Empty tables get a real empty state

- **Sept 30 2026: Empty tables get a real empty state.** The designer spotted that the Data Ingestion Report, with two filters that match nothing, showed one line of grey text under the chips. The design system has no empty-state component; the DLA and DSA status views already drew one (gray modern FeaturedIcon, heading, balanced line, action). That shape is now one shared `ListEmptyState` (`app/pages/_shared/list-empty-state.tsx`), used by the Data Ingestion Report (two cases: "No uploads yet" with no action because no next step is named, and "No uploads match" with "Show all uploads", which clears search and filters), and, by sibling grep, by the Projects list, the DLA and DSA lists (all-requests and status views), the Nominations list and the project artefacts table, each with an action named by its outcome ("Show all projects", "Show all requests" and so on). The action is not called "Clear search" because that is the accessible name of the search box's own X. New clause CONTRACTS 4.2e. Verified: tsc, eslint on the touched files, and a live Playwright pass (search and filters to nothing, then the action) on the report, Projects, DLA, DSA, Nominations and the artefacts tab, zero console errors; heading measured 18px, 600, Barlow, description 14px, `text-wrap: balance`. Not verified live: the status-scoped DLA and DSA views (only the collection-sidebar lab renders them; type-checked). Open: DLA and DSA still carry their own `DlaEmptyState` and `DsaEmptyState` for the "no requests in this status" case, which duplicate `ListEmptyState`; moving them over is a small follow-up. User Management's list has its own `empty` slot and was not touched. Not committed.
