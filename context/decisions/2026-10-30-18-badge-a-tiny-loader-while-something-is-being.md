# 2026-10-30 - Badge: a tiny loader while something is being processed

- **Oct 30 2026: a badge that names something still being processed leads with a tiny loader.** The designer, with a screenshot of the "PROCESSING (POST-FLIGHT)" pill, and the package they had just installed: "if something's being processed, let's have a tiny loader. I just installed the loader package. `<Classic duration={1580} size={...the one for the little pill} />` ... size= 12px?" Yes: 12px is the size of every icon in a small badge (`size-3`), so the loader fills the slot an icon would.
  - **Principles at stake (0.10):** 5 Make it obvious (a status that is still changing looks different from one that has settled), 3 One system (one behaviour in the badge, not a spinner drawn at each screen, 1.10), 8 Reach everyone (the loader stops with reduced motion, and the text still says what is going on). They agree.
  - **What changed.**
    1. **`Badge` takes an opt-in `isLoading`** (`components/base/badges/badges.tsx`; `loading-dev` is in `package.json`). It draws the badge as the icon badge, with the `Classic` loader (12px, 1.58s a turn, as given) in the icon slot, in the badge's own icon colour. Every badge without `isLoading` is unchanged (1.6). The Badge doc page has the prop in its API table and a "Loading" example.
    2. **Where it is on.** A new `isProcessingStatus` (`dataset-data.ts`: pre-flight validation requested, pre-flight validation in progress, processing) says which dataset statuses are going on right now, as opposed to waiting for a person (under review, submitted) or finished. The badge shows the loader for those: the Datasets tab's rows and a dataset's page, and the upload chip's popover ("Ingesting" while the run goes on, and its "Dataset status" line). In the Data Ingestion Report and the Post Ingestion Report, "Processing" (validation and dataset processing) has it; "Queued" does not. The audit feed does not: a line there says what a dataset moved to, which is over.
    3. **The Datasets table's Status column is wider** (29% of a 1200px minimum, was 16% of 1000px). The longest status, "Pre-flight validation in progress", with the loader is 243px and the old column was not wide enough for it at any window, which was already so at 1440px and with the loader would have made the table scroll sideways at 1716px. The other columns gave up the room (Dataset 12, File 24, Uploaded by 13, Uploaded 11, Records added 11) and none is cut at 1440 or 1716px.
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` pass. Live (Playwright, zero console errors): on the Badge page the three examples are 12 x 12px, run `ld-classic-fade` at 1.58s and take the badge's colour (warning, brand, gray); with the reduced-motion setting there is no animation; a project made through Add Project 2 with a file shows the loader on its row's status ("Pre-flight validation in progress", 12 x 12, the warning colour) and on the dataset page's card, and on both badges in the chip's popover; when the run ends the card's badge reads "Under review" and has no loader; the Data Ingestion Report shows the loader on its two "Processing" rows and on no other badge (45 successful, 23 approved and the rest are plain).
  - **Not checked.** The Post Ingestion Report's "Processing" rows (the same line as the Data Ingestion Report's, not opened); a screen reader (the loader is `aria-hidden`; the label says what is happening); touch.
  - **Open, for the designer (0.4).** (1) The chip's popover has two badges that both say the run is going on ("Ingesting" and the dataset's "Pre-flight validation in progress"), so it now shows two loaders at once. Keep both, or only the run's own? (2) Other "in progress" words are not badges and were not touched: "In progress" under Records added, the chip's own spinner (counterclockwise, `2026-10-30-09`), the progress bar and its stages. (3) The loader is `Classic` as asked; the package has many others (Arc, Ring, Pulse, Comet ...), if a different one reads better at 12px.
