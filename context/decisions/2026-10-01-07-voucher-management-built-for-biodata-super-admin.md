# 2026-10-01 - Voucher Management built for BioData Super Admin

- **Oct 1 2026: Voucher Management built for BioData Super Admin.** The designer: a scan runs on a set interval comparing herbarium (and SA Museum) records with current BioData records; thousands are checked, a few differ, and the admin decides to accept or ignore each. Figma "Biodata Wireframe Presentation" node 1584:10220 taken for reference only (content and flow), with headings and copy written fresh.
  - **Access:** new feature key `voucherManagement`, in `SUPER_ADMIN_ONLY` (a BioData Admin does not get it). Rail section "Voucher Management" after Controlled Vocabulary in `biodataSuperAdminNav`, icon `SwitchHorizontal01` (the Figma draws none). Route gated in `wholePageGates`. `ref-roles.md` and the tools bar's role description updated.
  - **Routes:** `/pages/vouchers` (scan batches), `/pages/vouchers/<batch>` (a batch), `/pages/vouchers/<batch>?record=<id>` (one record's comparison; a query, not a route, so the static export needs one page per batch, not per record). Code in `app/pages/_shared/vouchers/` (data, store, shell, list, batch, record, parts, routes). Three rows in the `/pages` index.
  - **List:** Scan batches with status tabs and counts (All, Needs review, Reviewed, No differences) in place of the Figma's stat cards, which repeated the tab counts (4.3). Columns: Batch (with "n records to review"), Ran on, Sources, Records checked, Differences (with "n missing in BioData"), Decided ("2 updated, 1 ignored"), Status. Nine columns did not fit at 1512px, so the Figma's Mismatched/Null and Updated/Ignored pairs became one cell each. Column 2 lists every batch with its records-to-review count, so an admin moves between batches while reviewing.
  - **Batch:** project-page layout (4.6). Tabs: To review, Ignored, Updated, All records. The Figma's "Herbarium" dropdown before the search is the source picker, scoping every tab and saying how many records each source still has to review; its "View only" checkboxes became the Field filter. Review table: one row per record, one line per differing field: source value, BioData now (the differing part in the error colour, a missing value a "Missing" badge), and Update BioData to (the source's value unless changed). Each line has Edit (dialog: a searchable BioData taxon for a name, a Rego ID, or a person and a calendar date) and Ignore (undo on the toast). "Show matching fields" reveals the rest. Select records, then Ignore, or Review and push: the Figma's confirmation, each old value struck through then the new one.
  - **Decided without the designer, to confirm:** an ignored difference carries into later scans while neither value changes, shown as "Ignored in batch 1011 by ..." (from the Figma's "last ignored in batch 1004" note), and can be reviewed again. A scientific name is pushed only as a BioData taxon: when the source's name has none (a new subspecies), the field asks for one to be chosen and push leaves it out, saying so. Observed by and date is updatable like the other three, though the Figma draws no "Your update" for it. Labels shortened in the review table only: "Identified / determined by" reads "Determined by".
  - **Sample data:** species are the NSX list; source-only names are real taxa with no BioData taxon; people are the placeholder people; IDs follow the wireframe's shapes. Matched records are generated deterministically so All records shows the whole scan. No scan interval is shown anywhere, since none is known.
