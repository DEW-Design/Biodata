# 2026-10-22 - post-6-oct: the project header's toggle no longer moves, the facts sit in the title's row

- **Oct 22 2026: post-6-oct: the project header's toggle no longer moves, the facts sit in the title's row.** The designer, on the header built in `2026-10-22-03-*`: "the chevron next to the name of the project has dancing layouts", and "anyway to optimise the project header info? Like have metadata sitting horizontally than stacked", with a screenshot of the closed header whose empty right-hand side is boxed and labelled "metadata?". Run through the `refine-prompt` skill: the dance is a layout shift (an element moving under the pointer that just pressed it), the metadata move is a flex row with a gap, wrapping where the content stops fitting rather than at a set width.

  **The cause, measured before the change (1440, 1280 and 1024 alike).** On every toggle the chevron moved 79px sideways (the status badge was drawn before it only while the header was closed) and 20px down (the "PROJECT" eyebrow was drawn only while it was open); the title moved 20px and the tabs 76px.

  **What changed (lab only, CONTRACTS 5.4), `ProjectHeader` in `app/proto/post-6-oct/project-workspace.tsx`.**
  - Nothing at the left of the toggle, or above it, appears or disappears: the eyebrow is always drawn, the title and toggle come first, and the status badge follows the toggle while closed (open, the status is among the facts, so it is not said twice, CONTRACTS 4.3). The title's line is 40px tall, the height of a fact (16px label, 4px gap, 20px value), so the title stays centred in it either way.
  - The five facts are in the title's row at the right, label over value as the production hero draws them, 32px apart, instead of in a row under the title. They wrap under the title only when the row has no room.
  - **Default:** open on every tab. Where the facts fit in the row they cost no height, so hiding them by default (the choice in `2026-10-22-03-*`: open on the Overview only) bought nothing. That default is superseded by this entry; the toggle and its per-tab memory are as they were.

  **Measured after.** Chevron and title move 0px, both ways, on Project records and the Overview at 1440, 1280 and 1024. The tabs also move 0 wherever the facts fit (Project records at 1280 and wider). Where they wrap (the Overview beside its "On this page", which leaves 840px; Project records at 1024), closing gives 56px back (the title's 40px line and a 16px gap). Project records at 1440 with every fact shown: the explorer's search starts at 338px, against 386px before the first change and 310px with the facts hidden.

  **Decided (by me, flagged for the designer):** "stacked" is read as the facts being under the title, so each fact keeps its production label over value (the production wording and treatment, 1:1); the eyebrow stays in both states rather than being dropped when closed (it is production's own word, and removing it would move the title); the default is open everywhere.

  **Open.** (1) The Overview wraps the facts under the title, because its "On this page" column narrows the content to 840px; the title with the five facts needs about 925px. To keep them in the row there, the facts would need to be tighter (an inline "label: value" per fact, about half the width) or the "On this page" column would have to give way; the first changes the production fact treatment and is not built. (2) Whether the closed state should keep only the status, as now, or also the Project ID. (3) The eyebrow costs 20px in both states; it could go if the designer drops the production word.
