# 2026-10-25 - No dot between pieces of text: contract 2.3c, ratcheted, the conversion waits on the replacement

- **Oct 25 2026: The middle dot is never used to separate pieces of text (CONTRACTS 2.3, new bullet and `AUTO §2.3c`).** The designer, of the species card's "1 record · Individual": "let's add another contract, let's never add the dot to separate text. Let's please tweak this across the webapp."
  - **Where it went:** a bullet under 2.3 "Copy and punctuation", beside the em-dash and arrow rules, not a new number: it is the same kind of rule (a character that is not used in copy) and 0.9 says to reuse the place the repo already has. The clause names the middle dot (`·`, U+00B7, `&middot;`) and says what is not covered: a bullet that masks a password (`dsa-form.tsx`, `dsa-detail.tsx`) or an overflow glyph (`results-table.tsx`) is not a separator.
  - **The check, `AUTO §2.3c`, ratcheted like the em-dash rule:** a line of code that is not a comment and holds the character, its `·` escape in a string, or `&middot;`. The uses there are today are recorded in `contracts/baseline.json` (only that rule's entries were added; no other count and not the component inventory changed) and may not grow; each conversion lowers the count and is locked in with `--update-baseline`. Shown to fail on every file before the baseline was recorded. Recording a baseline for a new rule is the audited act the contracts describe (9.4); it adds debt that already existed, it does not raise a count.
  - **What is on the books:** **130 lines in 53 product files** and **27 lines in 18 docs pages** (labs under `app/proto` are outside the scan, 5.4). By kind (the lines, not a formula):
    1. **An identifier before a name:** a project or dataset in a dropdown ("BD-5137 · Flinders Ranges Reptile Atlas"), a record in a tree ("Occurrence OCC00501 · Individual"), "Observation OBS094 · Individual", a record and its name in the review view, the species picker and the vocabulary code lists.
    2. **Two attributes of one thing:** "1 record · Individual", "Phalangeridae · Mammal" (family and group, on three screens), "author · date", "organisation · project" (Explore, the peek card, the global search), "{title} · {n} of {total}" in the walkthrough.
    3. **An eyebrow or a kicker:** "Add · {kind}", "Edit · {card}", "Voucher record · {source}", "Notification · {category}".
    4. **A status with its reason or a suffix:** "Not added · something went wrong on our side", "· Unsaved changes" (three screens), "Columns · 2 hidden", "Question 2 of 9" after a title.
    5. **A coded value and its meaning, in sample data:** "3 · Within 1 km", "GDA94 · Geocentric Datum of Australia 1994", "1 · 1 to 10%".
    6. **A list joined with `" · "`:** `.join(" · ")` in the vocabulary, the voucher list, the logo requirements, the review section.
  - **Not converted, on purpose:** what goes in its place is a copy decision on about 150 strings, several of which would read badly if one rule were applied to all (a count with a list of types, "2 records · Population, Individual", becomes "2 records, Population, Individual" if only the dot is swapped, which reads as three things). The agent did not decide it (0.4). The clause says only what it is sure of, that the dot goes, and says the replacement is decided by the kind of text. **Proposed, to confirm:**
    - **Attributes of one thing, a comma:** "1 record, Individual", "Phalangeridae, Mammal", "Adelaide Hills Landcare, Adelaide Hills Bushland Survey". Where the second part is itself a list, a colon: "2 records: Population, Individual".
    - **An identifier before its name, a hyphen** (the contracts already use the hyphen where a dash was wanted, 2.3): "BD-5137 - Flinders Ranges Reptile Atlas". Where there is room the code and the name are two elements (the code in the secondary colour).
    - **An eyebrow, the words:** "Add {kind}", "Edit {card}", "Voucher record, {source}": words, not a dot.
    - **A trailing status, a comma or its own element:** "Not added, something went wrong on our side"; "Unsaved changes" as its own tag where the title has room.
    - **A coded value:** the same as an identifier and its name, a hyphen.
  - **Checked:** `npm run contracts:rules` (the 2.3 text is in `contracts-build.md`), `npm run check:contracts` clean with the recorded baseline, the rule shown to fail without it. No application code changed, so no browser pass.
  - **Open, for the designer:** the replacement above (one answer converts the 130 product lines and the 27 docs lines, and the baseline goes to zero); and whether the docs pages' example strings, which show the product's own strings, follow the product.
