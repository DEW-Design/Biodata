# 2026-11-02 - Unstructured data uploads: one upload component, no pre-flight, post-flight validation on Fluree

- **Nov 2 2026: A dataset is structured or unstructured; unstructured data skips pre-flight validation.** The designer: unstructured data uploads share the same upload component; PDFs, images of all types (JPG, PNG, GIF, RAW), Word, audio and video; 10 MB each; they skip pre-flight validation and go straight to post-flight validation on Fluree ("a SaaS tool with all the smarts"). Built: `UploadDropzone` and `useFileQueue` take a `kind` (`structured` default, `unstructured`), which sets what the picker offers, the line under "Click to upload", and a size limit (`fileRulesFor`, `dataset-data.ts`); a file of the wrong type and a file over 10 MB are turned away with their own reason. The upload form's first section has a "Type of data" choice (radio, disabled once files are in the queue, so no file is dropped silently); choosing unstructured changes the instructions, hides the recommended templates, and there are no custom concepts (no workbook headings are read). A dataset carries `kind` (absent means structured). The run (`ingestion.ts`) has one stage for unstructured data, "Post-flight validation on Fluree" (the designer's words); `datasetStatusFor` moves it File uploaded, Processing (post-flight), Under review, and a failed run is Validation failed. `subjectOf(dataset)` now builds the run's subject in one place (the Datasets tab, the chip, the Data Ingestion Report and two labs each built it by hand). The Datasets page shows "Files added" for unstructured data and no Rows row or "Open project records" link. Verified in a browser as BioData Admin: kind choice, accepted and rejected files with their messages, the type radios disabling, rail and templates, creating the dataset, the Datasets tab showing Processing (post-flight) straight away, the chip's single stage, no console errors. Not committed.
- **Assumed, for the designer to confirm (0.3):** the extension list (PDF; JPG, JPEG, PNG, GIF; RAW as .raw, .dng, .cr2, .nef, .arw; Word as .doc and .docx; audio as .mp3, .wav, .m4a; video as .mp4, .mov), because the brief named groups and not extensions. A 10 MB limit rules out most camera RAW files and nearly all video. The acknowledgement (licence, classification, First Nations, privacy) is asked for unstructured data as for structured, and the same upload form and Upload menu entry are used.
- **Open:** what Fluree actually checks and reports, so a failed run says only that validation could not be finished (a fault to try again), with no invented findings; where an unstructured file lives once it passes (Artefacts and attachments, or its own place) and so what "Open project records" should do for it; the Data Ingestion Report is headed "Pre-Flight Validation" and its "Overall dataset" column counts rows, which for unstructured data is the number of files; the Datasets list column is "Records added" and counts files for unstructured data; the project-creation dataset step (option 2) still adds structured data only; whether the 10 MB limit also applies to spreadsheets (it does not today).
