# 2026-10-01 - Add area stays primary

- **Oct 1 2026: Add area stays primary.** The designer asked why Explore's "Add area" button turned from primary to secondary once an area was added, and whether there was a UX reason. There was no recorded decision: it was in the first build of the card with no comment. The usual reason (the main action follows the next likely step, so it is demoted once the setup is done) did not hold here: nothing else in the card becomes primary, so the card had none, and the product's other create actions (the DLA, DSA and nominations lists) keep "New ..." primary whether or not there are rows. It is now `color="primary"` in every state. Verified live as Registered User: the computed background is rgb(24, 94, 116) with white text with an empty card, with one area, and with every area hidden. Sibling grep for a button whose colour changes with state: the drawing-tool toggles (primary while a tool is active, in three places) are a selected-state indicator, and the export button changes with the layout variant, not with state, so neither is the same problem. The designer also asked that screens are checked against scenarios like this before they are built: `ref-shell.md` now has the rule ("a control keeps its treatment across states": list the states, ask for every control whether its emphasis, place or wording changes and why, and check how sibling screens treat the same control). Not committed.
