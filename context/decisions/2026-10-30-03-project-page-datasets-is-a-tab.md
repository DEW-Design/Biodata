# 2026-10-30 - Project page: Datasets is a tab

- **Oct 30 2026: the project page has a Datasets tab, a list of every dataset uploaded to the project.** The designer: "On the project detail, can we bring in dataset as a tab? A list of all the associated datasets?" Until now the list was a card behind the header's Upload menu and a `?view=datasets` screen that replaced the page.
  - **Principles at stake (0.10):** 3 One system (the other things a project holds, its records, species and artefacts, are a tab each: 4.6 item 7), 6 Reveal in steps (a count on the tab says how many, the list is a click away), 5 Make it obvious (the dataset page's trail says where you came from and Back goes to the tab). They agree.
  - **What changed.**
    1. **The tab.** "Datasets" with the `UploadCloud02` icon (the Uploads and Datasets icon in 3.13; `Database01` is already Project records) and a count badge, placed after Species and before Artefacts and attachments. Tabs now read Overview, Project records, Species, Datasets, Artefacts and attachments, Project access.
    2. **What it holds.** The list that was the Datasets screen, moved in as it was: the intro line, the upload being checked now (with its progress), a search, and a table with the dataset ID first (4.2i), the file, who uploaded it, when, the records it added and its status. A dataset is a row that opens its own page; the empty states are `ListEmptyState` ("No datasets yet" and "No datasets match", with "Show all datasets" to undo a search, 4.2e).
    3. **Who sees it.** The roles that could see the old Datasets card (`datasetUpload`: Registered User, Privileged User and Admin, BioData User, and the two admins). The public user has no Datasets tab, as before.
    4. **The dataset page.** Still `?view=datasets&dataset=<id>`, with its Validation, Details and Audit Log tabs. Its trail is Projects, the project, Datasets, then the dataset's ID; "Datasets" opens the tab, and Back returns to the tab, not to a screen of its own. The Flagged concepts review links and the production-routes map point at `?tab=datasets`.
    5. **The old address keeps working.** `?view=datasets` with no dataset opens the project on the Datasets tab, so a saved link or an earlier decision's URL still lands somewhere right. `?tab=<tab>` opens any tab by address; an unknown name opens Overview.
    6. **No Upload button in the tab.** Upload is already in the header's Upload menu on every tab (one control per action, 3.12); a second one in the tab would repeat it.
  - **Removed.** `DatasetsList`, `DatasetsScreen` and `DatasetsCard` from `datasets-view.tsx`, with the helpers only they used; `DatasetsTab` and `DatasetScreen` replace them. CONTRACTS 3.13's icon list reads "Uploads and Datasets `UploadCloud02`"; the scoped rule files were regenerated.
  - **Not done, on purpose.** The labs `/proto/project-access` and the post-6-oct mirror list their own tabs and were not changed; labs do not ship (5.4).
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` pass. Live (Playwright, zero console errors) on Adelaide Hills: the tabs read as above with Datasets 3; the table lists the three datasets with the ID first; a search narrows it and an unmatched one shows "No datasets match" with "Show all datasets"; a row opens the dataset page with the trail Projects, the project, Datasets, ID and its three tabs; Back returns to `?tab=datasets` with the tab selected; `?view=datasets` and `?tab=datasets` both open the tab; a public user has no tab; a project with no datasets shows "Datasets 0" and "No datasets yet"; `?tab=species` opens Species, an unknown tab name opens Overview, and the Flagged concepts review (`?view=review`) still opens.
  - **Not checked.** Touch and the narrow layout; the tab with an upload in progress on a project other than the first (the current-upload card was read from the code); the deployed static export (the Pages build check on the pull request is that check).
  - **Open, for the designer (0.4).** (1) The tab uses the old card's gate (`datasetUpload`), so the roles that can upload and the two admins see it and no one else does; should the Public User see a read-only list of a public project's datasets? It does not today. (2) The tab count is the project's datasets in any status, failed ones included; should a failed or pending dataset count? (3) Should a project's Datasets list ever offer an Upload button of its own, for a project with none, in the empty state?
