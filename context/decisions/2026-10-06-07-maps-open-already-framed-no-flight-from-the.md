# 2026-10-06 - Maps open already framed: no flight from the state view

- **Oct 6 2026: a rendering glitch when the project page's map is expanded: the circle was drawn only partly (shaded and outlined up to straight edges, the rest of the map plain) and the tiles filled in late. From the designer's screenshot: "performance glitch, please look into this".**
  - **Cause (measured while the dialog opened, 1708x1024):** every `SAMap` mounts at the state-wide zoom and then `FlyToBoundaries` flew it to the project's area over 0.6s. During that flight Leaflet scales the drawn shapes with the zoom, and the circle's overlay (`svg.leaflet-zoom-animated`) was 8,933 x 5,048 px in the first frame and 84,340 x 47,661 px in the next, while the dialog was also fading in over a blurred backdrop. The browser rasterises an SVG that size in pieces, so a screenshot or a slow machine catches it half drawn. The earlier `ResizeSync` fix (a circle cut off along a straight edge) covered a different cause, the container changing size, and is untouched.
  - **Fix, once, in the shared map (1.3):** the first fit of a map is now a jump (`fitBounds` with `animate: false`) and only later fits fly (`flyToBounds`, as before), in `FlyToBoundaries` (`app/pages/_shared/map-search/sa-map.tsx`). A map that mounts with areas opens already framed; a map whose areas change while it is open (Explore's search areas, a location added in the DLA form) still flies. Measured after: the overlay is 1,911 x 1,080 px in the first frame and 1,920 x 1,085 from then on, the whole circle is drawn from the first frame, and the tile count is 28 against 69 (the map no longer requests tiles for every zoom level on the way in).
  - **Verified live (Playwright, 1708x1024, BioData Admin):** the expanded map on `/pages/project-detail` in eight frames over 2.2s, the full circle in each; the inline project map (overlay 757 x 479 in a 631 x 399 box, normal), Explore's map (loads, no overlay until a search) with zero console errors. `tsc`, eslint and `check:contracts` pass.
  - **Not done:** the DLA record and Nominations pages have no map on their landing view, so their maps (the DLA "Add a location" takeover, a nomination's areas) were not opened; they share the same fit, so the same change applies, but they were not looked at. A throttled-CPU run to reproduce the glitch as the designer saw it was not done: the cause is measured, not reproduced.
  - **Open:** this is the first fix of this kind (0.8), so no `AUTO` check. The dialog still fades in over a 6px backdrop blur (`modal.tsx`); with the map no longer flying it has little to rasterise, but if a blur-related stutter is still seen on a slow machine, mounting the expanded map after the dialog's entrance would be the next step.
