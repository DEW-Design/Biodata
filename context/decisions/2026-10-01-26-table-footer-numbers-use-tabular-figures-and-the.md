# 2026-10-01 - Table footer numbers use tabular figures and the footer stops moving

- **Oct 1 2026: the numbered pagination footer of every table (`TableCard.PaginationNumbered`, `components/application/table/table.tsx`) no longer shifts as its numbers change. From the designer's page feedback on `/pages/project-list`: "Dancing layouts caught here. I think it's the numbers that are playing up. Can you enable the monospace mode for the barlow font?"**
  - **What "monospace mode" is here:** Barlow's own tabular figures (`font-variant-numeric: tabular-nums`, Tailwind `tabular-nums`), not a monospace typeface: every digit takes the same width and the letters are unchanged. Measured in the browser: three-digit strings are 22.4px for 0, 1, 4 and 8 with tabular figures, against 14.9px (1) to 24px (4) with Barlow's default proportional ones. Typography rule: fixed-width digits on anything that updates (`/emil-typography`; CONTRACTS 2.9 asks the same of changing figures).
  - **Two causes, both fixed in the component, once (1.9, 1.3):** (1) the figures were proportional, so "1 - 4 of 4" changed width with the digits; (2) the page numbers sat between two flexible spacers whose neighbours had different widths (the fixed "Rows per page" control on the left, the variable range text on the right), so the group slid sideways whenever the range text changed, and Next moved with it. The footer is now three columns (`grid-cols-[1fr_auto_1fr]`): rows per page and Previous, the page numbers, Next and the range. The page numbers are centred whatever the sides hold, the range has a minimum width (`min-w-32`, right-aligned) so Next stays put as it grows from "1 - 4 of 4" to "51 - 100 of 1,234", and the rows-per-page select has a fixed width (`w-14`). `tabular-nums` is on the range, the page-number buttons, the select and the simple "Page X of Y" footer too. Visually the footer is the same: Previous still sits beside the rows-per-page control, Next beside the range.
  - **Sibling sweep:** count badges (`CountBadge`) and the metric tiles already had tabular figures; the tab badge (`Tab`, `components/application/tabs/tabs.tsx`), a count that changes as filters change, did not and now does. Other tables' numeric cells in the reports already use it.
  - **Measured live at 1708x1024** (Playwright, BioData Admin): the page numbers' centre, Next's left edge, the range's right edge and the select's width are identical across the Projects list in both scopes (2 and 4 rows) and a 60-row table at 10, 50 and 100 rows per page and on page 1 and page 6: centre 1029, Next at 1435, range right edge at 1660, select 56px, and `tabular-nums` computed on the range and the select. Zero console errors. Documented on the Table page (`/components/table`).
  - **Not done:** a keyboard-only pass of the footer (its behaviour is unchanged), narrow widths (the footer was already a single row at every width), and a check on every screen that uses the footer beyond the Projects list and the reports.
  - **Open:** this is the first fix of this kind (0.8), so there is no `AUTO` check for a changing number without tabular figures; one is due if it recurs.
