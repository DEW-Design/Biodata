# 2026-10-29 - Consolidated report: a new report from the designer's sheet

- **Oct 29 2026: the Consolidated report is added to the Reports page, at `/pages/reports/consolidated`.** The designer: "we need a new report: report name: Consolidated report", with three screenshots of the sheet: its metadata (ten lines), its filters ("Add Filters": Project Owner, Sites, Source Type, Species) and its columns ("Add Columns": Reliability, Sites, Visits, Species), and the column list.
  - **Job and principles (0.10).** A signed-in person who reports on projects wants every species sighting with when and where it was made and in which project, to search, narrow, add columns to and download. Principles: 3 One system (it is a sheet like the Flora Taxonomy Report's, so it is built the way those are, and sits in the same report pattern), 4 Tell the truth (a column the app has no value for stays empty, never guessed), 6 Reveal in steps (the sheet's extra columns start hidden). They agree.
  - **How the three screenshots became the report (CONTRACTS 4.6, 4.2d).**
    1. **The ten metadata lines** (NSX Code, Scientific Name, Common Name, Sighting Period, Visit Observers, Site ID / Site Property, Location, Site Type, Geographic Coordinates, Projected Coordinates) are not a form of their own: a line a person types is the table's search (which matches NSX code, scientific and common name, site, property, visit, sighting number, coordinates and location comments), a line chosen from a list (Visit Observers, Site Type) and the Sighting Period are attributes of the one Filter menu (the Sighting Period is a date range on the visit's day, with presets and a custom range), and Export CSV and Export XLSX write the title and all ten lines above the columns, from the search and the filters in view. It reuses `useSheetTab` (`taxonomy-sheet-tab.tsx`), which the taxonomy sheets use.
    2. **"Add Filters"**: Project Owner, Sites and Species are Filter attributes (Sites and Species are searchable lists, bounded to 50 a time), and so is Project. **Source Type is not offered**: no record in the app has a source type, and a filter on a value the data does not have filters nothing (4.2d).
    3. **The columns**: the 30 of the sheet's list in its order, then the four it offers under "Add Columns" (Project owner email, Land form pattern, Bare earth estimate, Tissue and description), which are in the Columns chooser and **start hidden** ("Columns, 4 hidden"). Every column is exported, hidden or not (34 in the file). **It has no Parameters button.** It first had one (the project scope, copied from the Species Detail Report), and the designer asked: "We ditched parameters didn't we?" For a sheet they are gone: a sheet's inputs are its search and its Filter (`report-parameters.tsx`, 15 Oct 2026: "parameters are doubling up"), as on the taxonomy sheets. The project is one more Filter attribute, and a generated report (`?project=`) opens with that project's chip already on, which a person can remove (`DataReport` takes `initialFilters`, opt-in). Parameters are still on the Species Detail Report, the Events, Occurrences and Observations Report and the Data Validation Error Report (inline), which are not sheets; whether they should go too is the designer's call.
  - **What is filled and what is empty.** Read from the project page's own records, so the report and the record page cannot disagree: the sighting's species and codes, its visit (sequence number, ID, date, observers), the site (property, altitude, paddock, grouping, coordinates, location method, datum, reliability, comments), the project and its owner. Empty because the app holds no such value: **Zone, Easting, Northing, Site type, Generated location, Photos and Tissue and description**. Visit columns are empty for a sighting made straight at a site with no visit under it (most of the Adelaide Hills seed). The NSX code is empty for a species the NSX list does not hold (never made up).
  - **Readings I chose, for the designer to correct (0.4).** "Accuracy/Reliability" is the sighting's Date accuracy (the nearest field the app has); "Camp/Group" is the site's grouping (the BDBSA crosswalk maps Site Name to CAMPNAME); "Method name" is the description of the Location method code ("GPS", "Hand-held GPS"); "Visit Date Time" holds the day only, because no visit has a time; "Common Name" is in the list twice and is here once.
  - **Location and record access.** A sighting a project restriction generalises (Level 2, shown only as a block) must not put a place in this report beside its site's exact position. On such a row the coordinates and the location method and comments are left empty. Live: a Registered User's report has two (Pygmy Bluetongue Lizard, Yellow-footed Rock-wallaby, Flinders Ranges Reptile Atlas) with those columns empty, and the BioData Admin's has all coordinates.
  - **Where it is.** The Reports landing's "Project data" group (card with the layered-sheets icon, `scoped`), the reports switcher in the breadcrumb, and the `/pages` index; every role that has Reports can open it, the rows being what the role may see. Files: `consolidated-report-data.ts` (rows), `consolidated-report.tsx` (columns, filters, hero), `app/pages/reports/consolidated/page.tsx`, one entry in `reports-data.ts`.
  - **A small opt-in added to the shared report (1.6).** `DataReport` and `useColumnChoice` take `hiddenColumns`, the columns that start hidden; every other report is unchanged (the Species Detail Report still reads "Columns"). It is described in `/patterns/report-toolbar`.
  - **Checked.** `npx tsc --noEmit`, `npx eslint` on the reports folder, the route, the index and the pattern page, and `npm run check:contracts`: clean. Live (Playwright, 1716 x 1030, zero console errors, this checkout's dev server on port 3100; port 3000 was another workspace's), as Registered User, BioData Admin, BioData Super Admin and Public User: the hero reads "Consolidated report" with Latest record (where the rows have one), Visits, Sites and Species; the 30 columns draw, "Columns, 4 hidden"; the Filter menu lists Sighting Period, Project Owner, Sites and Species and a species chosen leaves 2 of 23 rows; a search for "Osprey" leaves 1; the chooser shows the four extras off, turning two on draws them and "Columns, 2 hidden", Reset puts them back; Export CSV writes the title, the ten metadata lines, a blank row, then 34 headings; the Reports landing and the breadcrumb switcher list the report; `?project=adelaide-hills` opens with the Project chip on (the same 8 sightings as the report shows for that project unfiltered), Clear all brings back all 23, and a project the role cannot report on in the link is ignored; there is no Parameters button on the report and the Species Detail Report still has its; the Public User gets the Reports restriction.
  - **Not checked.** The XLSX file's contents (the CSV was read; both share one builder); touch and the narrow layout; a filter on Visit Observers and Site Type (they are in the Filter menu only when a row has a value, and no seeded visit has an observer or a site a type, so neither shows today); a screen reader on the new report.
  - **Open, for the designer (0.4).** (1) What is Source Type, and where does it come from? (2) Is the second "Common Name" a different field? (3) Are the readings above right, especially Accuracy/Reliability and Camp/Group? (4) Zone, Easting and Northing could be worked out from the latitude and longitude in the MGA zone; should they be? And what is "Generated location", and where are Photos kept? (5) The sheet lists Species, Sites and the typed species lines both as filters and as metadata: the 15 Oct rule says one control for one thing ("parameters are doubling up"). Is a Species filter wanted beside the search that already matches the codes and names? (6) "Add Columns" groups its columns (Reliability, Sites, Visits, Species); the Columns chooser is a flat, searchable list, so the groups are not shown. (7) Which roles should have it? Today every role that has Reports, like the Species Detail Report; the Voucher and sensitive reports are gated by `specimenReports`. (8) Found while checking, in every report and not caused by this one: `report-projects.ts` gives all projects to `biodata-admin` only, so a BioData Super Admin, who is meant to have everything an Admin has, reports on 11 sightings where the Admin reports on 23 (the Species Detail Report reads the same). That is a change to a persona's access, so it was not made here.
