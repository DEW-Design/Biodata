# 2026-10-01 - Notification Management built for BioData Admin and above

- **Oct 1 2026: Notification Management built for BioData Admin and above.** A new rail section, "Notification Management" (`Bell01`, unused anywhere else in the product), after Taxonomy Management in the admin tree, at `/pages/notifications`, from the Figma wireframe "Notification Manaement" (YMproGZfrFB5jUqPHPxMhk, node 1584:22382: the list, and Add Notification as Message, Templates, Settings, Sender & Recipients tabs). No BRD exists for it; the Figma is the only source. Code: `app/pages/_shared/notifications/` (data, store, shell, list, email preview, detail, form, routes) and thin route files under `app/pages/notifications/`.
  - **Decided by the designer:** BioData Admin and above (`notificationManagement: []`, not in `SUPER_ADMIN_ONLY`, a `wholePageGates` entry). The Figma is for reference only; build the best, simplest UX, consistent with the other features, with a creation flow like Controlled Vocabulary's three steps but optimised for speed and accuracy. Asked three questions and the designer chose: browsing is a **split view with a live preview** (over a table that opens a page); **the template owns the look** (no font, size or colour toolbar); **one direction**, no options.
  - **CONTRACTS 4.2 overridden for the list screen, by the designer's choice above (0.1):** a row selects and previews instead of being a link. Everything else in 4.2 holds (SectionHeader with count and create action, ToolbarSearch and Filter, TableCard with `bodyScrollable`, sticky header, pagination). Enter or a double click opens the notification's page, as does "View details". The selection is in the URL (`?selected=`), so Back from a notification lands on it again. Not a precedent for other lists.
  - **Re-fitted from the Figma (named in each file's header):** the Active / Drafts / Disabled tabs became the Status filter; the categories (all eight, with counts, empty ones included) are column 2's; "View Logs" became the History tab. The four tabs became three form sections: Trigger, Recipients, Message. Trigger Type (Event, Time, Condition) and Scheduling Type (Time, Workflow) overlapped, so they are one question: when something happens (with an optional "only when the status becomes", the Figma's condition) or on a schedule. Sender "Current User" is gone: an automated email is sent by BioData SA, with an editable sender name and optional reply-to. Retention Period was a start and end date; it is a duration. The Message section stacks its fields beside a live preview instead of using label-left FormRows (the same exception as Controlled Vocabulary's Entries grid).
  - **Speed and accuracy:** the trigger comes first because everything depends on it. Picking an event fills in the name (numbered when taken, so it is never invalid), the category and the subject, sets "the person it's about" as the default recipient, and limits the Insert variable menu to what that event provides. A second active notification on the same event to the same person is warned about as it is picked. A variable the trigger doesn't provide is marked red in the preview as it is typed and refused on Add. Duplicate (record "..." menu) starts a new notification from an existing one; "New notification" from a category starts in it.
  - **Record page (4.6):** RecordHero with Edit as the next step; Duplicate, Send me a test, Enable, Export history, then Disable (confirmed) or Delete draft below the divider. Tabs: Preview, Settings, History. An active notification is disabled, never deleted.
  - **Sample content:** names and descriptions are the Figma's, and "Observation submitted successfully" carries the Figma's email word for word. Every other message, the Maintenance template's description, NTF-008's description (the Figma's is a stray placeholder) and the variables not named in the Figma are written for this build and marked as such in `nt-data.ts`. Placeholder people only; the support address is DEW's real BDBSA one. "Send me a test" says it isn't wired up rather than pretending.
  - **Shared changes:** `notificationManagement` feature key, `NOTIFICATION_SECTION_LABEL` and nav key `notifications`, the icon map, the Add menu item "Notification", the `wholePageGates` entry, three rows in the `/pages` index.
  - **Fixed on the way:** the list card was widened to 496px so its pagination fits; a row's second line is the description (the Figma's list item), not the trigger, which repeated the name; "Details missing" lists problems in page order; the email body dropped an unsourced `leading-6`.
  - **Verified:** `tsc`, `eslint` on every touched file and `check:contracts` clean. Live Chrome pass as BioData Admin: list, category nav and counts, Up and Down moving the selection and the preview, Show variables, `?selected=` scrolling back to the row after a notification's page; record page tabs, Disable with its confirmation, notice, toast and history; a new notification through all three sections (empty Continue blocked with "Details missing", event pick filling name, category and subject, the duplicate warning, Insert variable at the cursor, a misspelt variable marked and refused, then added and selected on the list); the schedule branch; editing a live one (no Save draft, Save changes disabled until a change). Registered User gets the restriction in main with all three columns and no name in the breadcrumb; Super Admin sees the section. Zero console errors. The test data was cleared from the browser afterwards. Typography: every layer measured as Barlow and copied from a sibling (list name cell, RecordHero, RecordRow, the restricted-state heading); `/emil-typography` and `/emil-design-foundations` ran.
  - **Found, not fixed (outside this feature):** `Select` and `MultiSelect` draw no invalid border on their trigger, only a red hint, so a required pick left empty shows no inline mark on this form, DSA, DLA or Controlled Vocabulary (a 1.9 fix, once, in the components). In development, Agentation's keyboard shortcuts (c, f, h, l, p, s, x) swallow those letters in every `MultiSelect` search, because react-aria forwards keys typed in the search to the list; production is unaffected. Next keeps a hidden copy of the page in the DOM, so `document.querySelector` can find an element in the copy; no other screen does this today.
