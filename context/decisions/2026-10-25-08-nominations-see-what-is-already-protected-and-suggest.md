# 2026-10-25 - Nominations: see what is already protected and suggest removals; Painted Dragon and more species

- **Oct 25 2026: Nominations: see what is already protected and suggest removals; Painted Dragon and more species.** The designer: nominators select the species as now, "however they can also see what is nominated already and then suggest adding or removing the already nominated attributes. Also, add painted dragon species to the list along with some more species."
  - **What is already protected** is `currentProtections` (`nomination-data.ts`): every accepted species nomination in the order it was accepted, its removals taken off before its additions are put on, one rule per item (All data, an attribute and its value, a Location by area), naming the nomination that protects it. Keys are `ruleLabel`'s, the identity `mergeRatings` already matches rules by.
  - **Species step:** under the species card, a brand alert "Already protected by accepted nominations" lists the rules (semicolon separated) and says the next step can add or remove. Not shown beside the open-nomination error.
  - **What to protect step:** with Specific attributes, an "Already protected" row (after Main reason, before Attributes) lists each rule with a "Suggest removing" checkbox; a ticked one takes the main reason or its own (the same inherited-value pattern as an attribute). With All data the list is read only. Attributes become optional once something is suggested for removal, and `ConceptRows` gained an opt-in `allowEmpty` (1.6) so the last attribute row can be removed. The Main reason and Attributes descriptions say what they cover when there is something already protected.
  - **Stored** as `Nomination.removals` (`NominationRemoval`: key, attribute, value, the protecting nomination, an optional own reason), a snapshot. Removals are not rated.
  - **Read:** `ProtectionView` (Review step and the version 3 record) lists removals after additions, a "Suggested removal" badge under the attribute and "Protected now by NSS-..." under the value, no rating. Version 1's What to protect tab has a row per removal.
  - **Accepting:** `currentSpeciesRating` takes an accepted nomination's removals off the species' rating before merging what it adds (removing All data leaves the species open).
  - **Species:** nine real South Australian species with no records in the shared dataset are added to `REGISTRATION_SPECIES` (`SPECIES_WITHOUT_RECORDS`, `project-registration/data.ts`): Painted Dragon (Ctenophorus pictus), Flinders Ranges Worm-lizard, Bush Stone-curlew, Mallee Emu-wren, Sandhill Dunnart, Greater Bilby, Brown Toadlet, Pink-lipped Spider-orchid, Metallic Sun-orchid. Kept off Explore's occurrence data, so the map and counts do not change; they show the group icon (no photo). They also appear in Add Project's species pickers.
  - **Seed:** NSS-2026-00015, an accepted Painted Dragon nomination (Location: Gawler Ranges dune burrows; Activity: Breeding; Animal life stage: Egg, Juvenile), illustrative, so the flow has something to show. Store version 7 adds it.
  - **Open:** (1) version 3's admin-only "Already protected" block on the record lists earlier nominations' ratings without honouring accepted removals; (2) adding a rule identical to one already protected is not flagged; (3) the form briefly shows "Details missing: Choose a species without an open nomination" after Submit, before navigation, because the saved nomination counts as an open duplicate of itself (existed before this change); (4) whether a removal should carry a rating or a panel decision per item.
  - Verified: `tsc` (only the two stale `.next` option-2 route types), `eslint` on touched files, `check:contracts` OK; live pass as Registered User on version 3: picked Painted Dragon, saw the alert, ticked Suggest removing on Activity, removed the empty attribute row, submitted, record pages (version 3 table, version 1 tab) show the removal; zero console errors. The test nomination was removed from local storage. Admin personas and the rating path were not exercised live. Not committed.
