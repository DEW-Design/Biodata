- **Sept 27 2026: two real bugs on Explore option 2's "Search areas" list and its draw tools, both flagged directly off a screenshot.**
  - **The "Search areas" count was a bare number, not a real component - "why is the 1 by itself? This is a grave violation of the design system."** `AreaLayerList` (`app/pages/_shared/map-search/area-layers.tsx`) rendered the row count as `<span className="ml-1.5 font-normal text-tertiary">{rows.length}</span>` next to the heading - a hand-tuned oval, not the real `CountBadge` (`components/base/badges/badges.tsx`), which exists for exactly this shape ("a true circle for a short numeric count sitting next to a heading, e.g. 'Needs your attention 3'" - its own doc comment). Verified live: a real 20x20px circle, `bg-utility-neutral-50`/`text-utility-neutral-700`, matching the tab-count pills directly below it in the same panel.
  - **leaflet-draw's own floating "Click to start drawing shape." tooltip was getting clipped against the viewport edge while drawing, duplicating the app's own real hint copy in the "Search the map" card below it.** `sa-map.tsx` drives `L.Draw.Circle`/`L.Draw.Polygon` directly, and leaflet-draw shows its own stock, unstyled, cursor-following tooltip by default - a library default this codebase never suppressed, now overlapping and getting cut off at the top of the map instead of reading cleanly. Fixed with one scoped override in `app/globals.css` (`.leaflet-draw-tooltip { display: none !important; }`, documented inline) rather than patching per call site - `sa-map.tsx` is the only consumer of `leaflet-draw` in this codebase. Verified live: drawing a polygon still creates the tooltip element in the DOM (leaflet-draw's own lifecycle untouched) but it renders with zero visible instances, and the card's own real hint text is the only instructional copy shown; zero console errors.
