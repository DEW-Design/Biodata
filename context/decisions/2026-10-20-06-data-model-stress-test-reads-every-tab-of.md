# 2026-10-20 - Data model stress test reads every tab of a workbook, classifies each tab and links tabs by key column

- **Oct 20 2026: Data model stress test reads every tab of a workbook, classifies each tab and links tabs by key column.** Brief: "If I insert an excel file that has the structure present but split in different tabs, the ingestion model needs to be smart enough to pick up, link and create the tree structure accordingly." `/proto/data-model-stress-test` read only the first sheet of an XLSX and classified a file only by a file-name prefix. Lab only (`app/proto`), no product screen touched.
  - **Pick up.** `workbook-ingest.ts` (new, pure, beside the page) reads every non-empty tab. The header row is found even under a title line or blank rows. Each tab is one source, the same as a separate file uploaded alongside others.
  - **What each tab is**, in this order: every row states its own Kind (kept as stated); the tab name (Sites, Visit data, Species Flora, word match on singular forms); the file name, only for a source that is the whole file (a CSV, JSON or one-tab workbook; in a multi-tab workbook the file name says nothing about one tab); then the tab's columns, scored against the schema's own field lists and the BDBSA crosswalk columns that belong to one record family only (at least two, strictly ahead of the others). The existing filename rule for the real BDBSA exports (SITE_*, VISIT_*, SPECIES_FAUNA_*, SPECIES_FLORA_*) is unchanged, and now also matches a prefix anywhere in the name.
  - **Link.** A key column points at another tab's records: "Site ID" on a Visit tab, "Visit ID" or "Visit Name" on a species tab (also Ref, Code, Key, a bare type name, "Site Name"). Deepest type named wins; an explicit Parent ID always wins; `linkByReference` runs before the coordinate and date traceback. A tab with no ID column is keyed by "Site ID" / "Visit ID", or by its own name when no coordinates exist. Each tab numbering its own rows (Site 1, Visit 1) is not a duplicate: ids from a type-specific key column that repeat on another type are kept apart as "Site-1" / "Visit-1". A pointer that matches nothing keeps its value as the Parent ID and is reported by its column ("Visit ID "9" doesn't match any record in this file"), never dropped.
  - **Visible.** "How the tabs were read" card (shown when more than one source): tab, rows, read as, the basis, and how its records were placed (by Site ID, by coordinates and date, at the top, not placed). A tab with no signal is left out and said so; a lone unclassified file is still ingested as before. The record card shows "by <column>" beside its parent and the tab it came from. "Load sample workbook" builds a real three-tab .xlsx (Sites, Visits with a title line, Species, a notes tab, one Visit ID that exists nowhere) and sends it through the same path as an upload.
  - **Also fixed, found while testing.** A record under a parent that could not be placed was itself counted as placed and floated to the top of the Resolved tree. It is now unplaced too, with "Parent ... couldn't be placed in the structure". This applies to every upload, not only workbooks.
  - **Verified (ran).** `npx tsc --noEmit` clean, `eslint` clean on the folder, `npm run check:contracts` OK. Live in Chromium against five generated workbooks and three BDBSA-style CSVs, no console errors: sample workbook (Site > Visit > Occurrence > Observation, Visit 9 unresolved); tabs with Kind/Type/ID/Parent ID split across tabs; generic Sheet1-3 tabs classified by columns and linked by Site Name / Visit Name; one-tab `site_export.xlsx`; multi-tab `site_data.xlsx` (file name ignored). "Load sample data" unchanged at 10 valid / 8 with errors.
