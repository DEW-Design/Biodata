# 2026-10-22 - post-6-oct project page: progressive disclosure on the Overview sheet

- **Oct 22 2026: post-6-oct project page: progressive disclosure on the Overview sheet.** The designer, on `/proto/post-6-oct`: the project detail page has too much information, all at the same weight, and asked for progressive disclosure. The request was first run through the `refine-prompt` skill (`emil-design-vocabulary` then `emil-engineering-vocabulary`), which named the problem as a flat hierarchy ("Without it, everything competes and nothing wins") and the fix as progressive disclosure ("Showing only what is needed at each step ... The opposite is putting everything on one page"), built with the real Accordion (stacked sections that expand and collapse, not tabs: the sections are read in turn, not compared) and lazy loading for what is closed.

  **What changed.** `ProjectTab` (`app/pages/project-detail/project-tab.tsx`) has a new opt-in prop, `disclosure` (default off, so the product page and the other labs are unchanged, CONTRACTS 1.6). With it, the first section (the Overview: Project details, Published by, Project managers) stays open and "Data collection and methodology" and "Privacy and restrictions" start closed under their headings, each the real `Accordion variant="compact"` (the pattern the user record's permissions already use, CONTRACTS 0.9) with its heading and description kept as they were. The cards inside are the production cards, 1:1 (nothing hidden, renamed or regrouped inside a section).
  - A section's cards are not drawn until it is first opened (the Mapbox map in Geographic extent is not built until wanted) and are kept after, with `inert` while closed so Tab and a screen reader skip them.
  - "On this page" opens a closed section before it scrolls to it (`OnThisPage onBeforeGo`, a new optional prop), and editing a card, including "Add restriction", opens the section that holds it. The TOC's active-item tracking ignores inert copies.
  - A closed header carries what its cards would otherwise say: a count of restrictions beside "Privacy and restrictions", and the "Details needed" badge (the card's own) while a card inside needs details, so closing a section does not hide a warning. The badge shows only while closed, so the fact is not stated twice when it is open.
  - `app/proto/post-6-oct/project-workspace.tsx` turns it on.

  **Decided (by me, flagged for the designer):** the default is Overview open, the other two closed; Privacy opens to "No restrictions" when it has none and shows no count then; the closed sections' headings are the compact Accordion's 14px semibold, not the 18px h2 they had open as plain sections. Each is a one-line change.

  **Open.** (1) Which sections should start open, and whether a project with restrictions should open Privacy (what is held back from release is something a reader may need at first look). (2) The 18px to 14px heading step and the loss of the h2 landmark in the lab (the Accordion's toggle is a button, not a heading): if headings are wanted, the compact variant needs an opt-in heading level (CONTRACTS 1.6), which is a change to a base component and is not made here. (3) Long text inside the cards (the abstract, methodology, limitations) is still shown in full: a second level of disclosure ("Show more") was not asked for and is not built. (4) The Records, Species and Artefacts tabs were not changed: the complaint reads as the Overview, which holds nine cards in one scroll.

  **Verified.** `npx tsc --noEmit` clean; `npx eslint` clean on both touched files; `npm run check:contracts` passes. A live pass in Chromium at 1440x900 and 1024x768 as BioData Super Admin, Registered User and Public User: zero console errors; the closed headers measured Barlow 14px, weight 600 (title) and 400 (description); mouse, Enter and Space toggle a section; "On this page" opens a closed section and scrolls to its card; "Add restriction" opens Privacy and the add card (not offered to the Public User); the map draws (360x399 canvas); the production page `/pages/project-detail` still has its four h2 sections and no accordion. **Not run:** `/emil-typography` and `/emil-design-foundations` (CONTRACTS 0.6 item 8), so the type check is by measurement against the existing patterns only; Safari and a real-scrollbar check.
