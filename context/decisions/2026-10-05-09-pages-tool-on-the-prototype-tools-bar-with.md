# 2026-10-05 - Pages tool on the Prototype tools bar with the DEW tree

- **Oct 5 2026: the Pages map is now a tool on the Prototype tools bar, on every screen, and its tree is the design system's own `TreeView` with no checkboxes. From the designer, after seeing the three lab layouts (`2026-10-05-03-*`): "Tree but use our component without the checkbox? Can I see how that would look? I'd rather see it in-site - put these options in the prototype tools rail."**
  - **Reading of the brief:** "these options" is taken as the map's views, so the bar's Pages panel has two: Tree (the designer's pick) and Search (the flat "go to a page" list, kept because it is the keyboard route). The wide Columns layout does not fit a panel and stays in the lab only.
  - **Override of 1.5 (designer, this session):** 1.5 says a Scaffold control is never built from a real DEW component. The Pages button, the panel's header, the view switch and the search box are still Scaffold (Geist, react-aria primitives, the bar's Flinders Violet). The map inside is the real `TreeView` (`components/application/tree-view/tree-view.tsx`, `selectionMode="none"` so no checkbox, `showConnectors`, unchanged component) on a plain product surface, because the designer asked to see how the design system's tree looks here. It is one panel, one instance, and not a precedent (0.1). No component was changed or added, so 1.4 does not apply.
  - **What the panel does:** opens above the bar from a "Pages" button that sits first on the bar on every screen (the role stays last, at the fixed right edge). Header: "N of 72 open as <role>", Tree and Search, a search box that filters and opens every match. Areas are the top level and open and close on click; a screen opens on click or Enter and keeps the role; a screen with sub-screens has its own chevron. The page you are on is marked, its area and ancestors start open and the list scrolls to it. A screen the viewed role cannot use is dimmed with a lock and the reason but still opens (3.7). Down arrow moves from the search box into the list, Enter in the box goes to the first match. The panel keeps one height whatever the search leaves (the body is `h-[min(58vh,520px)]`).
  - **Moved, same behaviour:** the page gates (`wholePageGates`, `isPageBlockedFor`) to `app/_prototype-tools/page-gates.ts` and the role names (`ROLE_OPTIONS`, `roleLabel`) to `app/_prototype-tools/role-options.ts`, so the tool and the role menu share them without importing each other; `prototype-tools.tsx` re-exports both for the lab. The map's data module moved from `app/proto/site-map/` to `app/_prototype-tools/pages-map-data.ts` because the bar (product code) must not import from `app/proto` (5.4); the lab imports it from there. `ref-shell.md` points at the new gates file.
  - **Verified live (Playwright, 1708x1024, BioData Admin, from `/pages/reports` and a DLA record):** the panel opens with 17 areas and no checkbox inputs; the tree font is Barlow (DEW) and the header Geist; clicking an area opens it (17 to 18 rows); searching "licence" leaves 4 rows, all open; clicking a leaf opens `/pages/dla/DLA-2026-00502` with `userRole` kept; reopening on that page shows the current screen marked with its ancestors open; the Search view lists by area with paths, and typing "vocab" then Enter opens `/pages/ctrl-vocab`. Zero console errors. `tsc`, eslint on `app/_prototype-tools` and `app/proto/site-map`, `check:contracts` pass.
  - **Not done:** a keyboard-only pass of the tree (arrow keys, Enter on a leaf), other roles in the panel (the lab covered the data for three), narrow windows (the panel is 440px wide and opens above the bar), the lab's own Tree (B) is still there beside the new one and has not been deleted (4.4: wait for the choice), the Escape key behaviour of the panel, and a type check with the Emil skills on the panel header.
  - **Open for the designer:** 3.8 reads "the role is always there, and any other tool is added by the code that owns it"; Pages is now always there too, so the clause needs a line saying so.
