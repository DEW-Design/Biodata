# 2026-10-23 - Truncation strategy for the report's dropdowns: files cut in the middle, titles at a word, the list wide enough

- **Oct 23 2026: Truncation strategy for the Data Validation Error Report's dropdowns.** The designer, with two screenshots, one of the vocabulary entry "Truncation strategy" (with a demo: "Quarterly-boar...-v3.pdf", "Homepage hero...", "Customer int...-14.docx", a Clip / Considered switch) and one of the report's two dropdowns, the dataset one open: "truncation strategy to be considered for these fields."
  - **The vocabulary (emil-design-vocabulary, as in the screenshot):** *Truncation strategy*, "deciding where and how text gets cut when it overflows. A name truncated mid-character is worse than one cut at a word boundary. Titles, labels, and descriptions each need their own truncation logic." Also *Text overflow*: "never cut mid-word".
  - **Principles at stake (0.10):** 4 Tell the truth (the part of a name that tells one file from another must not be what is cut), 5 Make it obvious (a value says what it is and which), 2 One thing first (the id leads). They agree.
  - **The faults, measured:** (1) a file name was cut at its end, so "flinders_bushland_assessment_01.xlsx" and "..._03.xlsx", told apart only by their ends, both read "flinders_bushla..."; the extension was always lost. (2) A title was cut mid-word ("Flinders Ranges Reptil..."). (3) The open list was as wide as the trigger (384px), so its longest row, "DS-2026-01003 · flinders_bushland_assessment_01.xlsx", was cut in the list too ("..._01....").
  - **The strategy, by what the text is (not one rule for every string):**
    1. **An identifier is not cut.** The code or id leads the line and the dropdown's own label ("Project", "Dataset") is fixed; the cut is always after them.
    2. **A title is cut at a word.** "BD-5137 · Flinders Ranges ..." and not "Flinders Ranges Reptil...". Done in CSS with no measuring: each word after the first is an atomic inline, and `text-overflow` drops an atomic inline whole, so the ellipsis falls between words (the first piece stays plain, so a line too short for one word still shows the start of it). Select prop `truncateAtWords`, opt-in.
    3. **A file name is cut in the middle and keeps its end,** the version and the extension: "DS-2026-01003 · flinders_bushland_a...01.xlsx" at 384px, "DS-2026-01003 · fli...01.xlsx" at 273px. Item field `labelEnd` (the end that is never cut), opt-in, filled by `splitFileName` (`utils/split-file-name.ts`): the last short chunk after the final `_`, `-` or space, and the extension. The middle is cut by character, not by word, on purpose: a word dropped whole left a hole between the ellipsis and "01.xlsx" (tried first, seen in a screenshot, taken out).
    4. **Something cut says its whole:** the full text is the tooltip (`title`), as the report's `Clamped` cells already do.
    5. **The open list shows a row whole before it cuts any of it:** as wide as its longest row, never narrower than the dropdown, never wider than 40rem or the window (`w-max min-w-(--trigger-width) max-w-[min(40rem,calc(100vw-2rem))]` on `popoverClassName`). Measured: the dataset list is 393px with no row cut, the project list 384px.
  - **Accessibility:** a name in two boxes is read with a break between them ("counts_ 07.xlsx"); the two visual halves are `aria-hidden` and the whole name is read once, in a visually hidden span (checked in Playwright's accessibility snapshot: "DS-2026-01017 · adelaide_hills_quadrat_counts_07.xlsx Dataset"). Typeahead matches the whole name (`textValue` includes `labelEnd`: typing "DS-2026-01011" chose that dataset).
  - **Defaults unchanged (1.6):** both are opt-in, so every other `Select` is as it was (checked: `/components/select` and its four examples load as before). `ComboBox` and `MultiSelect` do not take either.
  - **Checked live (Playwright; zero console errors):** Super Admin at 1686 (384px dropdowns), 1440 (353px) and 1280 (273px), and with the dropdowns forced to 220, 190 and 150px to see each cut; the open lists; the keyboard (Enter, ArrowDown twice, Enter: the third dataset; typeahead; choosing the other project moved the dataset to its own). `npx tsc --noEmit`, `npx eslint` on the touched files and `npm run check:contracts` clean.
  - **Not checked:** Safari and Firefox (word-boundary cutting relies on `text-overflow` dropping an atomic inline, which Chrome does; where a browser does not, the text is cut at the character, as before), touch, a screen reader beyond the accessibility tree. At 150px (below the 256px floor, so not reachable) the dataset's head is a sliver; it was left.
  - **Open, for the designer:** whether the same strategy should be the default for every `Select` and for the table's `Clamped` cells (the report's Description column still cuts at the character; an identifier column and a file-name column would want their own); whether a file name should keep more than its last chunk when there is room; and whether a hyphenated file name ("Quarterly-board-minutes-v3.pdf") should be cut at its hyphens (the title strategy cuts at spaces and underscores only).
