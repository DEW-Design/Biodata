# 2026-09-30 - Controlled Vocabulary Option 3 rebuilt for hundreds of vocabularies

- **Sept 30 2026: Controlled Vocabulary Option 3 rebuilt for hundreds of vocabularies.** Replaces the Option 3 of 2026-09-30-15, per the designer: "too complex and crowded. The list page and the shrinking of three step into 2 is not working ... It's okay to revert back to three step ... keep the template workflow separate", with column 2's Actions as the place to start it, and "list of all vocabularies may quickly grow to 100s so be careful how you handle this". Asked (via /emil-product-thinking) how templates are collected today, the designer answered "we don't do this yet, but we think people will": the template is a bet, not a response to an existing workaround, which is why it stays small and separate.
  - **Removed from Option 3:** the two-step form (back to Details, Columns, Entries), the fields toolbar and header-typed custom columns, the template bar in the form, the list's task cards, "Template out" badge, Template filter and "Upload filled template" header button, the vocabulary page's template notice and actions, and "Stop waiting". Hand-outs are still recorded, but only as History lines.
  - **Kept:** Code or No., now a row in the Columns step (Reference only; a Descriptive vocabulary's identifier is a table column). The upload review: an uploaded template opens the vocabulary's Entries step with its rows merged by Code or No., marked New or Updated, and a summary above the grid.
  - **Template, separate:** column 2's Actions gain "Download template" (a dialog with a searchable Reference-vocabulary picker, preselected to the open vocabulary) and "Upload filled template" (reads the vocabulary from the file and opens its Entries step), above Export CSV. Nothing else on the list or the vocabulary page mentions templates.
  - **At scale (list):** the search also looks inside entries, including a Descriptive vocabulary's table values, and a vocabulary found that way shows which entries matched on a line under its name (the Projects list's name-and-description cell: `text-sm font-medium` over `max-w-md truncate text-xs text-tertiary`); `Table.Body dependencies` so that line follows the search. Filter adds Updated by month; Category stays column 2's job, not also a filter (4.3). Start date leaves the table (Status already says Scheduled). Values sorts. An empty result offers "Clear search and filters".
  - **At scale (column 2):** past six categories a "Find among N categories" field appears; the category list scrolls inside column 2 on its own and Actions stays in reach below it.
  - **Sample size tool (Scaffold, Option 3 only):** "Sample size" on the Prototype tools bar adds 300 placeholder vocabularies in 24 categories, every name saying it is a placeholder, made in memory, never saved; other options reset it.
  - **Component fix, flows to every consumer (1.3, 1.9):** `MultiSelect` threw "Invalid slot errorMessage" when invalid with a hint inside a Dialog (a `FormModal`): it is not a react-aria field, so its `HintText` picked up the Dialog's text slots. Its hint now sits in `TextContext.Provider value={null}`. Other callers (the DSA scope field, the mapping step) were outside dialogs and unaffected, but get the same fix. Sibling not changed: `input-tags-outer.tsx` renders `HintText` the same way; not checked inside a dialog.
  - **Verified:** `tsc`, `eslint`, `check:contracts` clean. Live Chrome: the list with seed data; "fairywren" finds SU.SUSPECIES and SUREMSPECIES with their matching entries; 313 vocabularies with 7 pages, the category finder ("12" to one category, whose page hides the Category column), Actions in reach; the Download template dialog asks for a vocabulary when none is chosen (the crash above, then fixed); the edit form's three steps with the Identifier row locked to No. on the live Measurement. No console errors. The designer's stored data was not changed (read-only pass; the sample is in memory).
