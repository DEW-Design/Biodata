# 2026-10-16 - Reports: seven administration reports (user, role, user-role, permission, role-permission, notification config, control vocab)

- **Oct 16 2026: seven more reports on the Reports page.** The designer sent seven Figma frames (file YMproGZfrFB5jUqPHPxMhk), each with a Columns panel: User Detail (165:13113, columns 165:15008), Role Detail (165:13421, 165:15380), User - Role Detail (165:13646, 165:15230), Permission Detail (165:13881, 165:15337), Role - Permission Detail (165:14101, 165:15285), Notification Config Detail (165:14336, 165:15084) and Control Vocab Detail (165:14635, 165:15172), and said the Fauna Taxonomy Report comes after them. All seven are built in the shared `DataReport` pattern (search, Filter, Columns, hero with Export CSV and XLSX) with every column of each Columns panel in its order: 23, 13, 16, 12, 15, 28 and 18, Seq# pinned. Read from the stores that already exist (User Management, Notification Management, Controlled Vocabulary), so a report and the record's own page cannot disagree.

  **Where.** `access-reports.tsx` (the five user, role and permission reports, with `access-report-data.ts` for their rows), `notification-config-report.tsx` and `-data.ts`, `ctrl-vocab-detail-report.tsx` and `-data.ts`, the shared `admin-report-helpers.tsx` (day columns that sort by the day, the Created and Modified columns, the Filter attributes), seven routes under `app/pages/reports/<id>/`, entries in `reports-data.ts` and `screen-index.ts`. Two new landing categories: **Users and access** (the five) and **Application and system** (Notification Config, Control Vocab; the admin IA's own name), with icons in `reports-nav.tsx`. Icons: User Users01, Role UserCheck01, User - Role UsersCheck, Permission Key01, Role - Permission Key02, Notification Bell01, Control Vocab Database01 (each is the section's icon where there is one).

  **Access.** User, Role, User - Role, Permission and Role - Permission need `userManagement` and Notification Config `notificationManagement` (BioData Admin and Super Admin); Control Vocab needs `ctrlVocabManagement` (BioData Super Admin only, as Controlled Vocabulary). A role without the feature is not offered the report, and its address says "This report is not available to your role".

  **The wireframes' Filters cards** are the table's own controls, as in the Flora Taxonomy Report (CONTRACTS 4.6 item 4): a name or ID (User name, User full name, Role name, Role ID, Notification ID and name, Control Vocab Name) is the search; Institution / Organization, Status, Category, Type, Workflow, Stage, Role / User and the dates are attributes of the one Filter menu. None of the seven is run on a project or a dataset, so none has Parameters.

  **What the app does not record is left empty, never made up (CONTRACTS 0.3).** User Management keeps no created by, created on or modified by for a user, role or permission (only the day of the last update, which fills Modified on), and no status, dates or history for a role held by a user or a permission held by a role. So: User Detail's Nature of work, Purpose, the three acknowledgements, DEW review, DEW approval, Created by, Created on and Modified by; Role and Permission Detail's Created by, Created on and Modified by; and User - Role's and Role - Permission's assignment status, Valid from, Valid until and the four Created and Modified columns are in the table, in the wireframe's place, and empty. Notification and Controlled Vocabulary do keep a history, so their Created and Modified columns are filled.

  **Departures, each named in the file's header comment.** Labels are sentence case and spelled out ("Contact No" is "Contact number", "UR Assignment Status" is "User - role assignment status"). The wireframes' Creation Date is not offered where nothing records it: the Filter has Modified on (a column) and a valid period instead. Permission Detail's Filters card also asks for User full name, which no column of that report holds, so it is not offered. Notification Config reads the wireframe's Trigger Type, Scheduling Type and Condition as the build's one trigger question: Trigger type is Event or Schedule, Workflow and Stage are a status-change event and the status it is limited to ("Any status" when it is not). Control Vocab Detail is one row per entry beside its vocabulary, and a vocabulary with no entry is one row; its Status is the vocabulary's (Draft, Scheduled, Active, Archived), its Description the vocabulary's, and Control vocab code the entry's code (or ID), because a vocabulary has no code of its own.

  **Also changed.** The landing's category tab strip (`reports-landing.tsx`) now scrolls inside itself: nine categories are wider than main below about 1500px and the last tabs were clipped (the same fix as the Flora report's tab strip). The `/patterns/report-toolbar` "Used by" line names the seven.
