# 2026-09-29 - The ⌘K badge on search fields is removed, per direct instruction off a screenshot of the dataset-upload "Search projects" field ("Incorrect, command + K icon to be removed across all search field instances")

- **Sept 29 2026: the ⌘K badge on search fields is removed, per direct instruction off a screenshot of the dataset-upload "Search projects" field ("Incorrect, command + K icon to be removed across all search field instances").** Root cause, found once, not per field: `ComboBox`'s (`components/base/select/combobox.tsx`) `shortcut` prop defaulted to `true`, so any `Select.ComboBox` call site that didn't explicitly opt out rendered a hardcoded `⌘K` badge - and no `⌘K` keyboard handler exists anywhere in this app, so the badge was advertising a shortcut that does nothing. Fixed at the component (`shortcut = false` by default), which corrects every affected call site at once: the "Search projects" field in `app/pages/_shared/dataset-upload/choose-project-modal.tsx` (the field in the screenshot) and "Select Location" in `app/pages/_shared/dla/add-location-modal.tsx`. `GlobalSearch` (the header search) and `SpeciesField`'s combo box already passed `shortcut={false}` explicitly, so neither was affected either way. `Input`/`InputDate`'s own `shortcut` prop has no default (`undefined` unless a caller opts in) and no `app/pages/**` caller does, so those were never part of this bug. Logged as a new contract, `CONTRACTS.md §2.10` ("No affordance for a shortcut that isn't real") - a component MUST NOT default to showing a shortcut hint; it's opt-in per call site, and only where a real binding backs it.
