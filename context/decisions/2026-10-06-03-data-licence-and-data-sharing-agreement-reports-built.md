# 2026-10-06 - Data Licence and Data Sharing Agreement reports built on the shared report

- **Oct 6 2026: two more reports from the wireframe (Figma YMproGZfrFB5jUqPHPxMhk node 2645:176998, "DLA, DSA Reports"): the Data Licence Agreement Report (frame 2645:175676, columns list 2645:176056) and the Data Sharing Agreement Report (frame 2645:175863, columns list 2645:176111). Both are on the shared report (`DataReport`, `report-columns.tsx`) at `/pages/reports/dla-agreement` and `/pages/reports/dsa-agreement`, in a new "Agreements" category on the Reports landing.**
  - **Columns:** all 16 of each wireframe's, in the Columns list's order, in a table that scrolls sideways. DLA: Seq#, DLA ID, Data requested, Requested date, Purpose, Requestor full name, Organisation, Email, Agreement start date, Agreement end date, DLA status, DEW owner, DEW approver, Approved on, DEW comments, Agreement copy. DSA: Seq#, DSA ID, Requested date, Partnership organisation, Purpose, Requestor full name, Email, Agreement start date, Agreement end date, DSA status, DEW owner, DEW approver, Approved on, DEW comments, Agreement copy, Integration details. The wireframe's own table shows only the first nine (and omits Email); the Columns list is the full set, so the Columns list wins. Sentence-case labels, as the other reports.
  - **Real rows, not dashes.** Rows are read live from the DLA and DSA stores, so a status moved on those screens moves here. Drafts are left out (not yet a request or an agreement). What each column reads is in `agreement-report-data.ts`: Seq# is the number in the ID; Requested date is submitted (DLA) or created (DSA); start and end are the granted period (empty until set); DEW owner is who started the review; DEW approver and Approved on come from the Approved move in the Audit Log (a move by "System" has no approver); DEW comments is the newest note on a move, else a rejection reason or a DLA's custom-agreement note; Agreement copy is the attached file's name; Data requested is each location with its level; Integration details is each system with read or write and its scopes, or "Shared offline".
  - **Filters and Columns are the shared ones (4.2d, 1.9).** The wireframe's Filters card (DLA/DSA ID, Organisation, Requestor, Approver, Agreement Period, "Additional Filter", two chips, Apply Filter) is the one Filter menu that applies as values are chosen: Status, Organisation (Partnership organisation on the DSA report), Requestor, DEW approver and Agreement period; the ID is the search box's job; "Additional Filter" is not built. The Columns list's checkboxes and Apply are the Columns button. The wireframe's "50 of 1797" is the table's own footer. Export CSV is in the hero's "..." menu (4.6), which the wireframe does not draw.
  - **Who sees what (a decision the designer should confirm).** DLA: a registered user sees their own requests (as the DLA list's "My requests"), BioData Admin sees every one. DSA: BioData Admin alone, as the DSA screens are (`dsaManagement`), so no other role has rows. A report can now name a `feature` (`reports-data.ts`, new `reportsFor(role)`): the landing, its count, the Favourites tab and the breadcrumb switcher offer a role only the reports it has the feature for, so a Registered User is offered the DLA report and not the DSA one, consistent with the Pages tool hiding what a persona cannot open. Opened by its address, the DSA report says only BioData Admin can report on data sharing agreements.
  - **Spelling:** the wireframe says "License"; the DLA screens and the rail say "Licence", so the title is "Data Licence Agreement Report". Easy to change if the designer wants the wireframe's spelling.
  - **Also done:** both are in the `/pages` index (`screen-index.ts`, so in the Pages tool: DLA "Signed in", DSA "BioData Admin"); a new "Agreements" category tab with the agreement icon (`FileCheck02`); the DLA report's icon `FileCheck02` and the DSA report's `Share07` (the icon table's Permit and Agreement and Data Sharing).
  - **Verified live (Playwright, 1708x1024, zero console errors):** DLA report as BioData Admin 8 rows with all 16 columns, as Registered User 2 rows (Olivia Wyatt's); DSA report as BioData Admin all 16 columns, as Registered User the restriction state; the landing offers two agreement cards to BioData Admin and one to Registered User; default sort is newest request first. `tsc`, eslint on the touched folders and `check:contracts` pass.
