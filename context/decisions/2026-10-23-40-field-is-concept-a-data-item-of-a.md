# 2026-10-23 - Field is Concept: a data item of a record is called a concept across the webapp

- **Oct 23 2026: Field is Concept: a data item of a record is called a concept across the webapp.** The designer, page feedback on the "Field" label in the Map visualise summary: "Field = Concept. Let's make sure this is tweaked across the entire webapp. Replace." The product already said "concept" where a data item is flagged, restricted or attached to (the Flagged concepts page, "Restricted concept", "Attached to Concept") and "field" where the same thing is validated, audited or compared, so one screen said "flagged concepts" and its detail said "Notes on this field".
  - **The rule I applied (the designer said "entire webapp"; "field" has five meanings in this product, so the boundary is mine and is open below):** a **data item of a record the person reads, filters, flags, audits or compares** is a Concept. A **form control** is still a field ("This field is required", "Fields marked * are required"), **fieldwork** is still field ("Field Survey", "field sheet", "field measurements", "Field Officer", the field tablet) and the design system's own docs keep "text field".
  - **Changed, by place:**
    - **Data Validation Error Report and Map visualise (the feedback's own screens):** the report's column and Filter attribute are "Concept", its search placeholder "Search by record, species, rule or concept", its CSV and XLSX header "Concept"; the card's summary row is "Concept", and the rows' second line and the marker tooltips carry the concept's value as before. The code says what the screen says: `ErrorRow.concept` and the rule's `concept` (they were `field`), so the report and its derived view stay one wording (CONTRACTS 2.15).
    - **Project Audit Log Report:** its Entity type is "Record" or "Concept" (it was "Field"), the subtitle and description say "one row per concept", the search placeholder "concept or user". The log is kept in the browser, so its store is now version 2 and a migration turns a saved "Field" entry into "Concept" (checked live: an entry saved the old way shows as Concept and the stored version is 2). This also matches the Taxonomy Audit Log's own entity type, "Concept".
    - **Project page:** "Fields shown" (the checklist while a card is in edit mode) is **"Concepts shown"** with "Find a concept", its hint, and CONTRACTS 4.8 item 6; the notes on a flagged concept ("Notes on this concept", "The concept's comment and attachments.", "The reason is kept with the concept.", "A concept has one comment."), the record panel's "N flagged concepts", the notes card's "Edit a concept to add one.", the artefacts tab's "attached to the concepts of this project's records", the custom record type's "Anything the standard concepts don't cover.", and the Explore record detail's "[Custom concept name]" and "[Custom concept value]".
    - **Observation detail:** the flag's tooltip "this concept may need review or updating".
    - **Voucher Management (a voucher's Scientific name, Voucher ID and the like are data items):** the batch's "Concept" column and CSV header, the Filter attribute "Concept that differs", "Concepts that differ" and "Show matching concepts", the list's Differences tooltip, "All four concepts match BioData", the two layout descriptions, and the Voucher ID Update Report's subtitle and its description in the reports list.
    - **The screen index** (the three voucher rows and the audit log row) and, in the labs, the post-6-oct artefact modal ("Concept", "Search concepts") and the project-detail lab's tooltip, so a later fold brings the same words.
  - **Checked live (Playwright, scripts outside the repo; BioData Super Admin, BioData Admin for the audit log):** the report's columns read "Record ID | Project | Species | Category | Rule | Concept | Severity | Description" and its Filter menu "Category, Severity, Rule, Concept"; the summary's rows "Record, Rule, Concept, Severity"; the audit log's subtitle and a migrated entry; the voucher batch's column "Concept", filter "Concept that differs" and toggle; the voucher report's subtitle; "Concepts shown" and "Find a concept" appear in the project page's edit mode and "Fields shown" does not; the flagged concepts page has no "field". Zero console errors; `npx tsc --noEmit`, `npx eslint` on every touched file and `npm run check:contracts` clean; `npm run contracts:rules` run. A sibling grep for `"Field"`, "Fields shown", "Find a field" and "flagged field" leaves only the migration's own line, internal names and comments (`fieldId`, `FieldKey`, `field-notes.tsx`, which are code), and the two admin exports below.
  - **Kept as "Field", on purpose, for the designer to decide:** the **History CSV export of a Controlled Vocabulary and of a Notification** (`cv-detail.tsx`, `nt-detail.tsx`: a "Field" column naming which attribute of a vocabulary or notification changed). They are admin records, not biodiversity data, and a notification's title or message is not a concept in the BDBSA sense; but the Project Audit Log beside them now says Concept, so if the designer wants every change log to match, it is those two header strings. Also kept: every "This field is required" and "Fields marked * are required" (form controls), and "Field Survey" and the rest of the fieldwork wording. File and prop names (`field-notes.tsx`, `fieldId`, `FieldKey`) are code and were not renamed outside the validation report's own data.
  - **Not verified:** the observation detail's flag tooltip on hover (the string is changed in source; the tooltip opens on hover only), the notes card and the review view's detail on a real flagged concept beyond the page loading, the Voucher Option 2 layout. No `/emil-typography` pass (the words changed, not the type). Not committed.
  - **Open, with a recommendation:** (1) the two admin history exports above; recommend changing them for one wording across every change log. (2) Whether to make this a contract (a data item of a record is a Concept, not a Field, with the exceptions above), `REVIEW`, so a new screen does not bring "Field" back; recommend yes, say so and it is added.
